# Auto-Hunt (not finished)

> **:warning: Not finished**
>
> OgreBot marks this tab as not finished (its name is struck through). Some options below work and some do not yet - each one says which.

Auto-Hunt is a simple grinding mode. The bot looks for a mob near you, targets it and opens the fight with the first ready ability from your Pull Abilities list; your Cast Stack then fights as usual. This tab is marked not finished: the mob choice and safety settings work, but the walking part does not. The Auto Hunt and Movement Only boxes and the nav path list do nothing yet, so the bot never walks a route; it pulls what comes within the scan radius. To switch it on, use the OgreConsole command `-autohunt` with hunt, movement or off. It only runs while OgreBot is open with a profile loaded and the bot is not paused.

## Auto-Hunt

| Option | What it does | Default |
|---|---|---|
| **Auto Hunt** | **Not active yet.** It will be the on/off switch for Auto-Hunt. For now, start and stop it with the OgreConsole command `-autohunt` (hunt, movement or off). | off |
| **Movement Only** | **Not active yet.** It will make Auto-Hunt walk without pulling. The command `-autohunt movement` exists, but for now it does not walk anywhere; it only holds you still while a safety check is tripped. | off |

## Auto Hunt Options

| Option | What it does | Default |
|---|---|---|
| **Scan radius (box)** | How far around you the bot looks for a mob to pull, and for mobs attacking your group. Leave it blank to use 35. | empty (35 is used) |
| **Check Aggro** | While anyone in your group (or raid) is in combat, the bot stops pulling and holds still. Your normal combat settings handle the fight. | off |
| **Check HP @** | While anyone in your group (or raid) has less health than the % in the box beside it, the bot stops pulling and holds still.<br>*A group member who is not in the zone counts as low health. A blank box never stops the hunt.* | off |
| **Check HP @ (box)** | The health % used by Check HP @. Only used while Check HP @ is ticked. | empty (never stops the hunt) |
| **Check Mana @** | While anyone in your group (or raid) has less power than the % in the box beside it, the bot stops pulling and holds still. | off |
| **Check Mana @ (box)** | The power % used by Check Mana @. Only used while Check Mana @ is ticked. | empty (never stops the hunt) |
| **Check if any group members dead** | While anyone in your group (or raid) is dead, the bot stops pulling and holds still.<br>*A group member who is not in the zone also counts as dead, so the hunt waits for them to arrive.* | off |

## Ignore mobs by con

| Option | What it does | Default |
|---|---|---|
| **Gray** | The bot never pulls gray-con mobs.<br>*A gray mob already attacking your group is still fought.* | off |
| **Green** | The bot never pulls green-con mobs. | off |
| **Blue** | The bot never pulls blue-con mobs. | off |
| **White (even)** | The bot never pulls white-con (even) mobs. | off |
| **Yellow** | The bot never pulls yellow-con mobs. | off |
| **Orange** | The bot never pulls orange-con mobs. | off |
| **Red** | The bot never pulls red-con mobs. | off |
| **Non-Aggro** | The bot only pulls mobs that would attack you on sight. Mobs that leave you alone are skipped. | off |
| **Named** | The bot never pulls named mobs.<br>*Even when unticked, normal mobs in range are pulled before named ones.* | off |

## Pull Abilities

| Option | What it does | Default |
|---|---|---|
| **First ready one is used; drag order = priority** | Your pull list. When the bot has a mob targeted and you are out of combat, it uses the first entry from the top that is ready. Type in the box above to find one of your abilities or items; picking it adds it. Drag rows to change the order, double-click a row to switch it off or on.<br>*With an empty list the bot targets mobs but never pulls them.* | empty |

## Behaviour

| Option | What it does | Default |
|---|---|---|
| **Campspot** | When the bot finds a mob to pull, it sets a camp spot where you stand and holds you there for the fight. When no mob is left, it clears that camp spot again.<br>*It only sets and clears this character's own camp spot, not the group's.* | off |
| **CS-JO-JI** | Right now this does exactly the same as Campspot. | off |
| **Prebuff** | Before each pull, the bot targets you, turns auto-attack on and waits 3 seconds, so your normal buffs have time to go out. Then it targets the mob.<br>*It does not cast buffs itself; your Cast Stack does that.* | off |
| **Use IRC** | **Not active yet.**  | off |
| **Ignore Collision** | Normally the bot skips mobs it cannot see (a wall or hill in the way). Tick this to let it pull those too. | off |
| **Delay After Combat** | **Not active yet.**  | off |
| **Pause on Exquisite Chest drop** | While an Exquisite chest is lying within 50 of you, the bot stops pulling and holds still, so you can deal with it.<br>*It carries on by itself once the chest is gone.* | off |

## Nav Paths

| Option | What it does | Default |
|---|---|---|
| **Add a nav point** | **Not active yet.** It will list named places in the zone to add to the route; for now the list is always empty.<br>*Opened, it says 'No named nav points yet - not built in the new bot'.* | empty |
| **Nav Path Order** | **Not active yet.** It will hold the route Auto-Hunt walks, in order. It is saved with your profile, but nothing uses it. | empty |
| **Clear** | Empties the Nav Path Order list. Press Save at the top to keep the change. |  |
| **Loop path** | **Not active yet.** It will make the route start over when it reaches the end. | off |

## Good to know

- Ticking Auto Hunt does not start anything. Use `-autohunt` in OgreConsole (hunt / movement / off). That choice is not saved with your profile, so Auto-Hunt starts off every time the bot is loaded fresh.
- A mob that is already attacking your group is targeted before any new pull, whatever its con. The con, Non-Aggro and Named filters only decide which NEW mob to pull. With 'Check Aggro' ticked the bot instead holds still and leaves that fight to your normal combat settings.
- 'Check if any group members dead' and 'Check HP @' also count a group member who is not in the zone. The hunt waits until they arrive.
- Pulls only happen while you are out of combat, and only if at least one entry in the pull list is ready to use. With an empty list the bot targets a mob and just waits.
- If the Scan radius box is blank, the bot looks 35 around you.
- Movement mode (`-autohunt movement`) does not walk anywhere yet and never pulls. The safety checks still apply in it: while one of them is tripped (Check Aggro, HP, Mana, dead members, Exquisite chest), the bot holds you still.

# Cancel On Cast

Some casts spoil a buff you keep up, so that buff needs to be cancelled and cast again fresh. Each row here says: when you cast THIS, cancel THESE buffs. The Cast Stack then puts them back. To build a row, click what you cast in list 1 and one or more buffs in list 2 (click a buff again to unpick it), then press Add. The row appears in Cancels setup, for example 'Armored -> Battle Tactics, Call of Shielding'. It only runs inside instances unless you tick the overland box. It waits while you are in combat, and it waits while the bot is paused.

| Option | What it does | Default |
|---|---|---|
| **1. When you cast this  (ability or item)** | Pick the cast that should trigger the cancel. Abilities and items are both listed; items start with 'Item:'. Click one to select it. It is highlighted until you press Add. | your abilities and items |
| **2. ...cancel these  (pick several)** | Pick the buffs to cancel when that cast happens. Click as many as you like, and click one again to unpick it. Only buffs that last until cancelled are listed. | your until-cancelled buffs |
| **Cancels setup** | Your rows: the cast, then the buffs it cancels. After that cast, each buff still up is cancelled one at a time, once a second, until it is gone. Drag to reorder, double-click to switch a row off, X to remove.<br>*A 'C' on a row means it may cancel during combat. Tick 'In combat' beside Add when you make the row.* | empty |

## Options

| Control | What it does | Default |
|---|---|---|
| **Also run in overland zones (by default this only runs inside instances)** | Lets the cancels happen in overland zones too. When unticked they only happen inside instances. | off |

## Build a row

| Control | What it does |
|---|---|
| **Add** | Adds a row with your picks from lists 1 and 2 to Cancels setup. Tick 'In combat' beside it first to let that row cancel during a fight. It is greyed out until both lists have a pick (hover it to see which is missing). When several buffs are picked it reads 'Add (3)'. |

## Good to know

- While you are in combat the cancel is held until combat ends, however long the fight lasts. The 30-second limit below only starts counting once it is out of combat.
- Every cast the bot makes counts. A cast you make by hand counts only if it shows a cast bar, so an instant cast by hand is missed. Ranks do not matter: a row for 'Armored' fires on 'Armored IV' too.
- List 2 only shows buffs that last until cancelled. Timed buffs run out on their own, so they are left out.
- A buff on several people is cancelled once per second until it is gone everywhere. The bot gives up after 30 seconds or 12 tries (time held in combat does not count).
- Scripts can fire a row without casting anything: -CancelOnCast <who> "Armored" acts as if you had just cast Armored.

# Chat Events

Chat Events watches the game's incoming text for words you choose. When a line contains your text, the bot can run a console command, post a line to OgreConsole, play a 'Ding' sound, or any mix of the three. Nothing happens until you tick "Enable Chat Events" on the Settings tab. You build the events with the boxes at the top, and they appear in the Configured Events list below. Click a row to edit it, double-click it to switch it off or on, drag it to reorder, and use the X to delete it.

| Option | What it does | Default |
|---|---|---|
| **Configured Events** | Your chat events. Each row shows the text it watches for, its command, and OC or Ding if ticked. Click a row to edit it, double-click to switch it off or on, drag a row to reorder, and click X to delete it.<br>*A switched-off row is kept but never fires. The order does not change anything; every active row is checked.* | empty |

## Add an event

| Control | What it does | Default |
|---|---|---|
| **Text to watch for** | The text to look for in incoming game text. An event fires whenever a line contains this text, in any case.<br>*Required. An event with no text cannot be added.* | empty |
| **Code to execute (leave blank for nothing)** | A console command to run when the text is seen. It runs exactly as if you typed it into the InnerSpace console. Leave it blank if you only want the OC line or the Ding. | empty |
| **OC - on success, send a message to OgreConsole** | When the text is seen, a line goes to OgreConsole saying which character saw it, the text it matched and the full line. | off |
| **Ding - on success, play a 'Ding'** | When the text is seen, a 'Ding' sound plays on this PC. | off |
| **Add** | Adds the event to the list below. Pressing Enter in either text box does the same. While you are editing a row this button reads Update and saves your changes to that row. |  |
| **Clear Options** | Unticks OC and Ding. Ticks otherwise carry over to the next event you add. |  |
| **Cancel** | Only shown while editing a row. Stops editing without changing the row. |  |

## Good to know

- Nothing here works until "Enable Chat Events" is ticked on the Settings tab.
- The match ignores upper and lower case and can be anywhere in the line. Short text like "a" or "the" matches almost every line.
- An event with no command, no OC and no Ding is ignored, and the console prints a warning about it.
- The OC and Ding ticks stay ticked for the next event you add. Use Clear Options to untick them.
- Changes take effect within about a second. Press Save at the top to keep them for next time.
- Chat Events keep working while OgreBot is paused.

# Codex Inspect

Codex Inspect uploads the gear of the people in your group or raid to the EQ2Codex.com website, so you can see it there. You need an EQ2Codex API token first: press Setup API Token and paste the one from your eq2codex.com account. Opening the tab fills the left list (Roster) with your raid, or your group, or just you when solo. Each name shows how long until it can be inspected again, or 'ready'. Double-click names to move them into the right list (To Inspect), or press Queue All, then press Inspect Queued Now. The bot inspects each name in turn and uploads it. Names that upload leave the right list; names that fail stay there in red, marked FAIL.

| Option | What it does | Default |
|---|---|---|
| **Refresh from Group/Raid** | Reads your raid or group again and redraws the Roster. Opening the tab does this too. |  |
| **Roster (double-click to queue)** | Everyone in your raid, or your group, or just you when solo. Each name shows '(cd: ...)' with the time until it can be inspected again, or 'ready'. Double-click a name to add it to the To Inspect list.<br>*A name already in the To Inspect list is not added twice.* | empty until the tab is opened |
| **Queue All** | Adds every name in the Roster to the To Inspect list. |  |
| **To Inspect (double-click to remove)** | The names waiting to be inspected and uploaded. Double-click a name to take it out. Names leave on their own as they upload; failed ones stay in red, marked FAIL. | empty |
| **Clear Queue** | Empties the To Inspect list. It does not stop a run that has already started. |  |
| **Inspect Queued Now** | Starts a run: the bot inspects each name in the To Inspect list, one about every 3 seconds, and uploads their gear to eq2codex.com.<br>*Greyed out while a run is going. Names inspected in the last 5 minutes are skipped.* |  |
| **Reset Raid Force** | Clears your active group/raid on the eq2codex.com website, including the gear and adornments uploaded for it. Nothing on your PC changes.<br>*Greyed out while a run is going.* |  |

## Top of tab

| Control | What it does |
|---|---|
| **Visit EQ2Codex.com** | Opens eq2codex.com in your web browser. |
| **Wiki** | Opens the EQ2Codex help pages in your web browser. |
| **Setup API Token** | Opens the EQ2Codex API Token window, where you paste your token from eq2codex.com. The token is kept on this PC, outside your profile, and is never shown back to you.<br>*The same window opens from the Codex Toons tab. One token serves both.* |
| **View my Group/Raid** | Opens your active group/raid page on eq2codex.com in your web browser. |

## Good to know

- Nothing uploads until an API token is saved with Setup API Token. The line under the buttons says 'NOT configured' until then.
- A name inspected in the last 5 minutes is skipped. The Roster shows the time left for each name.
- The bot waits about 3 seconds between people, so a full raid takes a few minutes. Inspect Queued Now and Reset Raid Force are greyed out while a run is going.
- The inspect window pops open and closes for each person. That is normal.
- A FAIL row stays in the To Inspect list so you can see who failed. Press Inspect Queued Now again to retry them, or double-click to remove them.
- A '409' failure in the console means another uploader's account has already claimed that character.
- The To Inspect list is not saved in your profile. Closing OgreBot with its X stops a run in progress; the names not yet done stay in the list for next time you open it, until the bot is unloaded.

# Codex Toons

Codex Toons uploads a snapshot of your own character (gear and stats) to the EQ2Codex.com website. Press Setup API Token once to paste your token from eq2codex.com, then press Upload My Toon Snapshot whenever you want your page updated. The result, good or bad, is posted in OgreConsole. You can also have it upload by itself every time the bot camps you out. For your group or raid members, use the Codex Inspect tab instead.

| Option | What it does | Default |
|---|---|---|
| **Visit EQ2Codex.com** | Opens eq2codex.com in your web browser. |  |
| **Wiki** | Opens the EQ2Codex help pages in your web browser. |  |
| **Setup API Token** | Opens the EQ2Codex API Token window, where you paste your token from eq2codex.com. The token is kept on this PC, outside your profile, and is never shown back to you.<br>*Same window and same token as on the Codex Inspect tab.* |  |
| **Upload My Toon Snapshot** | Inspects your own character and uploads your gear and stats to eq2codex.com. OgreConsole reports whether it worked. |  |
| **(idle)** | The upload status: whether a token is set, and whether an upload is running. | (idle) |
| **View My Characters** | Opens your characters page on eq2codex.com in your web browser. |  |
| **View My Group/Raids** | Opens your saved groups and raids on eq2codex.com in your web browser. |  |
| **Auto-upload my toon snapshot to Codex when I camp (-camp / logout)** | When the bot camps you out, it first starts an upload of your toon snapshot. The camp does not wait for the upload.<br>*Only camps done by the bot count, not a /camp you type yourself.* | off |

## Good to know

- Nothing uploads until an API token is saved with Setup API Token. The same token is used by Codex Inspect.
- You must be in the world. The inspect window pops open on yourself for a moment while the bot reads your gear.
- If another upload is already running (for example a Codex Inspect run), the snapshot is refused and OgreConsole says so. Try again when it is done.
- The auto-upload on camp only happens when the bot does the camping (for example the camp command, or the Instance Controller's end-of-list camp). Typing /camp yourself does not upload.

# Consume Items

Consume Items keeps you using items such as potions and temporary buffs. While the bot is running and 'Enable Consume Items' is ticked on the Settings tab, it checks the list about once a second. It uses the first item that is in your bags and ready, then waits before using that item again for as long as its effect lasts (10 minutes if the bot cannot read the duration). The list order is the priority. By default it only works inside instances; the two boxes at the top also allow guild halls and overland zones. To build the list, click an item in the Full Item List (your registered items from the Items tab), tick 'In-combat' if it should only be used in combat, and press Add. On the Consume Item List, drag rows to change the order, click a row to edit it, double-click a row to switch it off or on, and use the x to remove it.

| Option | What it does | Default |
|---|---|---|
| **Full Item List** | Your registered items from the Items tab. Click one to pick it for the Add form, or double-click it to add it straight away with no options. | your registered items |
| **Consume Item List** | The items the bot uses, in priority order: each check it uses the first one that is in your bags, ready, and not waiting out its effect. 'IC' on a row means in combat only.<br>*Drag to reorder, click to edit, double-click to switch off or on, x to remove.* | empty |

## Where it works

| Control | What it does | Default |
|---|---|---|
| **Allow in Guild Halls** | Lets the list be used automatically in a guild hall. Without it, nothing is used there. | off |
| **Allow in Overland zones** | Lets the list be used automatically outside instances, in overland and city zones. Without it, items are only used inside instances. | off |

## Item lists

| Control | What it does | Default |
|---|---|---|
| **In-combat** | The item being added is only used while you are in combat. | off |
| **Add** | Adds the item picked on the left to the end of the list, with the In-combat option as ticked. When you are editing a row, it reads Update and saves your change. |  |
| **Clear Options** | Unticks In-combat. It otherwise stays ticked for the next Add. |  |

## Good to know

- Nothing happens unless 'Enable Consume Items' is ticked on the Settings tab. Pausing the bot also stops it.
- The Full Item List only shows items registered on the Items tab. If it is empty, register your consumables there first.
- Double-clicking an item on the left adds it straight away, without the In-combat option. To set it, click once, tick In-combat, then press Add.
- Nothing is used while you are moving or dead. In combat, the bot waits at least 5 seconds between uses.
- The wait for each item's effect is kept only while the session runs. After a reload the bot may use an item again straight away.
- The OgreConsole command `-ConsumeItems_ProcessList_AP` runs the list on demand (add `-all` to use every eligible item, not just the first). It ignores the zone boxes and the pause, but still needs 'Enable Consume Items'.
- To see what it picks and when, tick ConsumeItemsDebug on the Debug tab.

# Despawn Event

Despawn Event is the opposite of Spawn Events: it fires when something whose name contains your text disappears. The bot can then run a console command, post a line to OgreConsole, play a 'Ding' sound, or any mix of the three. Nothing happens until you tick "Enable Despawn Event" on the Settings tab. Build events with the boxes at the top; they appear in the Configured Events list below.

| Option | What it does | Default |
|---|---|---|
| **Configured Events** | Your despawn events. Click a row to edit it, double-click to switch it off or on, drag a row to reorder, and click X to delete it.<br>*A switched-off row is kept but never fires.* | empty |

## Add an event

| Control | What it does | Default |
|---|---|---|
| **Actor to watch for** | Part or all of the name to watch for. The event fires when something with a matching name disappears. Upper and lower case must match exactly.<br>*Required. An event with no name cannot be added.* | empty |
| **Code to execute (leave blank for nothing)** | A console command to run when a match disappears. It runs exactly as if you typed it into the InnerSpace console. Leave it blank if you only want the OC line or the Ding. | empty |
| **OC - on success, send a message to OgreConsole** | When a match disappears, a line goes to OgreConsole saying which character saw it, the text it matched and the full name. | off |
| **Ding - on success, play a 'Ding'** | When a match disappears, a 'Ding' sound plays on this PC. | off |
| **Add** | Adds the event to the list below. Pressing Enter in either text box does the same. While you are editing a row this button reads Update and saves your changes to that row. |  |
| **Clear Options** | Unticks OC and Ding. Ticks otherwise carry over to the next event you add. |  |
| **Cancel** | Only shown while editing a row. Stops editing without changing the row. |  |

## Good to know

- Nothing here works until "Enable Despawn Event" is ticked on the Settings tab.
- The name match is case-sensitive: "vindicator" does not match "a Vindicator". Part of the name is enough.
- Something leaving your view can count as disappearing, not only a mob that dies or despawns.
- An event with no command, no OC and no Ding is ignored, and the console prints a warning about it.
- The OC and Ding ticks stay ticked for the next event you add. Use Clear Options to untick them.
- Despawn events keep working while OgreBot is paused.

# Equipment Info

Equipment Info stores two charm choices so you can swap between them quickly. Pick an item in each drop-down (the choices are your registered items from the Items tab), then press Equip Charm 1 or Equip Charm 2. The bot looks for that item in your bags and asks the game to equip it. The buttons only affect this character. Scripts and OgreConsole can also run the same swap for other characters.

| Option | What it does | Default |
|---|---|---|
| **Charm Option 1:** | The item that 'Equip Charm 1' puts on. The list shows your registered items from the Items tab. | empty |
| **Charm Option 2:** | The item that 'Equip Charm 2' puts on. The list shows your registered items from the Items tab. | empty |
| **Equip Charm 1** | Finds the Charm Option 1 item in your bags and asks the game to equip it, on this character only.<br>*Does nothing but print a message if Charm Option 1 is empty or the item is not in your bags.* |  |
| **Equip Charm 2** | Finds the Charm Option 2 item in your bags and asks the game to equip it, on this character only.<br>*Does nothing but print a message if Charm Option 2 is empty or the item is not in your bags.* |  |

## Good to know

- The drop-downs are empty until you register items on the Items tab. They list every registered item, not only charms.
- The item must be in your bags (not the bank, and not already equipped). If it is not found, the console says so.
- The game can still refuse the swap, for example because of relic limits. The console line only says the bot asked.

# HO Excludes

HO Excludes lists abilities the bot must never use to work a Heroic Opportunity. When the bot picks an ability to match an HO icon, for the HO Starter or HO Wheel steps on the Settings tab or when a script asks for an HO icon ability, it skips anything on this list and uses another ability with that icon. Your normal Cast Stack rotation is not affected. Double-click an ability in the Full Ability list to add it. On the right, double-click a row to switch it off, or use the X to remove it. Changes apply straight away.

| Option | What it does | Default |
|---|---|---|
| **Full Ability list** | All of this character's abilities. Double-click one to add it to the exclude list. An ability that is already listed is not added twice. | your abilities |
| **Abilities to Exclude in HOs** | The abilities the bot will not pick for HO Starter or HO Wheel icons, shown A to Z. Double-click a row to switch it off (it is then used again), X to remove. | empty |

# HUDs

HUDs puts live text straight onto your game screen: the nearest mob, the nearest other player, how far each group or raid member is, and timed messages from encounter scripts. The text sits on a see-through layer over the whole game window. It has no title bar, you cannot click or drag it, and your mouse clicks go through it to the game. Each block is placed by its X and Y boxes, counted in screen pixels from the top-left corner. Changes take effect as soon as you make them. The layer appears when you tick any of the Display boxes (or when an encounter puts up a Raid Options message) and closes when OgreBot closes. The last section sets up the OSA (On-Screen Assistant), which is a separate window of its own.

## Nearest NPC

| Option | What it does | Default |
|---|---|---|
| **Display nearest NamedNPC/NPC** | Shows one line on your screen with the closest mob within 200 metres and its distance. A named mob always wins over a normal one, even if the normal one is closer. | off |
| **X** | How far from the left edge of the screen the Nearest NPC line starts, in pixels. | blank (300) |
| **Y** | How far down from the top of the screen the Nearest NPC line sits, in pixels. | blank (400) |

## Nearest PC

| Option | What it does | Default |
|---|---|---|
| **Display nearest PC** | Shows one line with the closest player within 200 metres who is not in your group or raid. The line is red under 30 metres, yellow under 150 and white further out. | off |

| **Y** | How far down from the top of the screen the Nearest PC line sits, in pixels. | blank (380) |
| **Msg alerts to OgreConsole** | When a player comes within 150 metres, and again within 30, a line such as 'Kannkor --> Nearest PC: Serath: 24.1 < 30' is posted to OgreConsole. Each player is reported once per distance band, and alerts are at least 5 seconds apart.<br>*Needs 'Display nearest PC' ticked.* | off |
| **Ding alerts** | Plays a short ding when a player comes within 30 metres. If 'Msg alerts' is also ticked, it dings at 150 metres too. A ding under 30 metres also posts the OgreConsole line, even without 'Msg alerts'.<br>*Needs 'Display nearest PC' ticked.* | off |
| **Loud alarm when close** | When a player comes within 30 metres, plays a louder two-tone alarm instead of the short ding.<br>*Does nothing on its own. 'Msg alerts' or 'Ding alerts' must also be ticked.* | off |

## Group Distance

| Option | What it does | Default |
|---|---|---|
| **Display group distance** | Shows a line for each other group member: their slot number, name, distance, their target and what they are casting. |---|---|---|

## What you see

- Nearest NPC - one white line: 'Named NPC: <name>: <distance>' for the closest named mob within 200 metres, or 'NPC: <name>: <distance>' when no named mob is in range.
- Nearest PC - one line: 'Nearest PC: <name>: <distance>' for the closest player within 200 metres who is not in your group or raid. It is red under 30 metres, yellow under 150 and white further out.
- Group distance - one line per group member (you are not listed): '(2) Brutus: 12.3 * <their target> * <what they are casting>'. Names are cut to their first 6 letters so the columns line up.
- Raid distance - one line per raid slot, '(01)' to '(24)', in the same layout as the group lines. An empty slot leaves a blank line and there is an extra gap after every 6 slots, so each line sits beside the matching row of the game's raid window.
- Group and raid line colours show distance: white under 20 metres, yellow under 30, orange under 75, red at 75 or more, grey when the game reports 0.
- The 'what they are casting' part shows the spell name for members running the new bot. For anyone else it just says 'casting'.
- Raid Options - up to 10 lines written by encounter files and scripts, usually a message with a countdown in seconds (for example 'Adds incoming: 12.4'). Each line disappears 5 seconds after its countdown ends.
- All HUD text is white-on-dark-outline monospace text so it stays readable on bright backgrounds. It refreshes about three times a second.

## Good to know

- The HUD layer has no title bar and ignores the mouse, so you cannot move it by dragging. Use the X and Y boxes to move each block.
- With 'Display raid distance' ticked and no raid, you see your group instead. So you do not need both boxes ticked. In a raid, the raid lines replace the group lines.
- The alert boxes only work while 'Display nearest PC' is ticked, and 'Loud alarm when close' does nothing unless 'Msg alerts' or 'Ding alerts' is also ticked.
- Scan Raid Window fills in the four Raid Distance boxes, but you still have to press Save to keep them.
- Emptying a position box does not move the block to 0,0. The block stays where it was, even after the profile is loaded again. It only goes back to its default position after the game client is restarted.

# Loot Distribution

Loot Distribution hands out gear from a Leader Only chest by Resolve. The looter asks the group about each piece of equipment. Every member's bot works out how much Resolve it would gain in the slot the item would replace, and the biggest gain wins. A plain upgrade always beats a 'maybe later' bid. The top half of this tab (Lootee and Weapon Choices) is what THIS character will accept when someone else's chest asks. The bottom half (Looter) only matters on the character opening the chest, and only when 'Loot Distribution' is ticked in the Leader Only block of the Loot tab.

## Lootee Options. Options receiving loot.

| Option | What it does | Default |
|---|---|---|
| **Match Type for secondary slot. Example: If you are using a tower shield, only accept a tower shield.** | For your secondary slot, this character only bids on the same kind of item it already holds there, for example tower shield for tower shield.<br>*If your secondary slot is empty, nothing matches, so you bid on nothing for that slot.* | off |
| **Weapons only for secondary slot. Example: Scouts/Brawlers - This means you will NOT accept a shield in your secondary.** | For your secondary slot, this character only bids on weapons (sword, dagger, mace, axe, rapier, hammer, fist, katana, great sword, great axe, great hammer, staff, spear). Shields and other off-hand items are refused.<br>*A weapon that also fits your primary slot can still be bid on for primary.* | off |
| **Match Type for ranged slot. Example: If you are using a crossbow, only accept a crossbow.** | For your ranged slot, this character only bids on the same kind of item it already holds there, for example crossbow for crossbow.<br>*If your ranged slot is empty, nothing matches.* | off |

## Weapon Choices

| Option | What it does | Default |
|---|---|---|
| **Do not accept two-handed weapons** | This character never bids on two-handed weapons.<br>*Tick both Weapon Choice boxes to take no weapons at all from distribution.* | off |
| **Do not accept one-handed weapons** | This character never bids on one-handed weapons. Shields and other off-hand items that are not weapons are still accepted.<br>*Ranged items are not affected.* | off |

## Looter Options. Options for the person opening the chest.

| Option | What it does | Default |
|---|---|---|
| **Only distribute items at or above a minimum Resolve:** | Only items with at least the Resolve in the box below are auctioned. Lower items go to the normal Leader Only loot boxes instead. | off |
| **Minimum Resolve** | The lowest Resolve an item needs to be auctioned. Only used when the box above is ticked. | empty (0 - no minimum) |

## Good to know

- Group only. In a raid nothing is auctioned; items go straight to the normal Leader Only loot boxes.
- Only the looter needs 'Loot Distribution' ticked on the Loot tab. Everyone else answers with the Lootee and Weapon Choice boxes from their own tab, whatever their own Loot tab says.
- Not auctioned: items with no Resolve, items you cannot equip, mercenary and mount gear, and items no class in the group can use. Those go to the normal loot boxes instead, as do items nobody bids on.
- A character never bids on an item it already has equipped or in its bags.
- 'Match Type' boxes need something in that slot. With an empty secondary or ranged slot and the box ticked, that character bids on nothing for that slot.

# OnZone

OnZone does two things each time you finish zoning. It runs the commands in the Executes list, top to bottom. Then it cancels any of your maintained spells that are on the 'Cancel after zoning' list. Both wait until the new zone has fully loaded (about three and a half seconds after it appears), so they act on a zone that is really there.

| Option | What it does | Default |
|---|---|---|
| **Executes** | Commands the bot runs, top to bottom, each time you finish zoning and the new zone has loaded. Switched-off lines are skipped.<br>*Runs even while OgreBot is paused. Double-click a line to switch it off; drag to reorder.* | empty |
| **Full Ability list** | All of this character's abilities. Click one and press Add below, or double-click it, to put it on the 'Cancel after zoning' list. |  |
| **Cancel after zoning** | After each zone has loaded, the bot cancels any of your maintained spells that match a name here, whatever its rank.<br>*Runs even while paused. Double-click a row to switch it off.* | empty |

## Executes

| Control | What it does | Default |
|---|---|---|
| **Command to run on zone** | Type a console command here. Put `eq2execute` in front of an in-game slash command. Press Enter or Add to put it on the list.<br>*Commas and ] are removed when you add the line.* | empty |
| **Add** | Adds the typed command to the end of the Executes list. It is not run now, only after your next zone. |  |

## Cancel after zoning

| Control | What it does |
|---|---|
| **Add** | Adds the ability you clicked in the Full Ability list to the cancel list. Greyed out until you click one. |

## Good to know

- Both lists work even while OgreBot is paused. They only need OgreBot to be loaded.
- The Executes list takes console commands. To run an in-game slash command, start the line with `eq2execute`. A command you add here is not run straight away.
- Commas and ] are removed from a command when you add it.
- The cancel list matches any rank: 'Assault' also cancels 'Assault XIII'. It only cancels spells you are maintaining (your own buffs and effects in the maintained window).
- To add a spell to the cancel list, click it in the Full Ability list and press Add, or double-click it. In the cancel list, double-click a spell to switch it off, and the x removes it. The cancel list is shown A to Z because order does not matter there.

# Other

Other holds options that do not have a tab of their own yet. The left column asks a dirge for Confront Fear when you have revive sickness, stops a few automatic cast cancels, and lets you accept group invites from any player nearby. The right column is a list of abilities the bot uses when you are stunned, stifled or rooted and have a detrimental on you, because the normal Cast Stack cannot act then.

| Option | What it does | Default |
|---|---|---|
| **Request confront fear via uplink.** | When you get revive sickness, send a request to your other characters over the uplink. A dirge among them, with OgreBot running (not paused) and in your group or raid in the same zone, casts Confront Fear on you. Used only if the raid and group chat requests below did not go out.<br>*Needs no message and no dirge in view; the other sessions decide if they can help. Fighters are cured first, then priests, then everyone else.* | off |

| **Request confront fear via raid chat:** | When you get revive sickness and another dirge is in your raid, say the text in the box beside this in raid chat. This is tried before group chat.<br>*Nothing is said if the box is empty.* | off |
| **(raid chat message)** | What to say in raid chat to ask for Confront Fear.<br>*A message containing the word NULL is not sent.* | empty |
| **[NOT RECOMMENDED] Do not cancel group cures when no one has a detrimental.** | Normally the bot stops a group cure mid-cast when nobody needs it any more. Tick this to let it finish anyway.<br>*Some raid scripts tick this during a fight.* | off |
| **[NOT RECOMMENDED] Do not cancel cure curse when no one has a curse.** | Normally the bot stops a Cure Curse mid-cast when the target no longer has a curse. Tick this to let it finish anyway. | off |
| **[NOT RECOMMENDED] Do not cancel res when the person has been res'd already.** | Normally the bot stops a res mid-cast when the target is no longer a corpse, for example because someone else res'd them first. Tick this to let it finish anyway. | off |
| **[NOT RECOMMENDED] Accept group/raid invites from ANYONE nearby.** | Accepts a group or raid invite from any player your client can see, not only from your own characters. It only works when 'Accept Invites' on the Settings tab is ticked too.<br>*Invites from your own characters are accepted by 'Accept Invites' alone.* | off |
| **Use these while stunned / stifled / rooted:** | While the bot is running and you are stunned, stifled or rooted with a detrimental on you, it casts the first ready ability from the list below. | **Delay between casts (seconds)** | How long to wait after one of these abilities fires before the next one may. Decimals work. Blank or not a number means 3 seconds; 0 means no wait. | empty (3 seconds) |
| **Full Ability list** | All of this character's abilities. Double-click one to add it to the end of the 'Use while disabled' list. |  |
| **Use while disabled (in order)** | The abilities to use while stunned, stifled or rooted, best first. The bot casts the first one that is ready; one on cooldown just lets the next one try.<br>*Group or raid cures are skipped while 'Disable Group/Raid Cures in CS' is ticked on Settings, and single-target ones while 'Disable Single Target Cures in CS' is ticked.* | empty |

## Good to know

- Confront Fear requests go out only once per revive sickness, and only while the bot is running. If you are paused when the sickness lands, the request waits until you resume. A revive at a scout camp is ignored.
- Only one channel is ever used for a request. Raid chat is tried first, then group chat, then the uplink.
- The stunned list only fires when you have an Arcane, Noxious, Elemental or Trauma detrimental. It does not check that the ability cures that type, so abilities that give immunity work too.
- 'Disable CS_Cure' on the Settings tab switches the stunned list off. The Enable Cures and Disable Cures commands also tick and untick 'Use these while stunned / stifled / rooted'.
- To add to the stunned list, double-click an ability in the Full Ability list. In the saved list, drag rows to set priority, double-click to switch one off, and the x removes it.

# Overseer

The left column controls the bot's daily Overseer run. The bot opens the Overseer window, turns in finished missions, adds any mission scrolls in your bags, starts new missions with the best agents it has, and afterwards uses any Research Material in your bags. The run starts on its own soon after OgreBot loads your profile, then at most once an hour. It will not start while the bot is paused, you are in combat or dead, or you are zoning. Start Overseer Now runs it straight away. The right column is a separate tool: stand at an Administrator Agent and it buys mission scrolls for you.

## Overseer

| Option | What it does | Default |
|---|---|---|
| **Do not touch overseer at all no matter what** | The bot does not run Overseer: no daily run, and Start Overseer Now does nothing (it says why in the console). Overseer reward windows are still answered.<br>*Buying missions (the right column) is a separate tool and still works.* | off |
| **Only do overseer when in a guild hall** | The bot only starts the daily Overseer run on its own while you are in a guild hall.<br>*Start Overseer Now works anywhere.* | off |
| **ONLY do Heritage Hunt [Daily]** | The only new mission the bot starts is 'Heritage Hunt [Daily]', and it skips Mishap missions. It still turns in finished missions and adds scrolls from your bags. | off |

| **Do not select overseer rewards when multiple are present** | When an Overseer reward window offers a choice, the bot normally takes the first reward. Tick this to leave the window for you. | off |

# Pack Pony

Pack Pony sends your Artisan's Pack Pony out to gather harvests by itself. With 'Enable Pack Pony' ticked and the bot running, the bot summons the pony, hails it and answers its questions using your choices below. If the pony offers to empty its packs, the bot accepts that first and then hails it again. The bot is paused while it does this and resumed afterwards. After a successful send-out it waits 2 hours 5 minutes before trying again, 10 minutes if the pony is still out or something failed, and 1 minute if you were busy. The three groups of boxes are the answers to the pony's three questions. Tick one box per group; ticking a box unticks the others in that group.

| Option | What it does | Default |
|---|---|---|
| **Enable Pack Pony** | While the bot is running, it sends your pack pony out whenever the wait from the last run is over. | off |
| **In Guild Hall only** | The pony is only sent out while you are in a guild hall. | off |
| **Do not dismiss when finished** | The pony stays summoned after the run. Normally the bot dismisses it when it is done.<br>*Runs started by TaskRunner still dismiss it.* | off (the pony is dismissed) |
| **Conversation 1 - Option 1 (1-59 harvests)** | When the pony asks its first question ('I need some level ... harvests'), the bot picks reply 1. | off |
| **Conversation 1 - Option 2 (60-99 harvests)** | When the pony asks its first question, the bot picks reply 2. | off |
| **Conversation 1 - Option 3 (100+ harvests)** | When the pony asks its first question, the bot picks reply 3. This is also used when no box in this group is ticked. | off (used anyway when none is ticked) |
| **Conversation 1 - Option 4 (Special Events?)** | When the pony asks its first question, the bot picks reply 4. | off |
| **Conversation 2 - Option 1 (1-9 / 60-69 / 100-109 harvests)** | When the pony asks its second question ('Gather level ... harvests'), the bot picks reply 1. | off |
| **Conversation 2 - Option 2 (10-19 / 70-79 / 110-120 harvests)** | When the pony asks its second question, the bot picks reply 2. | off |
| **Conversation 2 - Option 3 (20-29 / 80-89 / 120-130 harvests)** | When the pony asks its second question, the bot picks reply 3. This is also used when no box in this group is ticked. | off (used anyway when none is ticked) |
| **Conversation 2 - Option 4 (30-39 / 90-95 / 131-140 harvests)** | When the pony asks its second question, the bot picks reply 4. | off |
| **Conversation 3 - Option 1 (VoV 120-125 / PoM 110 / Thalumbra harvests / RoC 135)** | When the pony asks its third question ('Gather harvests from ...'), the bot picks reply 1. | off |
| **Conversation 3 - Option 2 (RoR 125 / EP 110 harvests)** | When the pony asks its third question, the bot picks reply 2. This is also used when no box in this group is ticked. | off (used anyway when none is ticked) |
| **Conversation 3 - Option 3 (BoZimara 125-130 / Luclin 110-120 harvests)** | When the pony asks its third question, the bot picks reply 3. | off |
| **Conversation 3 - Option 4 (SoD 130 harvests)** | When the pony asks its third question, the bot picks reply 4. | off |

## Good to know

- The character needs the 'Summon Artisan's Pack Pony' ability, or the run does not start.
- It never starts while you are in combat, while the bot is paused, or while another conversation window is open.
- If no box in a group is ticked, the bot uses option 3 for Conversations 1 and 2, and option 2 for Conversation 3.
- The boxes follow your earlier picks, the way the pony's questions do: Conversation 2 shows the replies the pony offers after your Conversation 1 pick (six under 1-59 harvests, five under 60-99, four under 100+), and Conversation 3 is only asked under 100+ harvests. Where a reply is not known (Special Events, Conversation 3 below 100) the boxes read 'placeholder' and can still be picked, in case the game adds one. A ticked box your path does not offer says 'not offered ..., pick another'. The options listed on this page are the ones shown for 100+ harvests, 120-130.
- The wait timers are kept only while the session runs. After a reload the bot tries again straight away.
- The harvest ranges in the box names describe what each reply meant in the old bot. The bot clicks the reply by its number (Option 1 = the first reply), so check them in game if the pony's replies change.

# Post-Cast

Post-Cast casts one thing right AFTER another has finished. Each row says 'after the bot casts B, cast A'. A can be an ability or an item; B is the ability that sets it off. For a spell with a cast time, A goes out once the cast bar is done; for an instant, straight after. Several rows can share the same B; they go one at a time, top to bottom.

| Option | What it does | Default |
|---|---|---|
| **1. Cast THIS  (ability or item)** | Pick what the bot should cast afterwards. Click an ability or item to select it for the next row. |  |
| **2. ...after this is cast** | Pick the ability that sets it off. After the bot casts this ability, the pick from list 1 follows. |  |
| **Post-casts setup** | Your post-cast rows, shown as 'what to cast   After: what it follows'. Rows for the same ability fire top to bottom, one at a time, once that ability's cast is over.<br>*Double-click a row to switch it off. Drag to reorder.* | empty |

## Post-Cast

| Control | What it does |
|---|---|
| **Add** | Saves your two picks as a new row at the end of 'Post-casts setup'. It stays greyed out until you have picked one entry in each list. |

## Good to know

- To add a row, click the thing to cast in list 1, click the ability it follows in list 2, then press Add under 'Post-casts setup'. The text next to Add shows your two picks.
- Any cast the bot makes can set off a post-cast: the Cast Stack, scripts and commands. Abilities you click yourself do not.
- If your cast bar stays busy with something else for more than about 2 seconds after B, the post-cast is dropped, because it would no longer be 'after B'.
- Names match any rank: 'Assault' also matches 'Assault XIII'. An ability must be ready; items are just tried.
- A row that points at itself is ignored, and a post-cast never sets off another post-cast or a pre-cast.
- 'Disable Post-Cast tab' on the Settings tab switches this whole tab off. While a script has 'Dynamic Ignore Encounter CAs' or 'Dynamic Ignore PBAE CAs' ticked, post-casts of that kind are skipped too.
- In 'Post-casts setup', drag a row to change the order, double-click a row to switch it off, and the x removes it.

The two Disable boxes at the top switch notifications off without losing your choices below.

| **[Normal Priority] When a loot window has been open for 60 seconds.** | If a loot window is still open 60 seconds after it appeared, you get a notification listing the items in it. | off |
| **[Normal Priority] When smartloot assigns an item.** | Each time SmartLoot gives an item to someone, you get a notification with the time, who got it and the item. | off |
| **[Normal Priority] When you get an in-game TELL from someone on your eq2chars list.** | When one of your own characters (anyone on the EQ2Chars tab) sends you a tell, you get a notification with who sent it and what they said. | off |
| **[HIGHEST Priority] When you get an in-game TELL from someone NOT on your eq2chars list.** | When anyone not on your EQ2Chars list sends you a tell, you get a high-priority notification with who sent it and what they said.<br>*This is the one notification that still gets through 'Disable Normal Pushover Messages'.* | off |

## Good to know

- Nothing is sent until your Pushover application token and user key are saved with 'Set up Pushover account'. They are kept on this PC, outside your profile.
- No tell notification is sent if you sent that person a tell in the last 60 seconds. You are clearly at the keyboard already.
- Notifications go out at most about one every 10 seconds. If many pile up, the oldest waiting ones are dropped.
- Scripts and commands can also send Pushover messages. The two Disable boxes block those too.

# Spawn Events

Spawn Events works like Chat Events, but it watches for things appearing around you instead of chat. When something appears whose name contains your text, the bot can run a console command, post a line to OgreConsole, play a 'Ding' sound, or any mix of the three. Nothing happens until you tick "Enable Spawn Events" on the Settings tab. Build events with the boxes at the top; they appear in the Configured Events list below.

| Option | What it does | Default |
|---|---|---|
| **Configured Events** | Your spawn events. Click a row to edit it, double-click to switch it off or on, drag a row to reorder, and click X to delete it.<br>*A switched-off row is kept but never fires. Every active row is checked, so the order does not matter.* | empty |

## Add an event

| Control | What it does | Default |
|---|---|---|
| **Actor to watch for** | Part or all of the name to watch for. The event fires when something with a matching name appears. Upper and lower case must match exactly.<br>*Required. An event with no name cannot be added.* | empty |
| **Code to execute (leave blank for nothing)** | A console command to run when a match appears. It runs exactly as if you typed it into the InnerSpace console. Leave it blank if you only want the OC line or the Ding. | empty |
| **OC - on success, send a message to OgreConsole** | When a match appears, a line goes to OgreConsole saying which character saw it, the text it matched and the full name of what appeared. | off |
| **Ding - on success, play a 'Ding'** | When a match appears, a 'Ding' sound plays on this PC. | off |
| **Add** | Adds the event to the list below. Pressing Enter in either text box does the same. While you are editing a row this button reads Update and saves your changes to that row. |  |
| **Clear Options** | Unticks OC and Ding. Ticks otherwise carry over to the next event you add. |  |
| **Cancel** | Only shown while editing a row. Stops editing without changing the row. |  |

## Good to know

- Nothing here works until "Enable Spawn Events" is ticked on the Settings tab.
- The name match is case-sensitive: "vindicator" does not match "a Vindicator". Copy the name exactly as the game shows it. Part of the name is enough.
- It fires when something comes into your view, not only for a fresh spawn. Things that were already around when OgreBot was loaded do not fire.
- An event with no command, no OC and no Ding is ignored, and the console prints a warning about it.
- The OC and Ding ticks stay ticked for the next event you add. Use Clear Options to untick them.
- Spawn Events keep working while OgreBot is paused.

# Tags

Tags let one bot's cast switch other abilities off or on for a while, across all your bots. On the Cast Stack you give an ability an Embargo tag (it is blocked while the tag is on) or an Allow tag (it may only fire while the tag is on). When the bot casts an ability that carries a tag, the tag turns on, on this bot and on your other bots in the same relay group, for the time set here (a Cast Stack row set to 'Listen Only' never turns its tag on, and one set to 'Trigger Only' is not held back by it). This tab is where each tag is defined. The left list holds your tag names: type a name under it and press Add. Click a name to pick it, set its duration and options on the right, and press Add to put it in the Tags List. A tag that is not in the Tags List never turns on.

| Option | What it does | Default |
|---|---|---|
| **Full Tag List** | Your tag names, sorted A-Z. Click a name to pick it for the Tags List on the right. Double-click a name to rename it, and click X to delete it.<br>*A name here does nothing until it is also added to the Tags List. Renaming it here does not rename it in the Tags List.* | empty |
| **Tags List** | The tags that are actually defined, with their duration and options. Click a row to edit it and click X to delete it.<br>*Only tags in this list can turn on.* | empty |

## Top of tab

| Control | What it does | Default |
|---|---|---|
| **Globally mute all tag messages** | **Not active yet.** In the old bot it hid the tag lines in OgreConsole. | off |

## Full Tag List (left)

| Control | What it does | Default |
|---|---|---|
| **Tag name** | Type a new tag name here. Use the same name you put in the Embargo tag or Allow tag box on the Cast Stack. | empty |
| **Add** | Adds the typed name to the Full Tag List. While you are renaming a name this reads Update. |  |

## Tags List (right)

| Control | What it does | Default |
|---|---|---|
| **Duration** | How many seconds the tag stays on after the ability is cast. Leave it blank to use the ability's own duration.<br>*Items need a number here.* | blank (the ability's own duration) |
| **IRC** | **Not active yet.** In the old bot it also sent the tag over IRC. | off |
| **Group** | The tag only turns on for bots in the caster's own group, instead of every bot in your relay group. | off |
| **Me** | The tag only turns on for the character who cast the ability. Your other bots are not told. | off |
| **Incl. caster** | **Not active yet.** In the old bot it added the caster's name and the ability to the tag message. | off |
| **Hide from OgreConsole** | **Not active yet.** In the old bot it kept the tag message out of OgreConsole. | off |
| **Maintained** | The tag stays on while the caster still has the buff in their maintained list, and turns off for every bot as soon as it drops. The duration is then only a safety limit.<br>*Any rank of the ability counts. For an item it is the buff the item puts on you when you use it.* | off |
| **Add** | Adds the picked tag name, with the duration and ticks you set, to the Tags List. While you are editing a row this reads Update and saves your changes. |  |
| **Clear Options** | Unticks every option. Ticks otherwise carry over to the next tag you add. |  |

## Good to know

- A tag used on the Cast Stack but missing from the Tags List (or typed differently) never turns on. The match ignores upper and lower case.
- Leave Duration blank to use the ability's own duration. An item has no duration of its own, so an item that sets a tag must have a Duration here or the tag does not turn on.
- Two bots can hold the same tag at once; it stays on until the last one runs out.
- Only three options change anything: Group, Me and Maintained. IRC, Incl. caster and Hide from OgreConsole are shown for your information - the bot saves them but does not act on them (by design).
- The ticks stay ticked for the next tag you add. Use Clear Options to untick them.
- Press Save at the top to keep your changes for next time.
- Changes to the Tags List are used straight away. Press Save at the top to keep them for next time.

# Unload

Unload is a list of commands the bot runs, top to bottom, when OgreBot closes. That is the X on the OgreBot window or its mini toolbar, or `ogre end bot`. It also happens when you camp to another character in the same game window, because OgreBot closes and reopens for the new character.

| Option | What it does | Default |
|---|---|---|
| **Executes** | Commands the bot runs, top to bottom, when OgreBot closes. Switched-off lines are skipped.<br>*Also runs when you swap to another character in the same game window.* | empty |

## Executes

| Control | What it does | Default |
|---|---|---|
| **Command to run on unload** | Type a console command here. Put `eq2execute` in front of an in-game slash command. Press Enter or Add to put it on the list.<br>*Commas and ] are removed when you add the line.* | empty |
| **Add** | Adds the typed command to the end of the list. It is not run now, only when OgreBot closes. |  |

## Good to know

- The list takes console commands. To run an in-game slash command, start the line with `eq2execute`.
- Unlike the Load tab, a command you add here is NOT run when you add it. It only runs when OgreBot closes.
- Commas and ] are removed from a command when you add it. A line that needs them will not run as typed.
- Double-click a line to switch it off without deleting it. Drag a row to change the order. The x removes it.
