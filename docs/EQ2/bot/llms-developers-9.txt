# ISXOgreEQ2.DepotTransfer

## Members

### `Running`

`${ISXOgreEQ2.DepotTransfer.Running}`

TRUE while a house-to-guild-hall, guild-hall-to-house or small-to-large depot transfer is running. Only one transfer runs at a time; starting another is refused with a busy warning.

**Returns:** bool: TRUE while a depot transfer is running; FALSE when idle.

```text
echo ${ISXOgreEQ2.DepotTransfer.Running}
```

### `Status`

`${ISXOgreEQ2.DepotTransfer.Status}`

The running transfer's current depot type, its place in the list and how many withdrawals have been made, or "idle". It is the same text `${ISXOgreEQ2.DepotTransfer}` returns.

**Returns:** string: "idle", or "&lt;type> (n/total, k pulled)" where type is harvest, ammo, adorn, food, lore, potion, collectible, fuel or scroll.

```text
echo ${ISXOgreEQ2.DepotTransfer.Status}
```

## Methods

### `GHToHouse`

`ISXOgreEQ2.DepotTransfer:GHToHouse[flags...]`

The engine behind `ogre ghtohouse`: must start in your guild hall, then withdraws each chosen guild hall depot and deposits it into the matching personal house depot, travelling back and forth until that depot is empty (at most 40 trips per type). If a house depot says it cannot hold any more, the rest goes back into the guild hall depot and that type is skipped; each house depot must be within 8 m of where you arrive in the house.

| Parameter | Type | Default | Meaning |
|---|---|---|---|
| `flags...` | string |  | -all (the eight shared depot types, not scroll), or any of -harvest/-h, -ammo, -adorn, -food, -lore, -potion, -collect/-collectible/-c, -fuel, each with a -no twin (-noharvest/-nh, -nocollect/-nocollectible/-nc, -nofuel ...); read left to right so `-all -nofuel` is all but fuel; a bare word is the house owner to enter (default your own name); an unknown flag is warned about and ignored; at least one depot type must end up selected or the call is refused; -scroll adds the scroll depot, which -all does not include |

```text
ISXOgreEQ2.DepotTransfer:GHToHouse[-harvest,-scroll]
```

### `HouseToGH`

`ISXOgreEQ2.DepotTransfer:HouseToGH[flags...]`

The engine behind `ogre housetogh`: empties the chosen personal house depots into the matching guild hall depots, travelling between the guild hall and the house as often as needed (at most 40 trips per depot type), and pulling Superior Rune items one at a time. Started in the guild hall it first deposits what you carry there; each guild hall depot must be within 11 m of where you arrive, and a missing door or depot stops the run with a console warning.

| Parameter | Type | Default | Meaning |
|---|---|---|---|
| `flags...` | string |  | -all (the eight shared depot types, not scroll), or any of -harvest/-h, -ammo, -adorn, -food, -lore, -potion, -collect/-collectible/-c, -fuel, each with a -no twin (-noharvest/-nh, -nocollect/-nocollectible/-nc, -nofuel ...); read left to right so `-all -nofuel` is all but fuel; a bare word is the house owner to enter (default your own name); an unknown flag is warned about and ignored; at least one depot type must end up selected or the call is refused; -scroll is warned about as unknown here (there is no house scroll depot) |

```text
ISXOgreEQ2.DepotTransfer:HouseToGH[-all,-nofuel]
```

### `SmallToLarge`

`ISXOgreEQ2.DepotTransfer:SmallToLarge[flags...]`

The engine behind `ogre smalldepottobigdepot`: in your guild hall, withdraws one depot type from "&lt;type> Depot" and deposits it into "&lt;type> Depot (Large)" (within 11 m), repeating until the small depot is empty. It is refused outside a guild hall or for an unknown type; with the do-not-deposit option it fills your bags once and stops.

| Parameter | Type | Default | Meaning |
|---|---|---|---|
| `flags...` | string | `-harvest` | one depot type: -harvest, -adorn/-adornment, -ammo, -scroll/-spell, -collectible/-collectable, -food/-drink, -fuel, -lore/-legend or -potion/-poison/-totem (the last one given wins); TRUE, 1 or -donotdeposit only fills your bags, FALSE or 0 turns that off again; any other word refuses the call |

```text
ISXOgreEQ2.DepotTransfer:SmallToLarge[-adorn]
```

### `Stop`

`ISXOgreEQ2.DepotTransfer:Stop`

Stops the running depot transfer and prints "depot transfer: stopped."; does nothing when idle. You stay where the transfer had got to, and items already withdrawn stay in your bags.

```text
ISXOgreEQ2.DepotTransfer:Stop
```

# ISXOgreEQ2.Det

## Members

### `DetrimentalInfo`

`${ISXOgreEQ2.Det.DetrimentalInfo[mainIconID,backdropIconID,-actorID,-maxEffects,field]}`

One field of a detrimental effect matched by its icon pair: on you (no -actorID, or your own ID) it reads the bot's detrimental tracker, which refreshes about every 500 ms, and for any other actor it walks that actor's effect list live, the first 10 effects unless -maxEffects says otherwise. Numeric fields (exists, id, mainiconid, backdropiconid, currentincrements, duration, maxduration, iseffectinfoavailable) come back as a number - 0 when not found, duration in whole seconds, and always 0 for duration on another actor - while any other field name (Name, Description, Type...) reads the game's effect info, a server request, and the read is NULL out of the world or with fewer than two arguments.

| Parameter | Type | Default | Meaning |
|---|---|---|---|
| `mainIconID` | int |  | the effect's MainIconID |
| `backdropIconID` | int |  | the effect's BackDropIconID |
| `-actorID` | switch | `0 (you)` | -actorID &lt;id>: read this actor's effects instead of yours |
| `-maxEffects` | switch | `10` | -maxEffects &lt;n>: how many of another actor's effects to walk; 0 walks them all; not used for you |
| `field` | string | `exists` | the field to return; the last word that is not a switch wins. A read changes nothing: ISXOgreEQ2.Det:DetrimentalCancel is the way to cancel |

**Returns:** int64 or string: exists is 1 or 0; id, icon ids, currentincrements, duration and maxduration are numbers (0 when not found); any other field is a string (empty when not found).

```text
echo ${ISXOgreEQ2.Det.DetrimentalInfo[176,313,-actorID,${Target.ID},currentincrements]}
```

### `DetrimentalInfo_JSON`

`${ISXOgreEQ2.Det.DetrimentalInfo_JSON[mainIconID,backdropIconID,-actorID,-maxEffects,-ExtraFields]}`

A detrimental effect as JSON (ID, BackDropIconID, MainIconID, CurrentIncrements, Duration, MaxDuration): with no icon pair (or 0,0) a JSON array of every detrimental on you (or of another actor's first effects with -actorID), and with an icon pair that one effect as an object, {} when not found. The switches are read in any position and the first two other arguments are the icon pair; Duration and MaxDuration are always 0 for another actor, and the read is NULL out of the world.

| Parameter | Type | Default | Meaning |
|---|---|---|---|
| `mainIconID` | int | `0` | the effect's MainIconID; 0 with backdropIconID 0 lists every effect |
| `backdropIconID` | int | `0` | the effect's BackDropIconID; with fewer than two icon arguments there is no pair (0,0) |
| `-actorID` | switch | `0 (you)` | -actorID &lt;id>: read this actor's effects instead of yours |
| `-maxEffects` | switch | `10` | -maxEffects &lt;n>: how many of another actor's effects to walk; 0 walks them all; not used for you |
| `-ExtraFields` | switch | `off` | -ExtraFields: add Name, Description, Type, UsesRemaining, NumEffectStrings and EffectStrings to a matched effect (a server request); not applied to the whole list |

**Returns:** string: a JSON array (every effect) or a JSON object (one matched effect, {} when not found).

```text
echo ${ISXOgreEQ2.Det.DetrimentalInfo_JSON}
```

## Methods

### `DetrimentalCacheClear`

`ISXOgreEQ2.Det:DetrimentalCacheClear`

Empties the bot's detrimental tracker, so its next scan sees every detrimental still on you as new. That fires OgreEvent_OnDetrimentalAdded again for each of them and echoes a +det line for each.

```text
ISXOgreEQ2.Det:DetrimentalCacheClear
```

### `DetrimentalCancel`

`ISXOgreEQ2.Det:DetrimentalCancel[mainIconID,backdropIconID]`

Cancels the detrimental effect on you with this icon pair, immediately, and echoes a cancel line to the console when it finds it. It says nothing when no such effect is on you; OgreBotAPI.Cures:CancelDetrimental is the same cancel with a for-who and a not-found message.

| Parameter | Type | Default | Meaning |
|---|---|---|---|
| `mainIconID` | int |  | the effect's MainIconID |
| `backdropIconID` | int |  | the effect's BackDropIconID |

```text
ISXOgreEQ2.Det:DetrimentalCancel[176,313]
```

### `Dump`

`ISXOgreEQ2.Det:Dump[mode,-noinfo]`

The `ogre dets` console dump: lists every detrimental on you from the tracker (dets, the default), your maintained spells and their targets (m), or your target's effects (target), one line each. By default it also reads each detrimental's Name and Description, a server request per effect, which -noinfo skips; out of the world it only prints a warning.

| Parameter | Type | Default | Meaning |
|---|---|---|---|
| `mode` | string | `dets` | dets (or det, d), m (or maintained), target (or t); -h, -help or ? as the first word prints usage |
| `-noinfo` | switch | `off` | skip the Name and Description reads; -info turns them back on |

```text
ISXOgreEQ2.Det:Dump[dets,-noinfo]
```

### `Set_DetrimentalScanTime`

`ISXOgreEQ2.Det:Set_DetrimentalScanTime[ms]`

Sets how often, in milliseconds, the bot's detrimental tracker rescans your detrimentals (500 by default); every reader of the tracker sees the change. A value outside 100 to 5000 is refused with a console warning and the interval stays as it was, and the setting is not saved.

| Parameter | Type | Default | Meaning |
|---|---|---|---|
| `ms` | int |  | the scan interval in milliseconds, 100 to 5000 |

```text
ISXOgreEQ2.Det:Set_DetrimentalScanTime[250]
```

# ISXOgreEQ2.EffectTracker

## Methods

### `Bench`

`ISXOgreEQ2.EffectTracker:Bench`

Times the reads of the open examine window and prints the result.

```text
ISXOgreEQ2.EffectTracker:Bench
```

### `Close`

`ISXOgreEQ2.EffectTracker:Close`

Closes the window and leaves the captures as they are. :End disarms them too.

```text
ISXOgreEQ2.EffectTracker:Close
```

### `CloseWindow`

`ISXOgreEQ2.EffectTracker:CloseWindow[word]`

Closes the top examine window. They stack, so all closes the whole stack, up to 12.

| Parameter | Type | Default | Meaning |
|---|---|---|---|
| `word` | string |  | all closes every one. Optional. |

```text
ISXOgreEQ2.EffectTracker:CloseWindow[all]
```

### `Demo`

`ISXOgreEQ2.EffectTracker:Demo`

Fills the window with sample data and opens it, for looking at the layout. Nothing is saved.

```text
ISXOgreEQ2.EffectTracker:Demo
```

### `Describe`

`ISXOgreEQ2.EffectTracker:Describe[state]`

Turns the Description capture on or off and prints the status. On, each new effect costs one server read, once ever; off, only Description is lost.

| Parameter | Type | Default | Meaning |
|---|---|---|---|
| `state` | string |  | on or off. Optional: anything but off, or nothing, turns it on. |

```text
ISXOgreEQ2.EffectTracker:Describe[off]
```

### `End`

`ISXOgreEQ2.EffectTracker:End`

Disarms both captures, which saves them, and closes the window, the same as `ogre end effecttracker` and the window's X.

```text
ISXOgreEQ2.EffectTracker:End
```

### `Merge`

`ISXOgreEQ2.EffectTracker:Merge`

Merges this zone's temporary capture files into the dataset and prints the result.

```text
ISXOgreEQ2.EffectTracker:Merge
```

### `Npc`

`ISXOgreEQ2.EffectTracker:Npc[state]`

Arms or disarms the NPC effect capture and prints the status.

| Parameter | Type | Default | Meaning |
|---|---|---|---|

```text
ISXOgreEQ2.EffectTracker:Npc[on]
```

### `Off`

`ISXOgreEQ2.EffectTracker:Off`

Disarms both captures and prints the status. The window stays up.

```text
ISXOgreEQ2.EffectTracker:Off
```

### `On`

`ISXOgreEQ2.EffectTracker:On`

Arms the player capture and prints the status.

```text
ISXOgreEQ2.EffectTracker:On
```

### `Open`

# ISXOgreEQ2.Encounter

## Members

### `ActiveCount`

`${ISXOgreEQ2.Encounter.ActiveCount}`

The number of encounters that are setting up or running right now.

**Returns:** int: encounters in setup or active; 0 when none.

```text
echo ${ISXOgreEQ2.Encounter.ActiveCount}
```

### `Current`

`${ISXOgreEQ2.Encounter.Current}`

The encounters setting up or running right now, as a JSON array. Each entry has primary (the first named mob), state ("setup" or "active"), named (every named mob), expansion and zone.

**Returns:** string: a JSON array of the active encounters; "[]" when none.

```text
echo ${ISXOgreEQ2.Encounter.Current}
```

### `IsActive`

`${ISXOgreEQ2.Encounter.IsActive[mob]}`

Whether any loaded encounter naming that mob is setting up or running. The mob name is matched ignoring case, whatever zone you are in.

| Parameter | Type | Default | Meaning |
|---|---|---|---|
| `mob` | string |  | The named mob's name. |

**Returns:** bool: TRUE when that mob's encounter is in setup or active; FALSE when it is not, when no encounter owns that name, or when no name is given.

```text
echo ${ISXOgreEQ2.Encounter.IsActive[${Target.Name}]}
```

### `Loaded`

`${ISXOgreEQ2.Encounter.Loaded}`

The number of encounter files loaded, across every zone. It changes when a reload or a zone-in picks up new or edited files.

**Returns:** int: the number of loaded encounters.

```text
echo ${ISXOgreEQ2.Encounter.Loaded}
```

### `Sequences`

`${ISXOgreEQ2.Encounter.Sequences}`

Every live encounter sequence as a JSON array, so you can see which step a fight is waiting on. Each entry names its encounter and holds either its condition rules or the list it is running (setup, a trigger and so on) with the current step.

**Returns:** string: a JSON array of live sequences; "[]" when none.

```text
echo ${ISXOgreEQ2.Encounter.Sequences}
```

## Methods

### `Debug`

`ISXOgreEQ2.Encounter:Debug[switch,value]`

Turns the console echo of encounter messages (comms) or step changes (steps) on or off, then prints both settings; with no switch it only prints them - the same as `ogre encounter debug`. Both are always written to the log; an unknown switch or a missing on/off prints a warning and changes nothing.

| Parameter | Type | Default | Meaning |
|---|---|---|---|
| `switch` | string | `""` | comms or steps; blank just prints the current settings. |
| `value` | string | `""` | on or off; needed when switch is given. |

```text
ISXOgreEQ2.Encounter:Debug[steps,on]
```

### `Fire`

`ISXOgreEQ2.Encounter:Fire[mob]`

Sets up for an encounter on the next pulse: the fight of the named mob given, or with no name the nearest or engaged named in this zone; a setup already running is started again. It is OgreBotAPI.Bot:SetUpFor without the for-who, and it is ignored with a warning when Enable Raid Setups (raid zones) or Enable Heroic Setups (other zones) is off, or when no encounter owns that name.

| Parameter | Type | Default | Meaning |
|---|---|---|---|
| `mob` | string | `""` | The named mob whose encounter to set up; blank picks the nearest or engaged named in this zone. |

```text
ISXOgreEQ2.Encounter:Fire[${Target.Name}]
```

### `Help`

`ISXOgreEQ2.Encounter:Help`

Prints the `ogre encounter` words (reload, debug and sequences) with one line each to the console, the same as typing a bare `ogre encounter`.

```text
ISXOgreEQ2.Encounter:Help
```

### `List`

`ISXOgreEQ2.Encounter:List`

Prints this zone's encounter coding to the console: one line per fight with its named mobs, (DISABLED) when switched off, and its file. It always answers, even "No encounter coding for this zone", and is OgreBotAPI.Encounter:List without the for-who.

```text
ISXOgreEQ2.Encounter:List
```

### `Reload`

`ISXOgreEQ2.Encounter:Reload`

Re-reads every encounter file from disk in the background and swaps the new set in when it is done, which ends every encounter setup and sequence in progress - the same as `ogre encounter reload`. It prints one line at once and a second with the loaded, scanned and error counts when the swap lands.

```text
ISXOgreEQ2.Encounter:Reload
```

### `Sequences`

`ISXOgreEQ2.Encounter:Sequences`

Prints the Sequences JSON to the console, or "(none live)" when nothing is running - the same as `ogre encounter sequences`.

```text
ISXOgreEQ2.Encounter:Sequences
```

# ISXOgreEQ2.Events

## Members

### `Count`

`${ISXOgreEQ2.Events.Count}`

How many native game events the extension listens to, currently 14, numbered from 0 for the event argument of Received, Dispatched, Subscribers, EventName and NativeName.

**Returns:** int: the number of events (14 today)

```text
echo ${ISXOgreEQ2.Events.Count}
```

### `Dispatched`

`${ISXOgreEQ2.Events.Dispatched[<event>]}`

How many arrivals of this game event have been handed out to the extension's features since it loaded, or the total for all events when the argument is left out. It trails Received only by what is still Pending, and an unknown event gives NULL.

| Parameter | Type | Default | Meaning |
|---|---|---|---|
| `&lt;event>` | string |  | The event's 0-based number or its name, such as ActorSpawned; leave it out for the total across all events |

**Returns:** int64: arrivals handed out for that event since load (or for all events); NULL for an unknown event

```text
echo ${ISXOgreEQ2.Events.Dispatched[ActorSpawned]}
```

### `Dropped`

`${ISXOgreEQ2.Events.Dropped}`

Total game events thrown away since the extension loaded, because more than 4096 were waiting at once (oldest dropped first) or the event was not recognised. It never resets.

**Returns:** int64: events dropped since load

```text
echo ${ISXOgreEQ2.Events.Dropped}
```

### `EventName`

`${ISXOgreEQ2.Events.EventName[<event>]}`

The extension's name for a game event, such as IncomingChatText, looked up by its 0-based number or its name. A missing or unknown event gives NULL.

| Parameter | Type | Default | Meaning |
|---|---|---|---|
| `&lt;event>` | string |  | The event's 0-based number (0 to Count minus 1) or its name |

**Returns:** string: the event's name; NULL for a missing or unknown event

```text
echo ${ISXOgreEQ2.Events.EventName[0]}
```

### `NativeName`

`${ISXOgreEQ2.Events.NativeName[<event>]}`

The ISXEQ2 event a game event is read from, such as EQ2_onIncomingChatText, which is also the name a script attaches its own atom to. A missing or unknown event gives NULL.

| Parameter | Type | Default | Meaning |
|---|---|---|---|
| `&lt;event>` | string |  | The event's 0-based number (0 to Count minus 1) or its name, such as IncomingChatText |

**Returns:** string: the ISXEQ2 event name; NULL for a missing or unknown event

```text
echo ${ISXOgreEQ2.Events.NativeName[IncomingChatText]}
```

### `Pending`

`${ISXOgreEQ2.Events.Pending}`

How many received game events are waiting to be handed to the extension's features; they are handed out every pulse, so this is normally 0. At most 4096 can wait, and beyond that the oldest are dropped and counted in Dropped.

**Returns:** int: events waiting to be handed out right now

```text
echo ${ISXOgreEQ2.Events.Pending}
```

### `Received`

`${ISXOgreEQ2.Events.Received[<event>]}`

How many times this game event has arrived since the extension loaded, or the total for all events when the argument is left out. The event is its 0-based number or its name in any case (IncomingChatText, ActorSpawned and so on), and an unknown event gives NULL.

| Parameter | Type | Default | Meaning |
|---|---|---|---|
| `&lt;event>` | string |  | The event's 0-based number or its name, such as IncomingChatText; leave it out for the total across all events |

**Returns:** int64: arrivals of that event since load (or of all events); NULL for an unknown event

```text
echo ${ISXOgreEQ2.Events.Received[IncomingChatText]}
```

### `Stats`

`${ISXOgreEQ2.Events.Stats}`

One summary line, such as attached=yes events=14 pending=0 dropped=0 recv=5120 disp=5120, with recv and disp totalled across all events. Echoing ${ISXOgreEQ2.Events} prints the same line after the word Events.

**Returns:** string: the summary line

```text
echo ${ISXOgreEQ2.Events.Stats}
```

### `StatsJSON`

`${ISXOgreEQ2.Events.StatsJSON}`

The full event table as one JSON object: attached, count, pending, dropped, and an events array giving each event's i, label, native, received, dispatched and subscribers.

**Returns:** string: a JSON object

```text
echo ${ISXOgreEQ2.Events.StatsJSON}
```

### `Subscribers`

`${ISXOgreEQ2.Events.Subscribers[<event>]}`

How many of the extension's own features are listening to this game event (such as the chat and spawn handling behind OgreBotAPI.Events), or the total when the argument is left out. Atoms a script attaches to the ISXEQ2 event itself are not counted, and an unknown event gives NULL.

| Parameter | Type | Default | Meaning |
|---|---|---|---|
| `&lt;event>` | string |  | The event's 0-based number or its name, such as FinishedZoning; leave it out for the total across all events |

**Returns:** int: listeners on that event (or on all events); NULL for an unknown event

```text
echo ${ISXOgreEQ2.Events.Subscribers[FinishedZoning]}
```

# ISXOgreEQ2.Experiment

## Methods

### `Boost`

`ISXOgreEQ2.Experiment:Boost[flag,count,...]`

Starts boosting the item already selected on the tradeskill window's Experiment tab, picking each queued stat and clicking Begin and the confirm dialog for every boost; it also turns on the crafting reaction handling. It refuses with a console line when you are not in the world, lack the Experiment AA, a run is already going or no stat is queued, and words it does not know are echoed and skipped.

| Parameter | Type | Default | Meaning |
|---|---|---|---|
| `flag` | string |  | the stat to boost: -p, -pot or -potency for potency, -cb or -critbonus for crit bonus, or -&lt;stat> for any other stat label the game offers |
| `count` | int |  | how many boosts of that stat to queue |
| `...` | string |  | more flag, count pairs, run in the order given |

```text
ISXOgreEQ2.Experiment:Boost[-p,3,-cb,2]
```

### `Items`

`ISXOgreEQ2.Experiment:Items`

Lists the numbered item rows on the Experiment tab's item page to the console, briefly enlarging the tradeskill window to read them and then putting it back. It prints a warning instead when you are not in the world, lack the Experiment AA, a run is in progress or no list is showing.

```text
ISXOgreEQ2.Experiment:Items
```

### `Run`

`ISXOgreEQ2.Experiment:Run[row,flag,count,...]`

Boosts the item on row `row` of the Experiment item list (the numbers Items prints) with the same flags as Boost. A missing row, a row number out of range or no queued stat is refused with a console line and nothing starts.

| Parameter | Type | Default | Meaning |
|---|---|---|---|
| `row` | int |  | the item row number from Experiment:Items, starting at 1 |
| `flag` | string |  | the stat to boost: -p, -pot or -potency, -cb or -critbonus, or -&lt;stat> for any other stat label |
| `count` | int |  | how many boosts of that stat to queue |

## Methods

### `MoveBag`

`ISXOgreEQ2.InvOps:MoveBag[from,to]`

The engine behind `ogre mbc`: moves every item in carried bag `from` into bag `to`, one item every 0.2 s, where a bag's number is its inventory slot (1-6). It is refused with a console warning when a number is missing or out of range, both are the same bag, a slot holds no bag, the source bag is empty, or another inventory flow is running.

| Parameter | Type | Default | Meaning |
|---|---|---|---|
| `from` | int |  | bag number (1-6) to empty |

```text
ISXOgreEQ2.InvOps:MoveBag[2,3]
```

### `Overflow`

`ISXOgreEQ2.InvOps:Overflow`

The engine behind `ogre overflow`: pops items out of the overflow window into your bags, one every 0.2 s, until the game says the overflow is empty or has no room, only one bag slot is left free, or 300 items have been popped. It returns at once and the work runs on later frames; it is refused with a console warning when another inventory flow is running or you are not in the world.

```text
ISXOgreEQ2.InvOps:Overflow
```

### `Stop`

`ISXOgreEQ2.InvOps:Stop`

Drops whichever overflow, bag move or trade flow is running, without printing anything; does nothing when idle. An open trade window is left as it is.

```text
ISXOgreEQ2.InvOps:Stop
```

### `Trade`

`ISXOgreEQ2.InvOps:Trade[count]`

The engine behind `ogre trade`: opens a trade with your current target, adds up to `count` whole stacks from your bags of the item you have EXAMINED (exact name, any case), then accepts. You need a target and an open examine window; when nothing is examined or no stack matches, the run rejects the trade it opened and ends with a console line.

| Parameter | Type | Default | Meaning |
|---|---|---|---|
| `count` | int | `12` | most stacks to hand over; missing, not a whole number, or 0 or less uses 12 |

```text
ISXOgreEQ2.InvOps:Trade[4]
```

# ISXOgreEQ2.Nav

## Members

### `NavActive`

`${ISXOgreEQ2.Nav.NavActive}`

TRUE while a nav trip is in progress - planning its route, waiting for this zone's navmesh, or moving. A paused trip still counts as in progress.

`${ISXOgreEQ2.Nav.NavDistance}`

```text
echo ${ISXOgreEQ2.Nav.NavDistance}
```

`${ISXOgreEQ2.Nav.NavMeshOn}`

TRUE unless nav has been switched off with Nav:Set[mesh,off] or `ogre nav -off`. While it is off, new trips are refused; the switch is not saved and starts TRUE each time the extension loads.

```text
echo ${ISXOgreEQ2.Nav.NavMeshOn}
```

### `NavMeshPolys`

`${ISXOgreEQ2.Nav.NavMeshPolys}`

How many walkable polygons the loaded navmesh has. It is 0 when no mesh is loaded in this zone yet.

```text
echo ${ISXOgreEQ2.Nav.NavMeshPolys}
```

### `NavMeshTiles`

`${ISXOgreEQ2.Nav.NavMeshTiles}`

```text
echo ${ISXOgreEQ2.Nav.NavMeshTiles}
```

`${ISXOgreEQ2.Nav.NavMeshZone}`

Name of the navmesh that is loaded - the zone's short name in lower case, or the base zone's name when this zone is a copy that uses it. It is "" until a mesh is loaded in this zone (see NavOnMap).

`${ISXOgreEQ2.Nav.NavOnMap}`

TRUE when a navmesh is loaded right now, so nav can plan a route without waiting. The mesh loads on the first trip or route request in a zone and is set aside on every zone change, so this reads FALSE after zoning until something asks for a route.

```text
echo ${ISXOgreEQ2.Nav.NavOnMap}
```

`${ISXOgreEQ2.Nav.NavOnMesh}`

TRUE while the current trip is driven over a navmesh route. It is FALSE when idle, while a trip still waits for its navmesh or plans its first route, and once a trip ends.

```text
echo ${ISXOgreEQ2.Nav.NavOnMesh}
```

`${ISXOgreEQ2.Nav.NavReason}`

Plain words about the trip: while it plans or moves, what the plan is doing; once it has ended or while it waits for a navmesh, why. It is empty before the first trip, and reads "already there" when a trip was asked for the spot the character already stands on.

**Returns:** string: the plan in force, or why the last trip ended; "" before any trip.

```text
echo ${ISXOgreEQ2.Nav.NavReason}
```

### `NavState`

`${ISXOgreEQ2.Nav.NavState}`

The trip's state as one word; Arrived, Stopped and Failed stay until the next trip starts, and a paused trip still reads Moving. Stopped means somebody ended the trip on purpose, Failed means nav gave up - NavReason says why.

**Returns:** string: a state word such as Idle, Planning, WaitingForMesh, Moving, Arrived, Stopped or Failed.

```text
echo ${ISXOgreEQ2.Nav.NavState}
```

`${ISXOgreEQ2.Nav.NavWaypoint}`

The waypoint on the current route the character is heading for, counted from 1 (the first point after the start) up to NavWaypoints on the last leg. It is 0 when no route is being walked, a finished trip included.

### `NavWaypoints`

`${ISXOgreEQ2.Nav.NavWaypoints}`

```text
echo ${ISXOgreEQ2.Nav.NavWaypoints}
```

| Parameter | Type | Default | Meaning |

```text
ISXOgreEQ2.Nav:Status
```
