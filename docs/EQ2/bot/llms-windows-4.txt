# ForWho Groups

> **:bulb: In game - the ? button on this window says**
>
> Name a set of characters once, then select them all with one for-who word, like `*Team:Raid1`.
>
> **What you can do here**
>
> - **Create group** - type a name in the top box (letters, digits, - and _).
> - **Add characters** - type a name and press Enter, or use **Add my Group** / **Add my Raid**.
> - **Rename** - type the new name in the top box first, then press Rename on the group.
> - **Save** - shares your groups with every session on this PC. **Discard changes** throws your edits away.
> - **Sync all sessions** - use after editing the groups file by hand. Save or discard your own edits first.
>
> **Good to know**
>
> - Nothing counts until you press Save.
> - `-*Team:Raid1` means everyone NOT in Raid1.
> - A misspelled group word quietly matches nobody.

**Open it:** Type `ogre forwhogroups panel` (or `ogre fwg panel`), or press **Team Groups…** on the OgreBot Aliases tab. Plain `ogre forwhogroups` only prints your groups to the console. `ogre end forwhogroups` closes the window.

## What it is for

A team group is a name for a set of characters. Once you make a group called Raid1, the word `*Team:Raid1` can be used anywhere a for-who goes (for example `oc !c -pause *Team:Raid1`), and only the characters listed in Raid1 act on it. This window creates, renames and deletes groups and edits who is in each one. Your edits stay in the window until you press Save. Save writes one file that every session on this PC shares, so the same group means the same characters everywhere.

## Header

| Control | What it does |
|---|---|
| **Print to console** | Prints every group, how many characters it has and their names to the console, plus where the file is.<br>*It prints the SAVED groups. Edits you have not saved yet do not show up.* |
| **Sync all sessions** | Re-reads the groups file in this session and tells every other session on this PC to re-read it too. The list in this window is reloaded as well. Use it after you edit the file by hand. Saving from this window already does this for you.<br>*With unsaved changes it refuses (red message): Save or Discard them first.* |



## Create and rename

| Control | What it does | Default |
|---|---|---|
| **new group name** | Type a group name here, then press Enter or Create group. Also where you type the new name before pressing Rename on a group.<br>*Letters, digits, - and _ only. No spaces. Case does not matter: Raid1 and raid1 are the same group.* | empty |
| **Create group** | Adds a new, empty group with the name in the box. An empty group selects nobody until you add characters.<br>*Refused, with a red message, if the name has a bad character or a group with that name already exists.* |  |



## A group

Each group has a header row and, when unfolded, its list of characters.

| Control | What it does | Default |
|---|---|---|
| **▼ / ▶ (fold a group)** | Click the arrow, or anywhere on the header row, to fold or unfold that group's character list. Display only - changes what you see, not what the bot does.<br>*Folding is forgotten when you close the window.* | unfolded |
| **Rename** | Renames this group to whatever is typed in the 'new group name' box at the top. The characters in it stay.<br>*Type the new name in the top box FIRST. With the box empty you just get a red message telling you to.* |  |
| **Delete** | Removes the whole group. There is no confirmation, but nothing is final until you press Save; Discard changes brings it back. |  |
| **Remove** | Takes that character out of the group. |  |



## Adding characters

The add row sits at the bottom of each unfolded group.

| Control | What it does | Default |
|---|---|---|
| **toon name** | Type one character name and press Enter (or Add). The box stays selected, so you can type the next name and press Enter again.<br>*Letters only, one word. A name with a space, digit or other character is refused with a red message.* | empty |
| **Add** | Adds the name in the box next to it to this group.<br>*A name that is already in the group is refused with a red message, and nothing changes.* |  |
| **Add my Group (n)** | Adds everyone in your current group, including you, to this group. The number is how many are in your group right now. Nobody already in the list is removed, and the message counts only the names that were new.<br>*Shows whenever you are in the world, even on your own: then it reads (1) and adds just you. The number updates by itself as people join or leave.* |  |
| **Add my Raid (n)** | Adds everyone in your raid, including you, to this group. Nobody already in the list is removed, and the message counts only the names that were new.<br>*Only shows while you are in a raid.* |  |



## Save and Discard

Everything you do in this window is only a draft until you press Save. Until then your groups keep working exactly as they were saved.

| Control | What it does |
|---|---|
| **Save** | Writes your groups to the shared file, and every session on this PC starts using them straight away.<br>*Greyed out when there is nothing to save.* |
| **Discard changes** | Throws away every unsaved edit and shows the groups as they were last saved.<br>*Greyed out when there is nothing to discard.* |



## Closing with unsaved changes

If you press the X in the title bar while there are unsaved changes, the window stays open and asks what to do.

| Control | What it does |
|---|---|
| **Title bar close (X)** | Closes the window. With unsaved changes it shows the question below instead of closing.<br>*`ogre end forwhogroups` closes the window without asking, and unsaved edits are lost.* |
| **Save & close** | Saves your changes, then closes the window.<br>*If the save fails, the window stays open with your changes and a red message saying why.* |
| **Close without saving** | Throws away your unsaved changes and closes the window. |
| **Keep editing** | Hides the question and leaves the window open with your changes still there. |



## What the window shows

- Next to the title: how many groups you have, or 'no groups yet'.
- Green line under the Create row: what your last action did (for example 'added Tobbin' or 'saved - every session is now in sync'). Red means it was refused, and says why.
- Group header: the word you type to use the group (e.g. *Team:Raid1) and how many characters are in it. The count turns orange at 0 toons.
- 'not in my group/raid' next to a name: that character is not in your group or raid right now. Only a hint - offline or elsewhere is fine, the name still counts. Not shown while you are out of the world.
- 'no members yet - *Team:X currently selects NOBODY': the group is empty, so using it does nothing.
- Next to Save: 'unsaved changes — nothing is shared until you press Save' (orange), or 'saved' (grey).
- Footer: total groups and memberships, how to type a group (*Team:GroupName) and everyone NOT in it (-*Team:GroupName), 'shared by every session', '(not in world - roster seeding unavailable)' when you are out of the world, and the path of the file your groups are saved in.

## Good to know

- Nothing you do here counts until you press Save. Your groups keep working exactly as last saved until then.
- Groups are shared by every session on this PC, not saved per character. Saving from any session updates them all.
- Rename uses the 'new group name' box at the top: type the new name there first, then press Rename on the group.
- A misspelled group word (e.g. *Team:Riad1) quietly matches nobody. No error is shown, so check the spelling.
- Plain `ogre forwhogroups` prints your groups to the console. Add `panel` to open this window.
- When the window opens it starts from the saved file, so unsaved edits do not survive closing it. Typing the open command while it is already open does nothing (your edits stay).
- If another session saves the groups while you have unsaved changes here, your changes are kept and a red message warns that Save would write over theirs. Discard takes theirs.

### Using a group

Put the group word anywhere a for-who goes. It can be combined like any other for-who word:

- `*Team:Raid1` - only the characters in Raid1.
- `-*Team:Raid1` - everyone who is NOT in Raid1.
- `*Team:Raid1+@Tank` - in Raid1 AND the tank.

The first time you open the window it is empty and explains how to start. Out of the world, the Add my Group / Add my Raid buttons are not offered:

# Auto-Login

> **:bulb: In game - the ? button on this window says**
>
> Builds auto-login profiles: which character goes into which session. Start makes your sessions match the profile and loads OgreBot on each character once it is in the world.
>
> **What you can do here**
>
> - **Profiles** - click one to open it. **+ New** starts a blank one; **Import** copies your old OgreBot profiles.
> - **Character rows** - pick the PC (ThisUplink, or another PC), the session (is1, is2, or any) and the character.
> - **Other PCs** - add another PC's uplink name so a row can put characters on it. Start connects to it and logs those characters in there.
> - **Settings** - the game to launch and the pauses between launches and logins (in tenths of a second).
> - **ISBoxer character sets** - if you launch with ISBoxer, pick the set for each PC. Start launches them first, then logs your characters into the sessions they opened, and launches only a session that is still missing. Leave a PC empty if it doesn't use ISBoxer.
> - **Save** the profile, **Delete** the one selected in the list, or make a **Desktop shortcut** that runs it.
> - **Start** runs the selected saved profile. Tick **Dry run** to only list what it would do.
>
> **Good to know**
>
> - Saving over an existing profile needs **Overwrite** ticked.
> - Start runs the saved profile, so Save first.
> - No passwords are stored; characters must be in your saved account list - on another PC, in that PC's list.
> - Another PC needs Ogre installed. One that can't be reached has its rows skipped.

**Open it:** Type `ogre autologin`. `ogre end autologin` closes it.

## What it is for

Auto-Login builds **profiles**: a named list of which character goes into which InnerSpace session. Press **Start** and InnerSpace itself (the uplink, not the game window) makes your sessions match the profile: characters already in the right place are left alone, a wrong character is camped out, missing sessions are launched, and each character is logged in with a pause between logins. Once a character is in the world, OgreBot is loaded for it. Profiles hold no account names or passwords; those come from your saved account list when the profile runs, so a profile is safe to share.

## Profiles list

Your saved profiles, in name order. The number after a name is how many characters it has. A red name with a warning sign is a profile file that could not be read.

| Control | What it does | Default |
|---|---|---|
| **Click a profile** | Opens that profile on the right so you can check it, change it, start it or delete it.<br>*Clicking a red (broken) profile only shows why it could not be read, in the log at the bottom.* |  |
| **+ New** | Clears the right side for a brand new profile: no name, one character row (ThisUplink, any), and the default settings.<br>*Nothing is saved until you click Save.* |  |
| **Import** | Copies your auto-login profiles from the old OgreBot into this window. It reads the old bot's AutoLoginProfiles.xml and AutoLoginSettings.xml (in Scripts\EQ2OgreCommon\OgreAutoLogin) and writes one new profile per old one. The log shows how many were written, skipped or failed.<br>*The old bot's timing settings are copied into every imported profile. Characters not in your saved account list are counted as warnings but still imported.* |  |
| **Overwrite on import** | When ticked, Import replaces a profile you already have with the same name. When not ticked, those are skipped and your existing profile is kept. | off |

## Profile name

| Control | What it does | Default |
|---|---|---|
| **Profile name** | The name of the profile. Save uses it. The file on disk is named after it, with anything that is not a letter or number turned into an underscore.<br>*Spaces are fine. Renaming a saved profile and clicking Save moves it to the new name.* | empty |

## Character assignments

One row per character. Each field is pick-or-type: click it for a list, or type anything. Typing narrows the list.

| Control | What it does | Default |
|---|---|---|
| **Uplink** | Which PC this character is logged in on. ThisUplink means "whichever PC runs the profile". To put a character on another PC, add that PC to Other PCs below and pick it here: Start connects to that PC, launches and logs in its sessions there.<br>*The list offers ThisUplink plus the PCs in Other PCs (this PC itself is ThisUplink). That PC logs the character in with its own saved account list, and it needs Ogre installed.* | ThisUplink |
| **Session** | Which InnerSpace session the character must be in: is1, is2 and so on. "any" means any session is fine: if the character is already in the world somewhere it is left alone, otherwise a free session is used or a new one is launched.<br>*The list offers any and is1 to is24. Left empty, it saves as any.* | any |
| **Character** | The character to log in. The list shows the characters in your saved account list.<br>*A character that is not in your saved account list gets a warning when the profile runs, because its account cannot be looked up.* | empty |
| **x (remove row)** | Removes that character row. If it was the last row, a fresh empty row takes its place.<br>*Not saved until you click Save.* |  |
| **+ Add row** | Adds another character row (Uplink ThisUplink, Session any, Character empty). |  |

## Other PCs (uplinks)

The other PCs a character row can name, by their InnerSpace uplink name. It is the same list as OgreBot's Uplink Info tab and the MCP's Connect button. When a profile has rows on another PC, Start connects to that PC if it is not connected yet, checks that its uplink answers, then launches, logs in and loads OgreBot on its sessions from this PC. A PC that cannot be reached has its rows skipped and the rest of the profile still runs.

| Control | What it does | Default |
|---|---|---|
| **Uplink name** | Type the InnerSpace uplink name of another PC (in InnerSpace on that PC: its Remote name). | empty |
| **+ Add** | Adds the typed name to the list. The log says whether it was added.<br>*The list is saved at once, for every profile on this PC.* |  |
| **x (remove PC)** | Takes that PC off the list.<br>*Rows that name it keep the name; Start still tries to connect to it.* |  |

## Settings

Times are in tenths of a second: 150 means 15 seconds. The editor scrolls; these are below the character rows.

| Control | What it does | Default |
|---|---|---|
| **Game** | The InnerSpace game entry used when a new session has to be launched. The list comes from the games set up in InnerSpace.<br>*Left empty, it saves as Everquest 2.* | Everquest 2 |
| **Game profile** | The InnerSpace game profile used when a new session has to be launched. The list shows the profiles of the game chosen above. | everquest 2 default profile |
| **ISBoxer character sets** | If you launch with ISBoxer, the character set to launch on each PC: one line for this PC (ThisUplink) and one for each other PC the rows name. Start launches every PC's set first (another PC's on that PC), then logs your characters into the sessions they opened, and launches only a session that is still missing.<br>*Each list shows that PC's sets from ISBoxer. Leave a line empty for a PC that does not use ISBoxer. A PC whose last row is removed keeps no set.* | empty (no ISBoxer) |
| **Wait after load** | After new sessions are launched, how long to wait for them to load before logging anyone in. Only used when a session had to be launched. | 150 (15 seconds) |
| **Wait between launches** | The pause after each new session is launched, before the next one. | 50 (5 seconds) |
| **Login stagger - base** | The pause between one character's login and the next, so the server is not hit with every login at once. | 300 (30 seconds) |
| **Login stagger - random** | A random extra pause, up to this much, added to the base pause for each login. 0 turns the random part off. | 150 (up to 15 seconds) |

## Save, Delete, Shortcut and Start

At the opening window size these buttons are below the fold: scroll the right side down to reach Start.

| Control | What it does | Default |
|---|---|---|
| **Overwrite** | Must be ticked to save over a profile that is already saved. Without it, Save refuses and says a profile with that name already exists.<br>*This includes saving changes to the profile you just opened. It is not remembered: it is off each time the window opens.* | off |
| **Save** | Saves the profile. The log says whether it worked, and the list on the left updates.<br>*A profile needs a name. A row with no character is dropped when saving; a blank Uplink saves as ThisUplink and a blank Session as any. Settings this window does not show (such as loginOnly or sessionAppearMaxDs, set by hand in the file) are kept.* |  |
| **Delete** | Asks for confirmation, then deletes the profile you selected in the list.<br>*It deletes the selected saved profile, even if you have typed a different name in the box. A new profile that was never saved cannot be deleted.* |  |
| **Delete (in the confirm box)** | Deletes the profile file and clears the right side to a new blank profile. This cannot be undone. |  |
| **Cancel (in the confirm box)** | Closes the confirm box without deleting anything. |  |
| **Desktop shortcut** | Puts a shortcut on your Windows desktop that runs this saved profile through InnerSpace, the same as pressing Start. The log shows where it was made.<br>*Save the profile first. A shortcut with the same name is replaced; if something else already has that name, a numbered copy like "Raid_Night (1)" is made instead.* |  |
| **Dry run** | When ticked, Start only works out and lists what it would do (who stays, who gets camped, which sessions it would launch, who it would log in). Nothing is actually done.<br>*Off means Start really does it. Tick it the first time you try a new profile.* | off |
| **Start** | Runs the selected profile, as it is saved, in InnerSpace. Characters already where they belong are left alone; a wrong character in a session is camped first; missing sessions are launched; then each character logs in, with the stagger pause between logins. Each character gets OgreBot loaded as soon as it is in the world. Progress appears in the log below as it happens.<br>*Start runs the profile as last SAVED, not what is on screen. Click Save first if you changed anything, or if the profile is new.* |  |

## Window

| Control | What it does |
|---|---|
| **Title bar close (X)** | Closes the window. A run that has already started keeps going in InnerSpace.<br>*Unsaved changes are lost.* |

## What the window shows

- Profiles (left): every saved profile, in name order. The number in brackets is how many characters it has. Green outline = the one open on the right. Red with a warning sign = a profile file that could not be read.
- The note under the name is a reminder that profiles hold no usernames or passwords.
- The log (bottom): green lines are things that worked, red lines are problems. During a Start it shows the run as it happens, between "run output" and "run complete" lines.
- The log stops following a run if nothing new appears for 90 seconds, or after 10 minutes.

## Good to know

- Saving changes to an existing profile needs Overwrite ticked, even if it is the profile you just opened.
- Start runs the SAVED profile. Save first if you changed anything.
- Rows on another PC are run from this PC: it connects to that PC and drives its sessions there. That PC needs Ogre installed and the characters in its own saved account list - passwords never leave the PC they are saved on.
- Profiles are saved as files in Scripts\OgreSave\EQ2\AutoLogin\Profiles. They hold no passwords, so they are safe to copy or share.
- Characters must be in your saved account list so their account can be found when the profile runs.
- Opening the window again while it is open does nothing, so the profile you are editing stays.

# Inventory Manager

> **:bulb: In game - the ? button on this window says**
>
> Tidies your bags: deposit to depots, sell, destroy, transmute or salvage (TSE), restock from depots, trade to players, and fill your quiver.
>
> **What you can do here**
>
> - **Run tab** - Look shows in the console what a mode would do; Run starts it. While something runs, Run becomes Queue.
> - **Sell list / Destroy list** - double-click a left row to add it; click a right row, then right-click it to remove it.
> - **TSE, Depot, Restock** - saved options for those modes. Depot saves only when you press Save.
> - **Trade** - queue items for nearby players, then Run the queue.
> - **Stop** stops the work; **Close** only closes the window. The X (or `ogre end im`) does both.
>
> **Good to know**
>
> - The bag boxes on the Destroy list and TSE tabs decide which bags those runs touch.
> - Restock on the Run tab always uses the profile named Default.
> - Quiver refills with the ammo already in your quiver first, then the name on the Quiver tab.

**Open it:** Type `ogre im` (or `ogre inventorymanager`). Any `ogre im` command that starts work (for example `ogre im sell` or `ogre im -depot -sell -end`) also opens it. `ogre end im` stops the work and closes it.

## What it is for

The Inventory Manager (IM) tidies your bags. It can deposit into house and guild-hall depots, sell to a merchant, destroy junk, transmute or salvage gear (TSE), top up supplies from the depots (Restock), hand items to other players (Trade), and fill your quiver. The Run tab starts any of these; the other tabs hold each one's saved list or options. Every button sends the same `ogre im ...` command you could type yourself, and the log strip at the bottom shows one line per thing IM actually did.

## Header, tabs and the log settings

The tabs only change what you see. The dot and word on the right say whether IM is working and on what.

| Control | What it does | Default |
|---|---|---|
| **Run / Sell list / Destroy list / TSE / Depot / Restock / Trade / Quiver** | Switches the page. Opening Sell list or Destroy list also rebuilds that tab's left-hand list (the merchant's items, or your bags). Otherwise display only.<br>*Switching to Sell list does not walk to or open a merchant - it only reads a merchant window that is already open.* | Run |
| **Log** | Shows or hides the row of activity-log settings under the header. Display only. | hidden |
| **Always** | The activity log strip is always on screen. Saved. | on (this is the starting choice) |
| **Only while running** | The log strip appears only while a mode is working, and hides again when it is idle. Saved.<br>*Showing and hiding the strip makes the whole window taller and shorter by the strip's height.* | off |
| **Never** | Hides the log strip for good. Saved. Use the Log button to get the setting back. | off |
| **Clear it** | Empties the activity log. |  |



## Run tab - the modes

One row per mode. Look prints what the mode would do in the console and changes nothing. Run starts it. While anything is running, every Run turns into Queue and every Look greys out (see the second picture).

| Control | What it does |
|---|---|
| **Run (depot)** | Deposits into your house or guild-hall depots using the line saved on the Depot tab.<br>*Greyed out if nothing is saved on the Depot tab. There is no Look for depot.* |
| **Look (sell)** | Lists in the console which items on your sell list the open merchant would buy. Sells nothing.<br>*Needs a merchant window already open.* |
| **Run (sell)** | Sells every item on your sell list to a merchant, then closes the merchant window. If no merchant window is open, it opens one that is within reach first.<br>*Stand next to a merchant. Bags marked NO SALE in the game are never offered.* |
| **Look (destroy)** | Lists in the console what the destroy run would destroy. Destroys nothing. |
| **Run (destroy)** | Destroys every item on your destroy list found in the bags ticked on the Destroy list tab. Destroyed items do not come back.<br>*Use Look first. It only touches the bags ticked on the Destroy list tab (bags 1 and 2 to start with).* |
| **Run (tse)** | Transmutes, salvages and/or extracts items using the options saved on the TSE tab.<br>*There is no Look for TSE.* |
| **Look (restock)** | Lists in the console what the Default restock profile still needs and which depots are in reach. Pulls nothing.<br>*Always the profile named Default. To look at another profile use Preview on the Restock tab.* |
| **Run (restock)** | Pulls items from your depots until you hold the target amount of each row in the Default profile. It never buys anything; a shortfall is reported.<br>*Always the Default profile. Use 'Run this profile' on the Restock tab for another one.* |
| **Look (trade)** | Walks the trade queue in the console: who is in reach and what would go in the first trade window. Hands nothing over. |
| **Run (trade)** | Hands each queued item to the player it names, one entry at a time. The other player must be nearby and accept the trade. |
| **Run (quiver)** | Fills your equipped quiver or pouch with ammo from your bags, then from the Ammo Depot. |
| **Queue (any mode, while something runs)** | Adds that mode to the waiting line. Queued modes run one after another, in the order you clicked, when the current one finishes. A dot or ×2 beside the mode name shows it is waiting.<br>*Look buttons stay greyed out until everything has finished.* |



## Run tab - Right now

Read-only. Window says whether IM counts its window as open. Doing names the running mode (or idle). Detail shows that mode's current step. Queued (only when something is waiting) lists the modes still to come, in order.

## Sell list tab

Left: what the open merchant would buy from you (green = already on your sell list, xN = how many stacks). Right: your saved sell list. It fills by itself when you open a merchant window while this tab is showing.

| Control | What it does | Default |
|---|---|---|
| **type to filter… (left)** | Hides left-hand rows whose name does not contain the text. Not case-sensitive. Display only. | empty |
| **Double-click a left row** | Adds that item to the sell list (or destroy list on the Destroy tab) and saves it. The row turns green.<br>*Adding an item that is already there does nothing.* |  |
| **type to filter… (right)** | Hides right-hand rows whose name does not contain the text. Display only. | empty |
| **Click a right row, then right-click it** | Removes that item from the list and saves it.<br>*Right-clicking a row that is not selected only selects it, so a stray right-click never removes anything.* |  |
| **Re-open merchant** | Reads the merchant again and refills the left list. If no merchant window is open it opens one within reach first (your last one, your target, or the nearest). Either way it then closes the merchant window.<br>*It closes the merchant window even if you opened it yourself. If no merchant is within reach it says so in the console and the list is left as it was.* |  |



## Destroy list tab

Same two lists as the Sell tab: left is what is in your bags, right is your saved destroy list. Double-click and right-click work the same way.

| Control | What it does | Default |
|---|---|---|
| **1 2 3 4 5 6** | Which of your six bags the destroy list works with: the left list shows their items, and Run destroy (and Look) only touch these bags. Saved. The list rebuilds as you tick.<br>*The same boxes decide the left list and the run, so they always agree.* | 1 and 2 on |

# TaskRunner Lists

> **:bulb: In game - the ? button on this window says**
>
> Builds the lists TaskRunner works through: which characters it logs in, in what order, and which timed chores each one does. Run a list with `ogre taskrunner -list <list>` (`run <list>` works too).
>
> **What you can do here**
>
> - **Run** - starts the selected list on this session (save first). The bar shows what it is doing: which character, which chore, and the last result. **Stop** stops it and leaves the character where it is.
> - **List** - click the box and type to find a list (they are in alphabetical order). Type a name that is not a list yet and pick **+ New list** (or press Enter) to make it.
> - **New / Duplicate / Rename / Delete** act on the selected list. Duplicate copies the members, their order and the run mode.
> - **Click a character** on the left to add it to the selected list. Use the **search** box to find a character or account. In **By account**, right-click an account and pick **Add all toons** (or open it and press **Add all**) to add the whole account - anyone already in the list is skipped.
> - **Drag a member row** up or down to change the order the list runs in.
> - **Chore buttons** on a row turn a chore on or off for that character. The **Everyone in** row does it for the whole list.
> - **When run** - **Keep looping** (stays running and picks chores up as they come due - leave it overnight) or **One pass** (does what is due now, then stops).
> - **Stagger start** - each session waits before its first login (is2 30 seconds, is3 60 seconds, and so on). Leave it on when one command starts lists on every session, or the server turns some logins away.
> - **Chore options** - one row per chore. **Guild hall first** travels to the guild hall unless the character is already in one or in a house. **Harvest depot after** puts all harvests into the nearest harvest depot afterwards. **Destroy list after depot** then destroys the items on your IM destroy list - the excess the depot would not take. It only runs with Harvest depot after on, and only when the depot finished. **Bushels** (Plant): the harvest gives a bushel - leave it packed, take the latest reward (a new expansion is picked up on its own), or a chosen reward number. A bushel is lore, so the plant is never harvested while one is still in the bags - with "leave it packed" that character skips the plant until you unpack it. (Pack Pony always loads OgreBot first - it reads its answers from your profile.)
> - **Save** writes your changes (what you set by hand in your own TaskRunner files is kept). **Discard** throws them away and reads the files again.
>
> **Good to know**
>
> - Never run two lists that share a character on two sessions at once.
> - A character's chores are the same in every list they are in.
> - **Overseer** never logs a character in by itself: it runs when the character is logged in for another chore (the pack pony). Its status says "next login" while it waits.
> - A character in a raid is never logged out: the run stops and leaves everyone where they are.
> - A character that cannot do a chore at all (no Pack Pony) is marked with an error and skipped until you clear it: `ogre taskrunner clear <name>`.
> - Closing the window loses unsaved changes without asking.
> - Closing the window also stops a run in progress, the same as `ogre end taskrunner`. `ogre taskrunner stop` stops it and leaves the window open.

**Open it:** Type `ogre taskrunner panel` (or `ogre tr panel`). `ogre taskrunner gui` and `ogre taskrunner config` also open it.

## What it is for

TaskRunner logs your characters in one after another and does their timed chores, such as the Artisan's Pack Pony and the Goblin House Plant. This window builds the named lists it works through. Then press Run, or type `ogre taskrunner run <list>`, to run the list on this session. Nothing is written until you press Save.

# Watcher

> **:bulb: In game - the ? button on this window says**
>
> Two small alert tools. **Find** tells you when a named creature or NPC shows up in your zone. **Track Shiny** tells you when a shiny of one colour appears near you. When one turns up it drops a waypoint and tells your other sessions.
>
> **What you can do here**
>
> - **Add** a name to watch, or add the **-rorr** preset (the four epic ability researchers).
> - **Click the idle pill** next to Find or Track Shiny to turn it on or off.
> - **Scan now** checks the zone once for every name on the list and writes what it finds in Hits (no waypoint).
> - **Colour**: click the shiny colour to track. Purple is chosen to start with.
> - **Clear log** empties the Hits list.
>
> **Good to know**
>
> - Names must match exactly: "Wanderer" will not find "The Wanderer". Find is silent in a guild hall.
> - Closing the window stops both tools, the same as `ogre end watcher`. To stop only one, click its pill, or type `ogre end find` / `ogre end trackshiny`.
> - Open this window with `ogre watcher`.

**Open it:** Type `ogre watcher`. `ogre find -panel` and `ogre trackshiny -panel` open the same window.

## What it is for

The Watcher has two small tools in one window. **Find** watches for named creatures or NPCs: when one on your list appears in your zone, you get a message, an alarm sound, an in-game waypoint on it, and every other session is told. **Track Shiny** looks for a shiny (a harvestable collectible) of one colour anywhere in your zone and does the same when a new one shows up, with a ding on every session instead of the alarm. Neither needs the window to be open, but closing it with the X ends both.

## Header

| Control | What it does |
|---|---|
| **Clear log** | Empties the Hits list below. It does not change the watch list or turn anything off. |
| **Title bar close (X)** | Ends the Watcher (the same as `ogre end watcher`): Find and Track Shiny both stop, and the window closes.<br>*To stop only one, click its pill, or type `ogre end find` or `ogre end trackshiny`. The window stays open.* |



## Find - the watch list

Names must match the whole name exactly (capital letters do not matter). "Wanderer" will not match "The Wanderer".

| Control | What it does | Default |
|---|---|---|

# Analysis

> **:bulb: In game - the ? button on this window says**
>
> Watches NPCs during an encounter and records every change to them, so you can see what else changed at the moment something happened. It only watches; it never changes what the bot does.
>
> **What you can do here**
>
> - **Monitor**: add actors (**+ Target**, or **+ Cursor** and put the mouse on one within 3 seconds), turn **Monitoring** on, then click a moment in Timestamps to see everything that changed then. The x on an actor stops watching just that one.
> - **Scan**: build terms (type a detail name - it suggests them - pick how to compare, add a value), then **Scan**. Click a result to see all its details; Ctrl+click a second to compare the two. **+ Target** / **+ Cursor** put one actor in the results. **monitor** on a result sends it to the Monitor tab.
> - **Events**: logs of announcements, spawns, chat and other game events. **Search the log** finds lines already recorded; **Record only lines containing** limits what is recorded from now on.
> - **Sessions**: save what you recorded to a file, or load an earlier one.
>
> **Good to know**
>
> - Tick **Keep previous results** to add to the results instead of replacing them. **Add new spawns that match** adds actors as they appear.
> - Pin a detail (the diamond) to show it as a column on every result.
> - Right-click any line to copy it, copy all of an actor's details, or remove it. The x on a result or an actor removes just that one.
> - Closing the window stops monitoring and the event logs, the same as `ogre end analysis`. What was recorded is kept.
> - **Taps** turns the event logs on and off.

**Open it:** Type `ogre analysis` (or `ogre anal`). `ogre end analysis` (or the window's X) turns monitoring and the event logs off, stops a scan in progress, and closes the window. What was recorded is kept.

Nothing here changes what the bot does; it only watches and records.

## What the window shows

- Closing the window stops monitoring and the event logs, the same as `ogre end analysis`. What was recorded stays until you unload the bot, so Export it or reopen the window to look at it.

# Ability Details

> **:bulb: In game - the ? button on this window says**
>
> Shows everything your ability export holds about each of your abilities. Use it to answer "why won't the bot cast this?"
>
> **What you can do here**
>
> - **Search** - type part of a name, an ID, or a test such as `IsInterrupt = TRUE` or `HOIconID = NULL`. Everything you type must match.
> - **Click a row** to see every field of that ability on the right. The `*` marks the rank the bot uses.
> - **Copy JSON** copies the whole entry. Right-click a field to copy its value or a search test for it.
> - `ogre abilitydetails <name or id>` opens the window on that ability.
>
> **Good to know**
>
> - The export leaves out flags that are false, so `IsAE = FALSE` matches nothing - use `IsAE != TRUE`. The footer lists the fields an entry does not have.
> - The window only reads your export. If an ability is missing, make a new export with `ogre export`.

**Open it:** Type `ogre abilitydetails`, or `ogre abilitydetails <name or id>` to open it on one ability (for example `ogre abilitydetails Assault` or `ogre abilitydetails Assault X`). A script opens it with `OgreBotAPI.Abilities:AbilityDetails[<forwho>,"<name or id>"]`. `ogre end abilitydetails` closes it.

## What it is for

Shows everything your ability export holds about each of your abilities: every rank of every line, and every field of the one you pick. It is the place to look when the bot will not cast something, or casts a different rank than you expected. The window only reads your export file - it never asks the game - so what you see is exactly what the bot works from. If OgreBot is not open yet, the window reads your export itself; it never changes it.

## The status line

Whose export this is, how many entries it holds (every rank of every ability) and how many ability lines that makes. The `*` in the list marks the rank the bot uses for each line - the highest rank your level allows. It turns red when there is no export for this character yet, or when the export is too old for the bot, and an **Ability Export** button appears.

| Control | What it does |
|---|---|
| **Ability Export** | Opens the Ability Export window, where you make a fresh export. Shown only when there is no export or it is out of date.<br>*When the export finishes the window shows the new one by itself.* |



## Search and the list

Every ability in your export, sorted by name with each line's ranks together, lowest level first. Lvl and Tier are the rank's level and spell tier. The count under the search box shows how many match out of the total.

| Control | What it does |
|---|---|
| **Search** | Filters the list as you type. Words match the ability's name. A number matches its ID or its line ID (and names with that number in them). A test such as `IsInterrupt = TRUE`, `HOIconID = NULL` or `Level >= 100` checks a field, exactly the way FindCastableID and FindAndCast check it. Everything you type must match.<br>*A field name typed without a comparison and a value is shown in orange under the box and ignored until you finish it.* |
| **Click a row** | Shows every field of that rank on the right. |
| **Right-click a row** | Copy name or Copy ID of that rank. |



## The selected ability

Every field the export holds for that rank, exactly as written: the name, IDs, level and tier first, then the rest A to Z, then the effect lines in order. The footer lists the fields this entry does NOT have. The export leaves a flag out when it is false, so those fields read as NULL - that is why `IsAE = FALSE` matches nothing. Use `IsAE != TRUE` instead.

| Control | What it does |
|---|---|
| **Copy JSON** | Copies the whole entry, in the same order as the window shows it. |
| **Right-click a field** | Copy value copies the value. Copy as a search term copies `Field = value`, which you can paste into the search box to find every ability with the same value. |
| **Title bar close (X)** | Closes the window. Same as `ogre end abilitydetails`. |



## Opening it on one ability

`ogre abilitydetails Assault` (the ability's own name, no rank) selects the rank the bot uses. A specific rank's full name (`Assault X`) or an ID selects exactly that rank, and the line under its name says which rank the bot uses instead. Either way the search is filled in with the ability's name, so all its ranks are listed. If nothing matches, nothing is selected, the line says so in orange and the console says it too.

## What the window shows

- `*` in the list and after the selected name: the rank the bot uses for that line (the highest rank your level allows).
- The orange line under the search box: a test you have not finished (a field name with no comparison or no value). It does not filter until it is complete.
- Status line '(Loaded by this window - OgreBot is not open.)': OgreBot has not been opened, so the window read your export itself. OgreBot reads it again when it opens.

## Good to know

- The window shows your own character's export only.
- It shows the export, not the game. An ability you trained after your last export is not in it - make a new export with `ogre export`.
- The export leaves out flags that are false. Test them with `!= TRUE` (or `= NULL`), not `= FALSE`.
- Typing a field name such as `Level` on its own starts a test, not a name search.

# Pulse Budget

> **:bulb: In game - the ? button on this window says**
>
> A performance window. A few big jobs are spread over several frames so the game does not freeze; this shows how much time each may use per frame, and what every part of the bot really costs.
>
> **What you can do here**
>
> - **Slice** on a row: how long that job may run each frame, in microseconds. Lower it if the game stutters while the job runs. 0 runs it all at once.
> - **Frame ceiling**: a shared limit for the bot's work each frame. Untick **Use the frame ceiling** to turn off just that limit - each job keeps its own slice.
> - **Reset counters** and **Refresh** to measure again.
>
> **Good to know**
>
> - A slice never skips work - a job just takes more frames to finish.
> - Most players never need to change anything here.
> - A row marked (idle) has not run yet this session. Its slice can still be changed, and is used when it runs.

**Open it:** Type `ogre pulse` (or `ogre pulsebudget`). `ogre end pulse` closes it.

## What it is for

A performance window. The bot does its work in small steps, once every frame the game draws. A few big jobs - planning a route, scanning all the actors for Analysis, walking a recipe book, walking the ability-upgrade list - would freeze the game for a moment if done in one go, so they are spread over several frames. This window shows how much time each of those jobs may take per frame, and how much time each part of the bot is really using. Most players never need to touch it. If the game stutters while one of these jobs runs, lower that job's slice; if a job takes too long and your PC has room to spare, raise it.

## Top row

On the right: how many frames have been counted, and how many times a job paused and carried on in the next frame. A pause never loses work.

| Control | What it does | Default |
|---|---|---|
| **Use the frame ceiling** | Turns the Frame ceiling on or off. Only the shared ceiling - each job's own slice still applies either way.<br>*Despite the name, unticking it does not make jobs run in one go - set a job's slice to 0 for that.* | on |
| **Frame ceiling … µs** | A shared limit, in microseconds (millionths of a second), for the bot's whole work each frame. Once the bot has used this much in a frame, the paced jobs stop early for that frame and carry on in the next. 0 = no ceiling.<br>*Saved when you press Enter or click away. Each job always gets at least one step per frame, however busy the frame is.* | 4000 µs (4 ms) |
| **Reset counters** | Sets the frame count, pause counts, Active frames, Units done and Worst back to zero, so you can measure from now. Slices are not changed. |  |
| **Refresh** | Updates the numbers. The window does not update by itself. |  |
| **Title bar close (X)** | Closes the window. Your slices and ceiling stay in force. |  |



## Resumable sections

One row per job that can be spread over frames. A job only appears after it has run once this session; jobs saved from earlier sessions are listed greyed out with '(idle)' - you can still set their slice, and it is used as soon as the job runs.

| Control | What it does | Default |
|---|---|---|
| **Slice µs/f (the box on each row)** | How long that job may run each frame, in microseconds, before it pauses and carries on in the next frame. 0 = run the whole job in one frame. Saved when you press Enter or click away.<br>*On an '(idle)' row the new slice is saved and handed to that job the first time it runs.* | each job has its own, for example nav ground plan 4000, zonereset: table 3000, craft: recipe scan 1500, analysis: actor scan 1000, abilityupgrades: row walk 1000 |



## Pulse profile

Read-only. Every part of the bot that runs each frame, costliest first, with its average and worst time per frame. Parts using less than half a microsecond on average are left out. Useful for spotting what is slowing the game down.

## What the window shows

- Section: the job's name - what it belongs to, then what it does.
- Last µs: how long the job ran the last frame it had work. Yellow at 1000 µs (1 ms) or more.
- Worst µs: its longest single frame since the last reset. Yellow at 1000 µs or more.
- Active frames: how many frames it did any work in.
- Units done: how many steps of work it got through.
- Paused: how many times it ran out of time and carried on in the next frame (green when above 0 - that is pacing working, not a problem).
- (idle): a job with a saved slice that has not run yet this session.
- Pulse profile - Avg µs/frame: yellow at 20 µs or more. Worst µs: yellow at 1000 µs or more.
- When no job has run yet, the table is replaced by a note saying so.

## Good to know

- A slice never skips work. A small slice only makes a job take more frames to finish.
- 1000 µs is 1 millisecond. At 60 frames a second a whole frame is about 16,600 µs.
- Settings are saved to OgreSave/EQ2/OgreBot/pulse-budget.json and apply to every character on this PC.
- The numbers are a snapshot - press Refresh to see new ones.

Straight after loading, before any paced job has run (and with no saved settings), the table is empty:

![Empty](../assets/pulsebudget/empty.png)

Console: `ogre pulse report` prints the same table; `ogrepulsebudget slice <section or number> <µs>` and `ogrepulsebudget ceiling <µs>` set values.
