# Inventory Manager

> **:bulb: In game - the ? button on this window says**
>
> Tidies your bags: deposit to depots, sell, destroy, transmute or salvage (TSE), restock from depots, trade to players, and fill your quiver.
>
> **What you can do here**
>
> - **Run tab** - Look shows in the console what a mode would do; Run starts it. While something runs, Run becomes Queue.
> - **Sell list / Destroy list** - double-click a left row to add it; click a right row, then right-click it to remove it.
> - **TSE, Depot, Restock** - saved options for those modes. Depot saves only when you press Save.
> - **Trade** - queue items for nearby players, then Run the queue.
> - **Stop** stops the work; **Close** only closes the window. The X (or `ogre end im`) does both.
>
> **Good to know**
>
> - The bag boxes on the Destroy list and TSE tabs decide which bags those runs touch.
> - Restock on the Run tab always uses the profile named Default.
> - Quiver refills with the ammo already in your quiver first, then the name on the Quiver tab.

**Open it:** Type `ogre im` (or `ogre inventorymanager`). Any `ogre im` command that starts work (for example `ogre im sell` or `ogre im -depot -sell -end`) also opens it. `ogre end im` stops the work and closes it.

## What it is for

The Inventory Manager (IM) tidies your bags. It can deposit into house and guild-hall depots, sell to a merchant, destroy junk, transmute or salvage gear (TSE), top up supplies from the depots (Restock), hand items to other players (Trade), and fill your quiver. The Run tab starts any of these; the other tabs hold each one's saved list or options. Every button sends the same `ogre im ...` command you could type yourself, and the log strip at the bottom shows one line per thing IM actually did.

## Header, tabs and the log settings

The tabs only change what you see. The dot and word on the right say whether IM is working and on what.

| Control | What it does | Default |
|---|---|---|
| **Run / Sell list / Destroy list / TSE / Depot / Restock / Trade / Quiver** | Switches the page. Opening Sell list or Destroy list also rebuilds that tab's left-hand list (the merchant's items, or your bags). Otherwise display only.<br>*Switching to Sell list does not walk to or open a merchant - it only reads a merchant window that is already open.* | Run |
| **Log** | Shows or hides the row of activity-log settings under the header. Display only. | hidden |
| **Always** | The activity log strip is always on screen. Saved. | on (this is the starting choice) |
| **Only while running** | The log strip appears only while a mode is working, and hides again when it is idle. Saved.<br>*Showing and hiding the strip makes the whole window taller and shorter by the strip's height.* | off |
| **Never** | Hides the log strip for good. Saved. Use the Log button to get the setting back. | off |
| **Clear it** | Empties the activity log. |  |



## Run tab - the modes

One row per mode. Look prints what the mode would do in the console and changes nothing. Run starts it. While anything is running, every Run turns into Queue and every Look greys out (see the second picture).

| Control | What it does |
|---|---|
| **Run (depot)** | Deposits into your house or guild-hall depots using the line saved on the Depot tab.<br>*Greyed out if nothing is saved on the Depot tab. There is no Look for depot.* |
| **Look (sell)** | Lists in the console which items on your sell list the open merchant would buy. Sells nothing.<br>*Needs a merchant window already open.* |
| **Run (sell)** | Sells every item on your sell list to a merchant, then closes the merchant window. If no merchant window is open, it opens one that is within reach first.<br>*Stand next to a merchant. Bags marked NO SALE in the game are never offered.* |
| **Look (destroy)** | Lists in the console what the destroy run would destroy. Destroys nothing. |
| **Run (destroy)** | Destroys every item on your destroy list found in the bags ticked on the Destroy list tab. Destroyed items do not come back.<br>*Use Look first. It only touches the bags ticked on the Destroy list tab (bags 1 and 2 to start with).* |
| **Run (tse)** | Transmutes, salvages and/or extracts items using the options saved on the TSE tab.<br>*There is no Look for TSE.* |
| **Look (restock)** | Lists in the console what the Default restock profile still needs and which depots are in reach. Pulls nothing.<br>*Always the profile named Default. To look at another profile use Preview on the Restock tab.* |
| **Run (restock)** | Pulls items from your depots until you hold the target amount of each row in the Default profile. It never buys anything; a shortfall is reported.<br>*Always the Default profile. Use 'Run this profile' on the Restock tab for another one.* |
| **Look (trade)** | Walks the trade queue in the console: who is in reach and what would go in the first trade window. Hands nothing over. |
| **Run (trade)** | Hands each queued item to the player it names, one entry at a time. The other player must be nearby and accept the trade. |
| **Run (quiver)** | Fills your equipped quiver or pouch with ammo from your bags, then from the Ammo Depot. |
| **Queue (any mode, while something runs)** | Adds that mode to the waiting line. Queued modes run one after another, in the order you clicked, when the current one finishes. A dot or ×2 beside the mode name shows it is waiting.<br>*Look buttons stay greyed out until everything has finished.* |



## Run tab - Right now

Read-only. Window says whether IM counts its window as open. Doing names the running mode (or idle). Detail shows that mode's current step. Queued (only when something is waiting) lists the modes still to come, in order.

## Sell list tab

Left: what the open merchant would buy from you (green = already on your sell list, xN = how many stacks). Right: your saved sell list. It fills by itself when you open a merchant window while this tab is showing.

| Control | What it does | Default |
|---|---|---|
| **type to filter… (left)** | Hides left-hand rows whose name does not contain the text. Not case-sensitive. Display only. | empty |
| **Double-click a left row** | Adds that item to the sell list (or destroy list on the Destroy tab) and saves it. The row turns green.<br>*Adding an item that is already there does nothing.* |  |
| **type to filter… (right)** | Hides right-hand rows whose name does not contain the text. Display only. | empty |
| **Click a right row, then right-click it** | Removes that item from the list and saves it.<br>*Right-clicking a row that is not selected only selects it, so a stray right-click never removes anything.* |  |
| **Re-open merchant** | Reads the merchant again and refills the left list. If no merchant window is open it opens one within reach first (your last one, your target, or the nearest). Either way it then closes the merchant window.<br>*It closes the merchant window even if you opened it yourself. If no merchant is within reach it says so in the console and the list is left as it was.* |  |



## Destroy list tab

Same two lists as the Sell tab: left is what is in your bags, right is your saved destroy list. Double-click and right-click work the same way.

| Control | What it does | Default |
|---|---|---|
| **1 2 3 4 5 6** | Which of your six bags the destroy list works with: the left list shows their items, and Run destroy (and Look) only touch these bags. Saved. The list rebuilds as you tick.<br>*The same boxes decide the left list and the run, so they always agree.* | 1 and 2 on |
| **Overseer** | Also use items in your Overseer bag, for the list and the run. Saved. | off |
| **Harvest** | Also use items in your Harvest bag, for the list and the run. Saved. | off |
| **Shared TS** | Also use items in your Shared Tradeskill bag, for the list and the run. Saved. | off |
| **Refresh** | Re-reads your bags and rebuilds the left list. |  |



## TSE tab

Everything here is saved, and a plain `ogre im tse` (or Run tse) uses it. Options typed on the command line still win for that one run.

| Control | What it does | Default |
|---|---|---|
| **Transmute** | TSE transmutes the items it picks. Ticking it unticks Salvage and Salvage + Transmute. | on |
| **Salvage** | TSE salvages the items it picks. Ticking it unticks the other two. | off |
| **Salvage + Transmute** | TSE salvages or transmutes each item, whichever applies. Ticking it unticks the other two. | off |
| **Extract (overlay)** | Also extracts, on top of whichever of the three above is ticked. | off |
| **No tier, Handcrafted, Treasured, Legendary, Fabled, Mastercrafted, Mythical, Celestial, Masters, Spell scrolls, Unknown tier** | Which item tiers TSE may use. An item of an unticked tier is left alone. Each box saves as you click.<br>*Treasured also covers Uncommon; Mastercrafted also covers Mastercrafted Legendary and Mastercrafted Fabled. Unknown tier is for a tier the bot has never seen (a new expansion).* | Treasured, Legendary and Fabled on; the rest off |
| **from** | Lowest item level TSE will use. Saved when you leave the box or press Enter.<br>*If 'from' is above 'to', nothing qualifies and a warning shows beside the boxes.* | 1 |
| **to** | Highest item level TSE will use. Saved when you leave the box or press Enter. | 200 |
| **Only at or below** | When ticked, TSE only uses an item whose resolve is at or below the number beside it. When unticked, resolve is not checked at all. | off |
| **Resolve number** | The highest resolve TSE may use when 'Only at or below' is ticked. Saved when you leave the box or press Enter; you can set it before ticking the box.<br>*With the box ticked, 0 means nothing qualifies.* | 0 |
| **Bags 1 2 3 4 5 6** | Which of your six bags TSE looks in. TSE's own set - separate from the Destroy tab's. Saved. | 1 and 2 on |
| **Overseer / Harvest** | Lets TSE also use items in your Overseer bag or your Harvest bag. Each box is for its own bag. | off |
| **Shared TS** | Lets TSE also look in your Shared Tradeskill bag. That bag holds crafting materials, so it rarely has anything TSE can use. | off |



## Depot tab

This builds the depot line a plain `ogre im depot` (and Run depot, and the -depot step of a chain) uses. Nothing is sent until you press Save; the line under 'The line this sends' shows what Save will store.

| Control | What it does | Default |
|---|---|---|
| **Nearest** | Use whichever size of each depot is in reach. Ticking it unticks Small and Large. | on |
| **Small** | Use the regular-size depots. Can be on together with Large (it visits both). Unticks Nearest. | off |
| **Large** | Use the large depots. Can be on together with Small. Unticks Nearest. | off |
| **everything, all tiers** | Ticks every depot with All (including Ammo). Unticking it unticks every depot.<br>*This includes the Ammo Depot, so a depot run would put your arrows back in the depot.* | off |
| **Depot name (Harvesting Supply Depot, Scroll Depot, ... Ammo Depot)** | Includes that depot. Ticking a depot with no tier beside it turns on its All.<br>*Ammo is off by default because `ogre quiver` pulls ammo out of that depot.* | every depot on with All except Ammo Depot (off) |
| **All (beside a depot)** | Uses that depot's own Deposit All button: everything the depot accepts. Ticking it clears that depot's single tiers. | on for every depot except Ammo |
| **Tier boxes (Common, Treasured, Legendary, Fabled, Rare, (Lesser), ...)** | Deposit only these tiers into that depot, using the depot's own buttons. Each depot has its own set. Ticking one turns off All for that depot. | off |
| **Commons, Rares, Manas, Infusions, Powders, Fragments** | Deposits these harvested/refined items one at a time by name, into a ticked depot that takes them. This is how you say, for example, 'fragments but not powders'.<br>*They only go into depots that are ticked above.* | off |
| **Arrows, Shurikens** | Deposits arrows or shurikens one at a time by name into the Ammo Depot.<br>*Only works when Ammo Depot is ticked.* | off |
| **Back to saved** | Throws away your unsaved ticks and shows the saved line again. |  |
| **Save** | Saves the line shown above. From now on Run depot, `ogre im depot` and the -depot chain step use it.<br>*Greyed out when no depot is ticked, no container size is ticked, or a ticked depot has nothing it could take (no tier, no All, and no item box that depot accepts - a red note says which).* |  |



## Restock tab

A profile is a list of items with a target amount. Rows that do not apply to this character (by For who) are dimmed. Changes save as you make them.

| Control | What it does | Default |
|---|---|---|
| **Profile** | Which profile this tab shows and edits. The number is how many rows it has. Display only. | the first profile (Default) |
| **Preview** | Lists in the console what this profile still needs and which depots are in reach. Pulls nothing. |  |
| **Run this profile** | Pulls items from your depots until you hold each row's target (only the rows meant for this character). Never buys.<br>*Greyed out while IM is running something.* |  |
| **Target** | How many of that item to hold. Saved when you leave the box or press Enter. 0 removes the row. |  |
| **For who** | Which characters this row is for: all, a name, @Scout1, a class word such as priests, *Team:Name and so on. Saved when you leave the box or press Enter. Other characters skip the row. | all |
| **▾ (beside For who)** | Opens a short list to pick from: All, Fighter, Mage, Priest, Scout, G1 to G4. Picking one fills the box and saves it. |  |
| **× (Drop)** | Removes that row from the profile and saves. |  |
| **item name…** | The exact name of the item for a new row. | empty |
| **From examine** | Fills the name in from the item examine window you have open. |  |
| **Amount (next to item name)** | The target for the new row. | 1 |
| **for who: all** | Who the new row is for: all, a name, or a class such as fighter. Empty means all. | empty (all) |
| **▾ (beside for who: all)** | The same short list. Picking one fills the box; nothing is saved until you press Add. |  |
| **Add** | Adds the row to the profile shown and saves, for the characters in the for who box. If the item is already there, its target is replaced. |  |



## Trade tab

A list of hand-overs: which item, how many, to whom. The list lives only until the game or the bot is restarted.

| Control | What it does | Default |
|---|---|---|
| **Preview** | Walks the list in the console: whether each player is in reach and what would go in the first trade window. Hands nothing over.<br>*Greyed out when the list is empty.* |  |
| **Run the queue** | Opens a trade with each named player in turn and hands over the item. They must be nearby and accept.<br>*Greyed out when the list is empty or IM is already running.* |  |
| **Clear** | Empties the whole list. |  |
| **× (Drop)** | Removes that one entry. The entries below it move up a number. |  |
| **player…** | Who gets the item. | empty |
| **qty or all** | How many to hand over. Empty or 'all' means every one you have. | empty (all) |
| **item name…** | The item to hand over. | empty |
| **From examine** | Fills the name in from the item examine window you have open. |  |
| **Queue it** | Adds the entry to the end of the list. Needs a player and an item. |  |



## Quiver tab

| Control | What it does | Default |
|---|---|---|
| **Arrows (bow) / Bolts (crossbow) / Throwing (shuriken)** | The ammo name to refill with. Filling the quiver uses the ammo already in your quiver first, then this name, then the built-in name shown in grey. | empty (built-in name) |
| **Examine** | Sets that kind of ammo to the item in the examine window you have open. |  |
| **Fill the quiver** | Fills your equipped quiver or pouch with ammo from your bags first, then from the Ammo Depot. The kind of ammo follows your ranged weapon and what is already in the quiver. |  |



## Button row and closing

| Control | What it does |
|---|---|
| **Stop** | Stops whatever IM is doing: the running mode, the whole waiting line, and any depot pull still going. The window stays open.<br>*Greyed out when nothing is running.* |
| **Run <tab> / Queue <tab>** | Starts the mode for the tab you are on - the same as that mode's Run on the Run tab (or Queue while something is running).<br>*On the Restock tab this runs the Default profile, not the one you picked - use 'Run this profile' for that. Not shown on the Run tab.* |
| **Help in console** | Prints the list of `ogre im` commands in the console. |
| **Close** | Closes the window. A mode that is running keeps running. Cancels a pending -end, and closes a merchant window IM left open.<br>*To stop the work and close, use `ogre end im`.* |
| **Title bar close (X)** | Stops the work and closes the window, the same as `ogre end im`. Also cancels a pending -end and closes a merchant window IM left open. |



## What the window shows

- Status dot and word (top right): grey and 'idle' when nothing runs; green and the mode's name while one runs.
- Yellow '-end is armed' notice: this window will close itself a moment after all the work finishes (started with `-end`, e.g. `ogre im -depot -sell -end`).
- Run tab, mode row highlighted with a dot: that mode is running now; its 'What it does' text is replaced by what it is doing.
- Run tab, dot or ×N after a mode name: that mode is waiting in the queue (N times).
- Sell and Destroy lists: green on the left = already on your list; xN = how many stacks of it there are.
- Restock rows in dim grey: not meant for this character (For who does not match).
- Activity log: one line per thing actually done - a stack sold, an item destroyed or transmuted, a depot emptied - plus a 'finished' line per mode. The coloured word is which mode did it.

## Good to know

- Restock's Look and Run on the Run tab (and 'Run restock' at the bottom) always use the profile named Default. Use the buttons on the Restock tab for another profile.
- Quiver refills with the ammo already in your quiver first, then the name on the Quiver tab.
- The Close button does not stop a running mode. The X (or `ogre end im`) stops it and closes the window; Stop stops it and keeps the window.
- The Depot tab saves nothing until you press Save.
- The trade list is not saved; it is lost when the game or bot restarts.

# TaskRunner Lists

> **:bulb: In game - the ? button on this window says**
>
> Builds the lists TaskRunner works through: which characters it logs in, in what order, and which timed chores each one does. Run a list with `ogre taskrunner -list <list>` (`run <list>` works too).
>
> **What you can do here**
>
> - **Run** - starts the selected list on this session (save first). The bar shows what it is doing: which character, which chore, and the last result. **Stop** stops it and leaves the character where it is.
> - **List** - click the box and type to find a list (they are in alphabetical order). Type a name that is not a list yet and pick **+ New list** (or press Enter) to make it.
> - **New / Duplicate / Rename / Delete** act on the selected list. Duplicate copies the members, their order and the run mode.
> - **Click a character** on the left to add it to the selected list. Use the **search** box to find a character or account. In **By account**, right-click an account and pick **Add all toons** (or open it and press **Add all**) to add the whole account - anyone already in the list is skipped.
> - **Drag a member row** up or down to change the order the list runs in.
> - **Chore buttons** on a row turn a chore on or off for that character. The **Everyone in** row does it for the whole list.
> - **When run** - **Keep looping** (stays running and picks chores up as they come due - leave it overnight) or **One pass** (does what is due now, then stops).
> - **Stagger start** - each session waits before its first login (is2 30 seconds, is3 60 seconds, and so on). Leave it on when one command starts lists on every session, or the server turns some logins away.
> - **Chore options** - one row per chore. **Guild hall first** travels to the guild hall unless the character is already in one or in a house. **Harvest depot after** puts all harvests into the nearest harvest depot afterwards. **Destroy list after depot** then destroys the items on your IM destroy list - the excess the depot would not take. It only runs with Harvest depot after on, and only when the depot finished. **Bushels** (Plant): the harvest gives a bushel - leave it packed, take the latest reward (a new expansion is picked up on its own), or a chosen reward number. A bushel is lore, so the plant is never harvested while one is still in the bags - with "leave it packed" that character skips the plant until you unpack it. (Pack Pony always loads OgreBot first - it reads its answers from your profile.)
> - **Save** writes your changes (what you set by hand in your own TaskRunner files is kept). **Discard** throws them away and reads the files again.
>
> **Good to know**
>
> - Never run two lists that share a character on two sessions at once.
> - A character's chores are the same in every list they are in.
> - **Overseer** never logs a character in by itself: it runs when the character is logged in for another chore (the pack pony). Its status says "next login" while it waits.
> - A character in a raid is never logged out: the run stops and leaves everyone where they are.
> - A character that cannot do a chore at all (no Pack Pony) is marked with an error and skipped until you clear it: `ogre taskrunner clear <name>`.
> - Closing the window loses unsaved changes without asking.
> - Closing the window also stops a run in progress, the same as `ogre end taskrunner`. `ogre taskrunner stop` stops it and leaves the window open.

**Open it:** Type `ogre taskrunner panel` (or `ogre tr panel`). `ogre taskrunner gui` and `ogre taskrunner config` also open it.

## What it is for

TaskRunner logs your characters in one after another and does their timed chores, such as the Artisan's Pack Pony and the Goblin House Plant. This window builds the named lists it works through. Pick characters from the ones you have a stored login for, put them in a list, and choose which chores each one does. Then press Run, or type `ogre taskrunner run <list>`, to run the list on this session. Nothing is written until you press Save.

## Header

| Control | What it does |
|---|---|
| **Refresh roster** | Reads your stored logins again, so characters you have added since the window opened show up on the left.<br>*Your unsaved list edits are kept.* |



## Lists

The box at the top picks the list you are editing. The buttons beside it act on that list.

| Control | What it does | Default |
|---|---|---|
| **List: (box)** | Click the box and type to find a list. Lists are in alphabetical order, each with how many characters it holds. Pick one to edit it. Type a name that is not a list yet and pick + New list, or press Enter, to make it. | the first list |
| **New** | Opens a name box under the row. Type the new list's name and press OK. The list starts empty.<br>*One word, no spaces or quotes, up to 40 characters: you type it after `ogre taskrunner run`. A name that is already used (in any letter case) is refused with a red message.* |  |
| **Duplicate** | Copies the selected list to a new name: its members, their order and its run mode. The name box opens with a free name filled in. The copy becomes the selected list. |  |
| **Rename** | Opens the name box with the selected list's name, to rename it. |  |
| **Name box (OK / Cancel)** | Shown by New, Duplicate and Rename. Enter does the same as OK, Escape the same as Cancel. |  |
| **Delete** | Deletes the selected list. The characters keep their chore choices.<br>*No confirmation, but nothing is written until Save; Discard brings it back.* |  |



## Run and Stop

At the right of the list row. While a list runs, the status here says which character and which chore it is on, and the footer shows the last result.

| Control | What it does |
|---|---|
| **Run <list>** | Starts the selected list on this session, using its When run choice and the Stagger start option.<br>*Run uses the saved lists: with unsaved changes it refuses and tells you to save first.* |
| **Stop** | Shown while a list runs. Stops the run and leaves the character where it is. |



## Run options

One row for the whole run, then one row per chore. These are for every list, and Save writes them like everything else.

| Control | What it does | Default |
|---|---|---|
| **Stagger start (30s per session)** | Each session waits before its first login: is1 at once, is2 after 30 seconds, is3 after 60, and so on. Leave it on when one command starts lists on every session, or the server turns some logins away.<br>*`nostagger` or `stagger` after `ogre taskrunner run <list>` overrides this for that run.* | on |
| **Guild hall first** | The chore only runs in a guild hall or a house. A character that logged out anywhere else travels to the guild hall first. | on for Pack Pony, off for the others |
| **Harvest depot after** | Afterwards, puts all harvests into the nearest harvest depot. Needs a depot near where the chore runs. | on for Pack Pony, off for the others |
| **Destroy list after depot** | After the harvest depot, destroys the items on your IM destroy list: the excess the depot would not take. It only runs with Harvest depot after on, and only when the depot finished. | off |
| **Bushels: <choice>** | Only on the Plant row. The harvest gives a bushel: leave it packed, take the latest reward (a new expansion is picked up on its own), or take a chosen reward number.<br>*A bushel is lore, so the plant is never harvested while one is still in the bags. With Do not unpack that character skips the plant until you unpack it.* | latest reward |



## Your characters (left side)

Every character you have a stored login for, with its account and server. 'in 2' means the character is already in two lists; those rows are dimmed.

| Control | What it does | Default |
|---|---|---|
| **All toons** | Shows every character in one alphabetical list. Display only. | on |
| **By account** | Groups the characters under their accounts. Display only. | off |
| **search characters or accounts...** | Narrows the left side to characters or accounts whose name contains the text. | empty |
| **Click a character** | Adds that character to the end of the selected list. A character new to TaskRunner starts with every chore turned on.<br>*A character already in the list gets a red 'already in' message. With no list yet you are told to make one first.* |  |
| **Click an account (By account view)** | Opens the account to show its characters. Click again to close it. Display only. | all closed |
| **Add all** | Adds every character on that account to the selected list. Characters already in it are skipped. Right-clicking an account does the same, from any account, open or not.<br>*The button is only shown on an opened account.* |  |



## How the list runs, and chores for everyone

| Control | What it does |
|---|---|

# Ability Export

> **:bulb: In game - the ? button on this window says**
>

>
> **What you can do here**
>
> - **Choose what to include**: passives, ascension abilities, a minimum tier or level range, or just a few named abilities.
> - **Merge** into the file you have, write a **Fresh file**, or add **Only abilities I don't have yet** (much faster).

# Analysis

> **:bulb: In game - the ? button on this window says**
>
> Watches NPCs during an encounter and records every change to them, so you can see what else changed at the moment something happened. It only watches; it never changes what the bot does.
>
> **What you can do here**
>
> - **Monitor**: add actors (**+ Target**, or **+ Cursor** and put the mouse on one within 3 seconds), turn **Monitoring** on, then click a moment in Timestamps to see everything that changed then. The x on an actor stops watching just that one.
> - **Scan**: build terms (type a detail name - it suggests them - pick how to compare, add a value), then **Scan**. Click a result to see all its details; Ctrl+click a second to compare the two. **+ Target** / **+ Cursor** put one actor in the results. **monitor** on a result sends it to the Monitor tab.
> - **Events**: logs of announcements, spawns, chat and other game events. **Search the log** finds lines already recorded; **Record only lines containing** limits what is recorded from now on.
> - **Sessions**: save what you recorded to a file, or load an earlier one.
>
> **Good to know**
>
> - Tick **Keep previous results** to add to the results instead of replacing them. **Add new spawns that match** adds actors as they appear.
> - Pin a detail (the diamond) to show it as a column on every result.
> - Right-click any line to copy it, copy all of an actor's details, or remove it. The x on a result or an actor removes just that one.
> - Closing the window stops monitoring and the event logs, the same as `ogre end analysis`. What was recorded is kept.
> - **Taps** turns the event logs on and off.

**Open it:** Type `ogre analysis` (or `ogre anal`). `ogre end analysis` (or the window's X) turns monitoring and the event logs off, stops a scan in progress, and closes the window. What was recorded is kept.

## What it is for

A tool for working out how an encounter behaves. You pick a few NPCs and it records every change to them - health, animation, target, mood and over 80 other details - several times a second, so you can see exactly what else changed at the moment something happened. It can also take a snapshot of many NPCs at once and compare two of them side by side, and log announcements, spawns, chat and other game events. Nothing here changes what the bot does; it only watches and records.

# Pulse Budget

> **:bulb: In game - the ? button on this window says**
>
> A performance window. A few big jobs are spread over several frames so the game does not freeze; this shows how much time each may use per frame, and what every part of the bot really costs.
>
> **What you can do here**
>
> - **Slice** on a row: how long that job may run each frame, in microseconds. Lower it if the game stutters while the job runs. 0 runs it all at once.
> - **Frame ceiling**: a shared limit for the bot's work each frame. Untick **Use the frame ceiling** to turn off just that limit - each job keeps its own slice.
> - **Reset counters** and **Refresh** to measure again.
>
> **Good to know**
>
> - A slice never skips work - a job just takes more frames to finish.
> - Most players never need to change anything here.
> - A row marked (idle) has not run yet this session. Its slice can still be changed, and is used when it runs.

**Open it:** Type `ogre pulse` (or `ogre pulsebudget`). `ogre end pulse` closes it.

## What it is for

A performance window. The bot does its work in small steps, once every frame the game draws. A few big jobs - planning a route, scanning all the actors for Analysis, walking a recipe book, walking the ability-upgrade list - would freeze the game for a moment if done in one go, so they are spread over several frames. This window shows how much time each of those jobs may take per frame, and how much time each part of the bot is really using. Most players never need to touch it. If the game stutters while one of these jobs runs, lower that job's slice; if a job takes too long and your PC has room to spare, raise it.

## Top row

On the right: how many frames have been counted, and how many times a job paused and carried on in the next frame. A pause never loses work.

| Control | What it does | Default |
|---|---|---|
| **Use the frame ceiling** | Turns the Frame ceiling on or off. Only the shared ceiling - each job's own slice still applies either way.<br>*Despite the name, unticking it does not make jobs run in one go - set a job's slice to 0 for that.* | on |
| **Frame ceiling … µs** | A shared limit, in microseconds (millionths of a second), for the bot's whole work each frame. Once the bot has used this much in a frame, the paced jobs stop early for that frame and carry on in the next. 0 = no ceiling.<br>*Saved when you press Enter or click away. Each job always gets at least one step per frame, however busy the frame is.* | 4000 µs (4 ms) |
| **Reset counters** | Sets the frame count, pause counts, Active frames, Units done and Worst back to zero, so you can measure from now. Slices are not changed. |  |
| **Refresh** | Updates the numbers. The window does not update by itself. |  |
| **Title bar close (X)** | Closes the window. Your slices and ceiling stay in force. |  |



## Resumable sections

One row per job that can be spread over frames. A job only appears after it has run once this session; jobs saved from earlier sessions are listed greyed out with '(idle)' - you can still set their slice, and it is used as soon as the job runs.

| Control | What it does | Default |
|---|---|---|
| **Slice µs/f (the box on each row)** | How long that job may run each frame, in microseconds, before it pauses and carries on in the next frame. 0 = run the whole job in one frame. Saved when you press Enter or click away.<br>*On an '(idle)' row the new slice is saved and handed to that job the first time it runs.* | each job has its own, for example nav ground plan 4000, zonereset: table 3000, craft: recipe scan 1500, analysis: actor scan 1000, abilityupgrades: row walk 1000 |



## Pulse profile

Read-only. Every part of the bot that runs each frame, costliest first, with its average and worst time per frame. Parts using less than half a microsecond on average are left out. Useful for spotting what is slowing the game down.

## What the window shows

- Section: the job's name - what it belongs to, then what it does.
- Last µs: how long the job ran the last frame it had work. Yellow at 1000 µs (1 ms) or more.
- Worst µs: its longest single frame since the last reset. Yellow at 1000 µs or more.
- Active frames: how many frames it did any work in.
- Units done: how many steps of work it got through.
- Paused: how many times it ran out of time and carried on in the next frame (green when above 0 - that is pacing working, not a problem).
- (idle): a job with a saved slice that has not run yet this session.
- Pulse profile - Avg µs/frame: yellow at 20 µs or more. Worst µs: yellow at 1000 µs or more.
- When no job has run yet, the table is replaced by a note saying so.

## Good to know

- A slice never skips work. A small slice only makes a job take more frames to finish.
- 1000 µs is 1 millisecond. At 60 frames a second a whole frame is about 16,600 µs.
- Settings are saved to OgreSave/EQ2/OgreBot/pulse-budget.json and apply to every character on this PC.
- The numbers are a snapshot - press Refresh to see new ones.

Straight after loading, before any paced job has run (and with no saved settings), the table is empty:

![Empty](../assets/pulsebudget/empty.png)

Console: `ogre pulse report` prints the same table; `ogrepulsebudget slice <section or number> <µs>` and `ogrepulsebudget ceiling <µs>` set values.

# Lag

> **:bulb: In game - the ? button on this window says**
>
> Records every frame of the last few minutes - how long it took and what ran in it - so when your FPS drops you can open that moment and see why.
>
> **What you can do here**
>
> - **The line** is your FPS, one point a second, for the last 3 minutes. A red tick marks a second with a frame over the budget (33 ms = under 30 FPS).
> - **Dips** lists those moments, newest first, with what caused the worst frame: **OgreBot**, the **GPU** (the game waiting on the graphics card), or **the game** itself. Click one to open its frames.
> - **What adds to the dips** ranks OgreBot's calls by how much longer they run in a dip than in a normal frame, and how often they run.
> - **Stats over** picks the window the numbers at the top use (30 s, 1 min, 5 min).
> - **Save frames** writes every recorded frame to a file under `OgreSave\EQ2\OgreBot\` to send to us.
>
> **Good to know**
>
> - It is always recording, even with this window closed. Its own cost is `ogre lag overhead`.
> - The target is: 95% of frames under 1.5 x your typical frame, and under 2% of frames over 33 ms.
> - `ogre lag report` prints the same numbers to the console; `ogre lag off` stops recording.
> - It holds the last 5 minutes by default. `ogre lag minutes 30` holds 30 (about 23 MB) - use it before a long session you want to save.

**Open it:** Type `ogre lag`. `ogre end lag` (or `ogre lag close`) closes it. If the window is already open, typing `ogre lag` again does nothing.

## What it is for

A recorder for frame rate drops. The bot writes down every frame the game draws - how long it took, how much of that time was the bot's own work, and which parts of the bot ran in it - and keeps the last few minutes. When your FPS drops, open this window and click that moment to see the frames around it and what caused the slow one: OgreBot, the graphics card, or the game itself. It records all the time, even with the window closed, so you can look after the drop has happened. Most players only need it when the game stutters and they want to know whether the bot is the reason.

## The numbers at the top

Read-only. All of these use the period picked under Stats over (1 minute to start with). Frames while zoning or on a load screen are left out.

| Control | What it does |
|---|---|
| **FPS (the big number)** | Your average frames per second over the period. |
| **median, 95%, worst** | How long frames took, in milliseconds. Median is a typical frame. 95% means 95 frames in 100 were faster than this; the number in brackets is that time divided by the median (1.00x would mean every frame is even). Worst is the slowest single frame. |
| **over 33.3 ms** | The share of frames slower than 33.3 ms - that is, frames that drop you under 30 FPS. These slow frames are what this window calls dips. |
| **frame-to-frame** | How much one frame's time differs from the next, on average. A low number means smooth play, even if the FPS is not high. |
| **target met / target not met** | Green when the period was smooth: 95 frames in 100 took less than 1.5 times the median frame, and fewer than 2 in 100 frames were over 33.3 ms. Red when either is not true. Not shown when there are no frames yet. |
| **OgreBot: … ms of each frame** | How much of each frame, on average, was the bot's own work: all parts of the bot, drawing its windows, and any bot commands that ran between frames. Then the period and how many frames it covers. |
| **Warning line (yellow)** | Shows 'Recording is OFF' when recording is turned off. It can also say the window system loaded in your game is too old to report its time - the UI and GPU numbers then read 0 until you restart the game client. |

## Stats over, Recording and Save frames

| Control | What it does | Default |
|---|---|---|
| **Stats over: 30 s / 1 min / 5 min** | Picks the period used by the numbers at the top, the counts under Dips, the What adds to the dips list, and the 'typical frame' used to judge what caused each dip. The picked button is outlined. Display only - changes what you see, not what the bot does.<br>*The FPS line and the list of dips always cover the last 3 minutes, whichever button is picked.* | 1 min |
| **Recording** | Turns the recorder on or off. Off: nothing new is recorded, but the frames already recorded are kept. The choice is saved and applies to every character on this PC.<br>*While Recording is off the window stops updating, even after you click something. Close and reopen it to see the current state.* | on |
| **Save frames** | Saves every frame the recorder is holding (the last 5 minutes, unless you changed that) to a file in OgreSave/EQ2/OgreBot/, named lag- plus the session name and the date and time. The console says how many frames were saved and where. Send the file to us when you report lag.<br>*Saving takes a moment, so the frame you saved in shows up as a dip itself. The console line says how long it took.* |  |

## The FPS line

Read-only. Your FPS, one point a second, for the last 3 minutes - newest on the right. Grey lines mark every 20 FPS. A red tick along the bottom marks a second that had a frame over 33.3 ms; the taller the tick, the more slow frames in that second. Hover a tick to see how many and the worst one.

## Dips

Every slow moment of the last 3 minutes, newest first. Slow frames that come within a tenth of a second of each other are one entry. The line at the top counts the slow frames in the Stats over period and how many each cause had. When the dips come at a steady beat it adds 'they repeat every … ms' and how many of the gaps match - a steady beat usually means something on a timer.

| Control | What it does |
|---|---|
| **Click a dip** | Opens the frames around that dip (see below). Each entry shows how long ago it was, the cause of its worst frame, the biggest bot call in that frame with its time, the worst frame's time, and 'x2', 'x3' … when more than one frame was slow. |

## What adds to the dips

Read-only. The bot's calls over the Stats over period - up to 14 - with the one that adds most to the slow frames first. A call that runs no longer in a slow frame than in a normal one is listed after those, by how long it takes on average. Hover a row for more: how often it ran in slow and in normal frames, its average time per frame, and how long it takes 95 times in 100.

## The frames around a dip

Opens over the two lists when you click a dip. One row per frame, from half a second before the dip to a second and a half after it. Slow frames are bright and carry their cause. 'typical frame' at the top is the median frame of the Stats over period.

| Control | What it does |
|---|---|
| **Back** | Closes the frame list and shows the two lists again. |
| **Title bar close (X)** | Closes the window. The recorder keeps recording. |

## What the window shows

- Dip causes: OgreBot (red) - the bot's own work covers at least half of the extra time over a typical frame. GPU/Present (yellow) - the game handing its picture to the graphics card covers at least half of it. game/other (grey) - neither: the game itself, or something else on the PC the recorder cannot see.
- What adds to the dips - +… ms: how much longer the call runs in a slow frame than in a normal one, on average. A minus means it runs shorter in slow frames.
- What adds to the dips - % of dips: in how many of the slow frames the call ran. worst: its slowest single run, in ms. every … ms: shown when it runs on a steady timer.
- (command) in front of a name: an `ogre` command or a script call into the bot (for example one sent from another session), not part of the bot's regular work each frame.
- (inside) in front of a name: a step that runs inside another call on the list, so its time is already part of that call's time.
- Frame list - when: seconds from the start of the dip. frame: how long the frame took, in ms.
- Frame list - OgreBot: all of the bot's time in that frame (adapter + core + UI + cmds). adapter: the EverQuest 2 part of the bot. core: the shared part of the bot (with '(… panel)' when clicks from the bot's windows were handled in that frame). UI: drawing the bot's windows. cmds: bot commands that ran between frames.
- Frame list - GPU: time the game spent handing its picture to the graphics card. reads: how many values the bot read from the game in that frame. biggest calls: the bot's slowest calls in that frame, up to 8, in ms.
- Calls that take less than 0.01 ms in a frame are not named for that frame - their time is still counted in OgreBot's total.
- The window updates itself about once a second while you are in the game.

## Good to know

- It is always recording, even with the window closed. `ogre lag off` (or unticking Recording) stops it.
- It holds the last 5 minutes by default. `ogre lag minutes 30` holds 30 (about 23 MB of memory) - do that before a long session you want to save. Changing it throws away what was already recorded.
- A dip marked GPU/Present or game/other had no bot work big enough to explain it. Graphics settings, other programs or the game itself are the better place to look.
- The list of dips always covers 3 minutes, but the count above it covers only the Stats over period - so the count can be smaller than the list.
- Recording, the budgets and the minutes to hold are saved to OgreSave/EQ2/OgreBot/lag.json and apply to every character on this PC. Stats over is not saved - it is back to 1 min after the bot is reloaded.

Opened while Recording is off, the frames already recorded are still shown, with a warning above the buttons:

# Migration Assistant

> **:bulb: In game - the ? button on this window says**
>
> Copies your OgreBot Classic settings into the new bot: logins, Inventory Manager settings and lists, OgreBot profiles, IRC settings, MCP buttons and saved AutoTarget lists. It also adds an InnerSpace game profile, **Everquest 2 ISXOgreX**, under each InnerSpace game that runs EverQuest2.exe (whatever you named it) - launch a session with it and the new bot loads by itself.
>
> **What you can do here**
>
> - **Nothing, usually** - at load, anything not copied yet is copied for you, and this window shows the progress, then closes.
> - **Check the status** of each item with `ogre migrate`: Migrated, No source found, Nothing to migrate, or Not migrated (a copy that failed - the message says why).
> - **Re-run (overwrite)** copies an item again from Classic, replacing what the new bot has. It asks first: **Overwrite** or **Cancel**.
> - **Add what is missing**, on the InnerSpace profile item, adds the profile to any game that lacks it and replaces nothing. It asks first: **Add** or **Cancel**.
>
> **Good to know**
>
> - Your Classic files are only read, never changed.
> - The InnerSpace profile is the one thing it adds outside the bot: a copy of your EverQuest 2 Client profile whose startup runs `timedcommand 10 ext isxogrex`. Your other profiles are not touched, and a backup of InnerSpace's GameConfiguration.XML is kept next to it (GameConfiguration.before-ISXOgreX.XML).
> - Each item is copied automatically only once. After that, only Re-run (overwrite) copies it again.
> - Problems are listed in ISXOgreEQ2.log.

**Open it:** Type `ogre migrate`. It also opens by itself once, a few seconds after the bot loads, when it finds Classic settings that have not been copied yet.

## What it is for

The Migration Assistant copies your Classic settings into the new bot: logins, Inventory Manager settings and lists, OgreBot profiles, IRC settings, MCP buttons and saved AutoTarget lists. It also adds an InnerSpace game profile, **Everquest 2 ISXOgreX**, that loads the new bot by itself. You do not have to do anything. When the bot loads, every item that has Classic files but nothing in the new bot yet is copied automatically, and this window pops up to show the progress, then closes itself. Your old Classic files are only read, never changed. Open it yourself with `ogre migrate` to see the status of each item and to copy an item again, replacing what the new bot has.

## The item boxes

Each box shows one thing that can be copied from Classic and where it stands right now. The status is worked out from your files every time the window opens.

| Control | What it does |
|---|---|
| **Re-run (overwrite)** | Asks to copy this item from your Classic files again, replacing what the new bot already has. Nothing is copied yet - the box changes to an Overwrite / Cancel question first.<br>*Only shown when you opened the window with `ogre migrate`, and only for items that have Classic files to copy. The InnerSpace profile item has Add what is missing here instead.* |
| **Add what is missing** | Asks to add the InnerSpace profile to any EverQuest 2 game that lacks it. Nothing is replaced: a game that has it is left alone. Nothing is added yet - the box changes to an Add / Cancel question first.<br>*Only shown when you opened the window with `ogre migrate`.* |
| **Overwrite** | Copies the item again from your Classic files and replaces what the new bot has. For profiles, every copied profile file is rewritten. When it finishes, the box shows what was copied.<br>*Anything you changed in the new bot for that item since the first copy is lost.* |
| **Cancel** | Backs out of the Overwrite question. Nothing is copied. |
| **Title bar close (X)** | Closes the window. Copying that is already running keeps going.<br>*The automatic progress view closes by itself about 4 seconds after everything is done.* |



## Asking to overwrite

After Re-run (overwrite), the box asks before it replaces anything. This is the only question the assistant ever asks.

## The automatic run at load

When the bot loads and finds Classic files for an item that the new bot does not have yet, it copies them without asking and shows this view. There are no buttons here. Profiles can take a moment for a big library and show Running... until they are done. When every item is finished the window closes by itself.

## What the window shows

- ✓ Migrated (green) - the new bot already has this item. It may have been copied just now, automatically, or in an earlier session.
- No source found (grey) - you have no Classic files for this item, so there is nothing to copy.
- Nothing to migrate (grey) - you have Classic files for this item but the new bot has nothing yet, and no copy was tried this session.
- Not migrated (red) - this session tried to copy the item and could not. The message above it says why.
- Running... - the item is being done right now (OgreBot profiles and the InnerSpace profile only).
- Green message - what was copied, e.g. 'Migrated 6 characters to the new store.'
- Orange message - a warning or a question, e.g. a few profile files were skipped, or 'overwrite it?'.
- Red message - the copy failed. The details are in ISXOgreEQ2.log.
- Grey message - the item is still being copied (OgreBot profiles, which can take a moment).

## Good to know

- Your Classic files are never changed or deleted. You can keep using Classic alongside.
- An item is copied automatically only once: as soon as the new bot has that item's file, it is treated as done. To copy it again you must use Re-run (overwrite).
- Opening the window with `ogre migrate` first copies anything that is still waiting, without asking - the same as the automatic run.
- Profiles: files that were missing or could not be read are skipped and counted in the orange message. Running it again copies the same set, so re-running will not fix them - check ISXOgreEQ2.log for which files.
- Inventory Manager lists (sell, destroy, restock) go into your own custom files. A list you already have is kept, not replaced, unless you use Re-run (overwrite).
- Saved AutoTarget lists go into one file per zone. A list you already have in the new bot is kept, and any others are added beside it. Re-run (overwrite) replaces only the lists with the same name, and never removes one.
- The InnerSpace profile is the one thing added outside the bot: a copy of your EverQuest 2 profile, under each InnerSpace game that runs EverQuest2.exe, whose startup loads the new bot. Launch a session with it and the new bot loads by itself. Your other profiles are not touched, and a backup of GameConfiguration.XML is kept next to it. Its Add what is missing button adds the profile to any game that lacks it and changes nothing else.
- The first time the bot loads, the New User Tour runs first. The automatic copy starts a few seconds after the tour is finished or skipped.
- Typing `ogre migrate` while the window is open does nothing.

# New User Tour

> **:bulb: In game - the ? button on this window says**
>
> A quick hands-on tour of the new Ogre windows. Each step moves on by itself as soon as you do it.
>
> **What you can do here**
>
> - **Step 1** - drag the right edge, bottom edge or bottom-right corner to resize the window.
> - **Step 2** - right-click the title bar to open its menu.
> - **Step 3** - choose **Save Position** so the window opens in the same spot next time.
> - **Step 4** - click the gear to open the settings, then click it again (or its X) to close them.
> - **Skip** ends the tour at any step. **Got it** closes it at the end.
>
> **Good to know**
>
> - Your other Ogre windows are hidden during the tour and come back when it ends.
> - Type `ogre tour` to see it again any time.

**Open it:** Opens by itself the first time the new bot loads. Type `ogre tour` to see it again any time (typing it while the tour is open does nothing).

## What it is for

A short hands-on tour of the new Ogre windows, for players coming from Classic. It starts with a short cartoon (the Welcome to OgreBot window), then teaches four things you do on the tour's own window: resize it, right-click its title bar, save its position, and open its settings gear. Each step moves on by itself as soon as you do it, and a pulsing outline shows you where to click. While the tour is up, your other Ogre windows are hidden; they come back when it ends.

## Step 1 - Resize me

Drag the right edge, the bottom edge or the bottom-right corner of the tour window (only those can be dragged). They pulse to show where. As soon as the size changes, the tour moves to step 2.

| Control | What it does |
|---|---|
| **Skip** | Ends the tour now. It counts as seen, so it will not open by itself again. Your hidden windows come back.<br>*Every step has Skip. `ogre tour` brings the tour back later.* |
| **Title bar close (X)** | Closing the tour window is the same as Skip: the tour counts as seen and your hidden windows come back. |

## Step 2 - Right-click my title bar

Right-click the title bar (the bar with the window's name). Its menu opens and the tour moves to step 3. Every Ogre window with a title bar has this menu.

## Step 3 - Save this window's spot

In the title-bar menu, choose Save Position (it pulses). That makes the window open in the same place and size next time. Once you save, the tour moves to step 4.

| Control | What it does |
|---|---|
| **Save Position (title-bar menu)** | Saves where this window is and how big it is, so it opens there next time. On the tour this also finishes step 3.<br>*If the menu closes without saving, right-click the title bar again.* |

## Step 4 - Open the settings

Click the gear (⚙) in the top-right corner. Many windows keep their settings behind a gear like this. Close the settings again (gear or its X) to finish.

| Control | What it does |
|---|---|
| **⚙ (Settings)** | Opens and closes a small example settings panel inside the tour window. On step 4, closing it finishes the step.<br>*The example settings do nothing and save nothing.* |
| **x (close settings)** | Closes the example settings panel, the same as clicking the gear again. |
| **A toggle option / A slider / A colour** | Examples only, to show what a settings panel looks like. Nothing here saves or changes anything. |

## All set

The last page reminds you that most commands work like before (`ogre` still loads OgreBot), and that right-clicking windows and lists often shows extra options.

| Control | What it does |
|---|---|
| **Got it** | Closes the tour. It counts as seen and will not open by itself again. Your hidden windows come back. |

## What the window shows

- Step label - which step you are on (Step 1 of 4 to Step 4 of 4, then All set).
- Pulsing yellow outline - the thing to click or drag for the current step (the right and bottom edges and the bottom-right corner, the title bar, the Save Position menu row, or the gear).

## Good to know

- While the tour is open, every other Ogre window is hidden so you can focus. They all come back when the tour ends (Got it, Skip or closing it).
- If the InnerSpace console is open when the tour starts, it is closed so it does not push the tour out of the way.
- On the very first load, the Migration Assistant waits for the tour: your Classic settings are copied a few seconds after you finish or skip the tour.
- Whether you have seen the tour is saved in OgreSave\EQ2\TourState.json. Delete that file to have the tour open by itself again.
