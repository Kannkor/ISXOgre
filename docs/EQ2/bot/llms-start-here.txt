# OgreBot - User Guide

This guide explains every window of the new OgreBot: what each one is for, and what every option on it does.

Every page starts with a picture of the window, then goes through it one area at a time. The area being
described is outlined in **pink** in its picture.

> **:memo: Examples use made-up names**
>
> Every name in these pictures - Kannkor, Brutus, Mirelle, Tobbin - is made up. Nothing here shows a real
> character, account, guild or server.

## Where to start

- New to the bot? Read [The basics](basics.md) first. It covers the window buttons every window shares.
- Setting up a character: [OgreBot](ogrebot/index.md), then its [Settings](ogrebot/settings.md) and
  [Cast Stack](ogrebot/cast-stack.md) tabs.
- Running zones: the [Instance Controller](windows/ic.md).
- Sharing out loot: [SmartLoot](windows/smartloot.md).

## Help inside the game

Every window has a **?** in its title bar. Click it for a short explanation of that window. The
**Full documentation** button in that box opens this guide.

# The super secret project

Where to even start! I guess a super brief history of how OgreBot became to be. I'd guess the basics of my story was the same as most people's here. A friend wanted me to play eq2 with them (they wanted me to make a bot, as I had done so for eq1). I said sure, but I was ONLY playing 1 toon. Pretty sure I made a troubadour. I was coding at low levels but it was hard back then. It logically only made sense, to have a second account for a priest. It's only 2 accounts, that's basically just 1 account.

Then I was killing slow... so may as well add some dps to the group... 3 accounts is barely more than the 2 I already have. It's only 1 more. Yes, you can absolutely hear the "justification" to myself about how this is all fine. The friend who got me into eq2, I'm pretty sure at this stage, is absolutely laughing his ass off, because he new this would happen, and he knew exactly what was coming next.

Well, if I'm already at 3, then I may as well just have my own group. Then there were 6.

Okay, fast forward almost 20 years or something now. Lax/Innerspace comes out with LGUI2 (it's what OgreCraft2's UI is done in). It provided a TON more options for dealing with GUIs, but LGUI2 isn't very friendly. I find it way over complicated, it was very new, so minimal documentation or examples. I made it work, but still didn't like it.

Then others, decided to bring in external GUIs. I thought this was an interesting idea, but the problem is, EVERYTHING is tied to my current GUI, that changing would be an absolute nightmare. It would basically be a rewrite of Ogrebot... and for what? To change the GUI?

Then a friend (don't tell him I called him that) and I were talking and joking... How long would it take, to rewrite Ogrebot from scratch, and make it work with a new GUI. With basically full parity (meaning, no loss of features). Our estimate was over a year. That assumes I focus the majority of my time there. That was absolutely not going to be worth it. Full stop, no thanks.

I didn't want to code untolds above tier 20, because Dominion of Pain sucks, so I was looking for a way to distract myself. I thought I'd look into these alternate GUIs to run some performance bench marks. If a new fancy GUI would be a net loss in performance, that's not worth it, at all. FPS (frames per second, not first person shooter) is way more important than having a fancy dancy GUI.

Did a bunch of research, and choose one. It is built using HTML (basically a webpage). This is fantastic, because HTML is likely the most common language ever (I didn't actually check to see if that's true, but almost every single website uses html). That means there's infinite amount of examples, and support etc etc.

I figured, okay, lets load this up, see how it works, do some performance tests, then go from there.

A WEEK LATER, I finally get it working. Like... me working on it every spare moment I have for an entire week. I was ready to bash my head into a wall.

Now that I've wasted a week, figured I should do some performance tests. I figured sink or swim new GUI. I created 3 identical GUIs. One in LGUI1, one in LGUI2, and one in this newGUI. They had something like 50 checkboxes, 50 labels etc.

I then had the same script monitor the fps while idle, then I started sending information to them every frame (this isn't realistic, but it's a good test). It was doing I think almost 200 changes to the GUI every frame. (a label that goes from 1, to 2, to 3, sliders going up like a progress bar etc). I figured put it under stress and see what happens.

Here's the results (higher numbers are better)

Static:

NewGUI: 45.7

LGUI1: 39.4

LGUI2: 33.2

Under extreme load:

NewGUI: 41.9

LGUI1: 36.7

LGUI2: 26.1

Well, that tells two stories. LGUI2 is bad on performance, is difficult to work with, and is in the garbage.

NewGUI is actually better than LGUI1 in performance, and looks better. How about that.

Okay, cool story, time to move on... ... ...

I started messing around to see what it looked like, and what it was capable of doing. Thought it would be nifty, but honestly, a rewrite of Ogrebot still was not worth it. Too time consuming.

But for a new project... maybe.

So I started a new extension, got things loaded up, but wasn't sure what new project to work on. I thought okay, I'll just re-create something of Ogre. I'll do OgreConsole, keep it simple, doesn't require any external things like isxeq2, it simply displays information.

Did that, was pretty nifty. But it was basically a listbox. I used 1 element. May as well do another window. Was curious how it could handle something like MCP. Being able to drag and resize, how it could handle right clicking with new windows, swapping buttons, frame in frame (static vs changing buttons), etc. This was going to be a good test.

It was.. overall.. pretty simple. It was HTML... webpages. Almost anything you want to do, has 25309235 examples available.

Okay, so the GUI works. How am I going to make it actually usable. I've always known that lavishscript is "slow" overall, and here I am using an extension written in c++ (which is very fast). Well, lets go down that road a little bit, and see if I can figure out how to do more stuff in c++, then start testing performance, to see where this goes. As you can tell, performance is likely the highest priority I have. I want more FPS, and never want to lose any FPS. Could I move any big number crunching, into c++. For example, there's HUNDREDS of checks for Ogrebot to find an ability it wants to cast from the caststack. I start down that road....

Okay, have a mock of that working, but the real test is having an actual cast stack. Well, what if we just made a little mock up of Ogrebot's GUI, then loaded the caststack in, and see how it goes.

Well, in order to have a usable caststack, you need an export, so gotta load that up too.

Here's where it became very obvious to me. Loading the export in lavishscript, you know when you load ogrebot, and it has that bed red message of "Loading..." on top of the GUI, most of that time is loading the export and pulling it apart (finding the highest ability etc). It's something like 2-5 seconds.

I have the export in c++, and did the same thing, had it pull out the highest abilities etc. I load it... it loads. Like.. instantly. Okay, I must have missed something... oh no. It's done.. instantly.

Pretty sure I pivoted, and started running tests. Just simple tests.

In lavishscript, doing ${Me.Name}, ${Me.Health}. Doing it both in lavish and in c++. Ran them a few hundred thousand times, turns out c++ does them 3 to 10 times faster (depending, string vs int etc). Everything, is just insanely faster in c++. Okay, how much can I do solely in c++?

Apparently, I started rewriting Ogrebot, in c++, as kind of a, lets see how this goes. Every time I ran performance tests, with the new GUI, and c++, it absolutely destroyed lavishscript and LGUI1 (that's what Ogrebot is currently in). Apparently I was going down this rabbit hole, that I said was not worth it at all.

I had to take a pause and started thinking. Okay, if I'm doing this, it's going to break *EVERYTHING*. Every single side script out there that touches my GUI. If I'm basically re-doing it in c++, that's going to break OgreBotAPI... breaking everything. I had to decide, am I okay with breaking everything? If I'm going to break things, then I may as well fix things too. For example, I'm sure you've all heard of the famous "ForWho". That decides who listens to the various commands. Almost everything has a forwho... but did you know, 27 things either did not have a forwho, or had it in the wrong spot? But i couldn't change it, because it would break things. GUESS WHAT! I'M ALREADY BREKAING THINGS!

I still have not told anyone except my "friend" that got me into this mess. He was sworn to secrecy, because I knew where he lives. Well.. I know he lives in USA.

At the time of writing this portion of this, I'm still a long ways away from having something for alpha testers. Most of the important subsystems are built. The caststack, campspot, mcp, ogreconsole, osa. 100% within c++, and all with this new fancy html GUI. It's super speedy! And as I have been going along, I have been trying to put together a list of "what do I think works well" and "what needs improved". There are some seriously cool QoL (quality of life) features. I'll document them as I get there, but most of them you will be able to find on your own.

So, what does this mean for the future of Ogre? It's changing with the times. It's getting a complete overhaul. A face lift (new GUI), and complete back end rewrites.

Here's the short "good and bad" about this.

The good:

New, modern GUI that is much easier to use, and more familiar for people.

FPS increase, although I'm not going to hold my breath until I get more and am able to use it in a zone etc.

Everything has it's own TLO and datatypes, and for scripters, this means you can LSTYPE things! (if you're not a scripter, this won't mean anything).

The bad:

Every single script/side script out there, will stop working immediately. While this is really unfortunate, it was the only way to do this project. I'm going to have documents that explain, with examples, of how scripts can be updated to a new format that will work (basically instead of calling the GUI this way, you do it this way).

I will also do my best to help people who have scripts, but got them from people who no longer play, and help you convert them.

People will need to "learn" a new GUI, but I honestly don't think this will be a big deal. It looks modern, but the same. Once you see it, you'll understand.

That's it for now. I would like to say, I have learnt my lesson.. by putting off doing untolds, I ended up with a much, much bigger project on my hands... but I have definitely not learned anything from this...

&lt;fast forward like 2 months&gt;

It's Oct 14th, 2026. I have said I am going to add some testers this week. So.. this is coming out for people to see and test, REAL soon.

Anyone who was paying attention to my clues I was giving, one of them was this, a common phrase I say:

`____ _______`

4 letter word, space, 7 letter word. Only 1 person got it. I think everyone got caught up, on the 4 letter word had to be "ogre", but it wasn't.

It was "full rewrite". One person did guess "ogre rewrite", which was half right, I suppose.

Which then leads to a question of "full rewrite of what?", and the answer to that, is "EVERYTHING".

Now, lets talk about what, everything means. Oh, it means everything. Every, single, thing.

From authentication, to ogrebot, to craft (yes, another rewrite), to mcp, etc etc. When you are rewriting things, you know what that means? UPGRADES! So many things, got upgrades. When in doubt, right click.

I took 20 years of Ogre content, and rewrote all of it. Was it worth it? I guess in the end, that depends on how you all think of it. So far, I am very pleased with it.

# The basics

Every OgreBot window works the same way. This page covers what they all share.

## The title bar

![A title bar](assets/basics/titlebar.png)

| Part | What it does |
|---|---|
| **Title** | The window's name. Drag it to move the window. |
| **?** | Opens a short help box for this window. Its **Full documentation** button opens this guide. |
| **Lock** | Shows when the window is locked. A locked window cannot be moved or resized. |
| **X** | Closes the window. |

Some windows put extra buttons in the title bar too, for example a gear for settings.

## The right-click menu

Right-click a window's title bar for this menu:

![The right-click menu](assets/basics/menu.png)

| Item | What it does |
|---|---|
| **Help** | The same as the **?** button. |
| **Save Position** | Remembers where the window is and how big it is. It opens there next time. |
| **Scale + / Scale -** | Makes this window bigger or smaller. |
| **Scale: use default** | Goes back to the size set in Ogre Options. |
| **Lock / Unlock** | Stops the window from being moved or resized, or allows it again. |
| **Reset** | Puts the window back where it first opened, at its first size. |

## The help box

![The help box](assets/basics/help.png)

The help box sits next to the window it explains. You can move it and close it like any other window.

## Resizing

Drag the right edge, the bottom edge, or the bottom-right corner of a window to resize it.

# What's new

What changed in OgreBot, release by release, newest first. Every release listed here was published to the patcher.

A release is named by the day it was published and its number that day: **2026.10.16.005** is the fifth release on October 16, 2026. Releases with nothing you would notice are not listed, so the numbers can skip.

Dates and times are US Eastern time (EST in winter, EDT in summer).

## 2026.10.18.005 {#r2026-10-18-005}

*Sunday, October 18, 2026 at 11:44 PM EDT*

- **Fixed** · Bot: **Position-on-NPC buttons use your NPC target.** `-SetCS_PositionNPC`, `-SetCS_BehindNPC`, `-SetCS_InFrontNPC` and `-SetCS_NPC` did nothing when no NPC was given. Now a blank NPC means your NPC target: your target if it is an NPC you can fight, otherwise your target's target. OgreMCP buttons migrated from OgreBot Classic that used `${u_NPCTargetID}` now use `${ISXOgreEQ2.NPCTarget.ID}`, the new bot's name for it.

## 2026.10.18.004 {#r2026-10-18-004}

*Sunday, October 18, 2026 at 10:50 PM EDT*

- **New** · Bot: **Instance Controller can summon your mercenary when you are solo.** A new Instance Controller option, "Summon merc if solo" (on by default), summons your mercenary once you are inside the zone with nobody else in your group. On a zone-in it happens as you land, so the mercenary also gets the rebuff time before the zone starts.
- **Fixed** · Bot: **A mercenary no longer holds up the next zone.** Playing solo with a mercenary, the Instance Controller waited the full two minutes after every zone-out for the mercenary to arrive, because it waited for every group member to report in. A mercenary travels with you and is no longer waited for, so the list moves on to the next zone right away. Teleporters and the after-fight res check now skip it too.
- **Fixed** · Bot: **Switching characters keeps OgreBot running.** `ogre login <character>` pauses OgreBot while the old character camps out, and the new character's OgreBot used to come up paused because of that. Now it comes up running if the old one was running, and paused if it was paused.

## 2026.10.18.003 {#r2026-10-18-003}

*Sunday, October 18, 2026 at 8:59 PM EDT*

- **New** · Bot: **Edit an alias by clicking it.** On the OgreBot Aliases tab, click an alias to load it into the form, change its name, who it is for or No-Raid, and press Save Alias. Double-click still turns an alias on or off.
- **New** · Bot: **Option to skip repairing at Mender bots.** When a Mender bot is put down near you, the bot repairs your gear at it. To turn that off, tick "Do not auto-repair with Mender bots" in the Pop up windows options on the Settings tab. A Mender bot the Instance Controller summons to sell to is still used for selling; it just does not repair first.
- **New** · Bot: **Sort the Instance Controller's zones by name.** The Instance Controller's Zones list has a Sort button beside its heading. Click it to switch between "Sort: #" (by number, as before) and "Sort: A-Z" (by zone name). The choice is remembered, and Add all queues the zones in the order shown.
- **New** · Windows: **Add items from the examine window.** The Inventory Manager Restock and Trade tabs, and the Auto-Loot item names list in OgreBot, have a From examine button. Examine an item in game, press it, and the item name is filled in for you, so there is nothing to mistype.
- **Changed** · Bot: **Saving a profile says where it was saved.** When you save an OgreBot profile, the console now shows the full location of every file it wrote, so you can find it.
- **Fixed** · Bot: **Switching characters keeps OgreBot small.** When you log a different character in on a session where OgreBot is open, OgreBot reloads for the new character with only its small window showing, the same as when it first loads. Use Show Main to open the full window.
- **Fixed** · Windows: **Numpad Enter leaves a text box too.** Pressing Enter on the number pad in an Ogre text box now does what the main Enter key does: it enters the value and lets go of the box.
- **Fixed** · Windows: **The cast stack list keeps its place.** The cast stack lists no longer jump back to the top when OgreBot refreshes them, for example when travel starts, your group changes, or you open the Target list. Only switching to the Cast Stack tab starts at the top.

## 2026.10.18.002 {#r2026-10-18-002}

*Sunday, October 18, 2026 at 7:06 PM EDT*

- **New** · Windows: **The small OgreBot window shows your class and what the bot is doing.** The small OgreBot window now has a line with your class, and a line saying what the bot is doing: paused, the ability or item it is using, who it is following, or that its camp spot is active. The cog in its title bar lets you choose what it shows. Hovering the yellow star now says it means unsaved changes.
- **Changed** · Windows: **A window's value reads back at once after your script changes it.** After ISXOgreX.UI:Set changes an element in your own window, ISXOgreX.UI.Value now reads the new value straight away, even inside an event handler. Before, the read returned the old value until the next frame and a script had to waitframe first.
- **Fixed** · Bot: **A cast that is out of range or out of sight gives up at once.** When the game says your target is too far away or out of sight, or the spell fizzles or is interrupted, the cast stack now moves on straight away instead of waiting 3 seconds. Auto-attack range messages are not mistaken for it.
- **Fixed** · Bot: **Cures set to yourself no longer spam.** A cure in the cast stack aimed at yourself (@Me) kept starting and cancelling over and over when you had nothing it could cure. It now casts only when you actually have a detriment that cure removes, as OgreBot Classic did.
- **Fixed** · Bot: **Trades from your own characters are accepted automatically.** When one of the characters on your EQ2Chars list accepts a trade with you, the bot now accepts it too, as OgreBot Classic did. Trades with anyone else are never accepted. To turn it off, tick "Do not auto accept trades from trusted toons" in the Pop up windows options.
- **Fixed** · Windows: **Enter leaves a text box again.** Pressing Enter in a one-line text box in any Ogre window gives the keyboard back to the game, like a second Escape. On some PCs Enter did nothing and the box kept the keyboard. Restart the game after patching to get the fix.
- **Fixed** · Windows: **Holding a key repeats in Ogre text boxes.** Holding an arrow key, Backspace, Delete or a letter in an Ogre text box now repeats it like any other Windows text box, at your Windows keyboard repeat speed. Hold Shift with an arrow to keep selecting text.
- **Fixed** · Windows: **Migrated raw-command and Inviter buttons work again.** Raw-command buttons brought over from OgreBot Classic were wrapped in quotes and did nothing, and Inviter buttons invited nobody. Both are fixed: new imports come out right, and buttons already imported are fixed once, automatically, with a backup of your button file kept next to it.
- **Fixed** · Windows: **The Restock profile picker can be clicked.** In the Inventory Manager, the Profile box on the Restock tab could not be opened, so you could only ever see the first profile. It is now a normal Ogre dropdown. The number boxes in the Inventory Manager and Auto-Login no longer empty themselves when a letter is typed.
- **Fixed** · Console: **A restarted bot no longer reads as frozen for minutes.** After the bot was reloaded inside a running game, the session watch kept calling that session frozen for several minutes before saying it had recovered. It now sees the reloaded bot straight away.

## 2026.10.18.001 {#r2026-10-18-001}

*Sunday, October 18, 2026 at 2:01 PM EDT*

- **New** · Windows: **Your scripts can open their own windows.** A script or extension can now put its own window on Ogre's in-game UI, made from one HTML file: ISXOgreX.UI:Open shows it, ISXOgreX.UI.Value reads its checkboxes and text, ISXOgreX.UI:Set changes them, and the OgreUI_Opened and OgreUI_Closed events say when windows open and close. Two examples ship in Ogre/Common/OgreUI/examples, and the new Build your own window page explains it.

## 2026.10.17.017 {#r2026-10-17-017}

*Saturday, October 17, 2026 at 1:21 AM EDT*

- **New** · Other: **Script messages can play a sound and go to a console tab.** OgreBotAPI.Comms:Message and :Broadcast take "-sound","ding" or "-sound","alarm" after the text and play it, and "-tab" followed by a tab name also shows the line in that OgreConsole tab. Fight announcements that ask for a sound now play it instead of only printing it. The chest-drop ding is unchanged.
- **Fixed** · Navigation: **Flying takes off and lands under overhangs and tree canopies.** Flight now knows about the open air under ledges, overhangs and tree canopies, so a trip can take off from a covered spot like the landing pad below the Ulteran Spire in Moors of Ykesha, and more trips fly instead of walking. Planning a long flight no longer causes a small hitch.

## 2026.10.16.024 {#r2026-10-16-024}

*Friday, October 16, 2026 at 5:00 PM EDT*

- **New** · Windows: **Full documentation opens the window's own page on the new docs site.** The Full documentation button in every window's help (the ? in its title bar) now opens that window's own page on the new OgreBot documentation site, which explains every window and option. Script writers will find a guide and a converter for moving OgreBot Classic scripts under Developers.
- **New** · Windows: **New Commands panel opens with `ogre ?`** `ogre ?`, `ogre help` and `ogre commands` now open a window listing every `ogre` command you can use, searchable by name, other names or any word in the description. Run does exactly what typing `ogre <command>` does, End does what `ogre end <command>` does, and commands that take something after their name have a box for it. Commands not yet in the new bot are shown greyed out, so you can see what is still to come.
- **New** · Instance Controller: **Instance Controller runs all 12 Rage of Cthurath heroic and solo zones.** The Instance Controller zone files and fight files for all 12 Rage of Cthurath [Heroic] and [Solo] zones are now in the default folder: Ver'Bohten Atoll, Coral Roost, The Chimeric Chain, The Graftwerk, Dominion of Pain, Ark of Ascension, Sacrificial Pursuits, Edge of Oblivion, Realm of Conquest, The Oculeum, Zruul's Dominion and The Obliviwrought Conclusion. Before release, a group of six completed all 12 zones in both versions, with 60 of 60 nameds killed each time.
- **New** · Instance Controller: **Instance files can ask the whole group a question.** Instance files can now ask the whole group a question, such as "does everyone have a repair bot?" or "is anyone level 130 yet?", and act on the answers as yes/no results, counts, and lists of who said yes and who said no. Scripts can ask the same questions and get the answer back as an event or by checking when it is done. A misspelt answer in an instance file is now caught when the file loads, instead of silently doing nothing.
- **New** · Crafting: **Scripts can see what crafting is doing.** Scripts can now see whether crafting is busy, which stage it is at, how far along it is (3 of 10), and whether the last queue was short on resources. Every kind of crafting run now announces when it ends, including auto tinkering and low level leveling. Scripts can also read the recipe you scribed most recently.
- **New** · Console: **New `ogre version` shows which release you are on.** `ogre version` prints the OgreBot release you are on, by the same name this page uses, and when the core was built. The bottom of the Commands panel and of every window's help shows the release name too.
- **New** · Other: **New Coming from Classic guides for your own scripts.** New "Coming from Classic" pages help you move your own OgreBot Classic scripts to the new bot, starting with camp spots and console commands. Each page lists what every old call does today and what to write instead, with real before and after lines, because an old name does not give an error in the new bot, it silently does nothing. A conversion tool looks up any old name, makes the safe rewrites for you, and checks a converted script for anything left over.
- **New** · Other: **Session watch tells you when a session freezes or disappears.** Tick the new Session watch box on the EverQuest 2 tab of `ogre config` (off by default) and the uplink says in every OGRE console when a session goes silent for 30 seconds, comes back, or disappears, and fires an event your uplink scripts can act on. `ogre sessions` lists every session the uplink hears and when it was last heard; `ogre sessions on|off` turns the watch on or off until the uplink restarts. The uplink only announces; what to do about it is up to your script.
- **Changed** · Bot: **Heroic Surge is turned off for fights that run heroic opportunities.** Any fight that sets up heroic opportunities now turns Heroic Surge off for that fight and puts it back afterwards. Before, Heroic Surge could start heroic opportunities on characters the fight had told not to.
- **Changed** · Instance Controller: **Instance Controller panel shows zone file numbers.** The Instance Controller panel now shows each zone file's number, and ticked boxes show green.
- **Changed** · Instance Controller: **Starting a zone part-way only begins where the group is standing.** In zones with teleporters inside them, a run you start part-way (for example "start at named 3", or a resume) now begins only where the group is standing: at the start of a walk, at a named, or where the step before would have left it. Anywhere else the Instance Controller refuses to start, says why, and nobody moves. This stops the group walking across ground the zone's teleporter is there to skip, such as the lava in The Graftwerk.
- **Changed** · Other: **Classic OgrePing scripts can move to session watch.** The conversion tool now rewrites Classic OgrePing lines for you: starting it, checking it is running, and its timeout event. There is also a worked example of a pack-pony "restart a frozen session" script converted to the new events.
- **Changed** · Other: **Coming from Classic guides now cover every Classic name.** The "Coming from Classic" pages now cover every Classic call, object, console command and option your scripts or buttons may use, including OgreBotAPI, camp spots, the ask system, events, crafting and instance files, and they honestly list what is not in the new bot yet. The conversion tool can now convert a script in place (keeping a copy of the original), checks MCP button files button by button, and lists the lines you should look at by hand. It does not convert instance files yet.
- **Fixed** · Bot: **Camp spot buttons with an empty coordinate no longer move you.** A camp spot button whose coordinate comes back empty no longer moves your camp spot to a random spot; it now does nothing, as Classic did. Giving `x,y,z` as one value works again.
- **Fixed** · Bot: **Detrimental checks look further down a mob's effect list.** The bot now checks the first 10 effects on a mob instead of 7, so a mechanic further down a busy raid mob's list is no longer missed.
- **Fixed** · Bot: **Fight mechanics are more reliable.** A fight step that looks for something that is not there (a cloud, a totem, an add) now just skips instead of failing the whole mechanic, and a fight no longer ends early when the named briefly has no target. Spells a fight queues, like a dispel, now go before your normal rotation's next spell instead of being skipped.
