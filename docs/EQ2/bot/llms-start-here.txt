# OgreBot - User Guide

This guide explains every window of the new OgreBot: what each one is for, and what every option on it does.

Every page starts with a picture of the window, then goes through it one area at a time. The area being
described is outlined in **pink** in its picture.

> **:memo: Examples use made-up names**
>
> Every name in these pictures - Kannkor, Brutus, Mirelle, Tobbin - is made up. Nothing here shows a real
> character, account, guild or server.

## Where to start

- New to the bot? Read [The basics](basics.md) first. It covers the window buttons every window shares.
- Setting up a character: [OgreBot](ogrebot/index.md), then its [Settings](ogrebot/settings.md) and
  [Cast Stack](ogrebot/cast-stack.md) tabs.
- Running zones: the [Instance Controller](windows/ic.md).
- Sharing out loot: [SmartLoot](windows/smartloot.md).

## Help inside the game

Every window has a **?** in its title bar. Click it for a short explanation of that window. The
**Full documentation** button in that box opens this guide.

# The super secret project

Where to even start! I guess a super brief history of how OgreBot became to be. I'd guess the basics of my story was the same as most people's here. A friend wanted me to play eq2 with them (they wanted me to make a bot, as I had done so for eq1). I said sure, but I was ONLY playing 1 toon. Pretty sure I made a troubadour. I was coding at low levels but it was hard back then. It logically only made sense, to have a second account for a priest. It's only 2 accounts, that's basically just 1 account.

Then I was killing slow... so may as well add some dps to the group... 3 accounts is barely more than the 2 I already have. It's only 1 more. Yes, you can absolutely hear the "justification" to myself about how this is all fine. The friend who got me into eq2, I'm pretty sure at this stage, is absolutely laughing his ass off, because he new this would happen, and he knew exactly what was coming next.

Well, if I'm already at 3, then I may as well just have my own group. Then there were 6.

Okay, fast forward almost 20 years or something now. Lax/Innerspace comes out with LGUI2 (it's what OgreCraft2's UI is done in). It provided a TON more options for dealing with GUIs, but LGUI2 isn't very friendly. I find it way over complicated, it was very new, so minimal documentation or examples. I made it work, but still didn't like it.

Then others, decided to bring in external GUIs. I thought this was an interesting idea, but the problem is, EVERYTHING is tied to my current GUI, that changing would be an absolute nightmare. It would basically be a rewrite of Ogrebot... and for what? To change the GUI?

Then a friend (don't tell him I called him that) and I were talking and joking... How long would it take, to rewrite Ogrebot from scratch, and make it work with a new GUI. With basically full parity (meaning, no loss of features). Our estimate was over a year. That assumes I focus the majority of my time there. That was absolutely not going to be worth it. Full stop, no thanks.

I didn't want to code untolds above tier 20, because Dominion of Pain sucks, so I was looking for a way to distract myself. I thought I'd look into these alternate GUIs to run some performance bench marks. If a new fancy GUI would be a net loss in performance, that's not worth it, at all. FPS (frames per second, not first person shooter) is way more important than having a fancy dancy GUI.

Did a bunch of research, and choose one. It is built using HTML (basically a webpage). This is fantastic, because HTML is likely the most common language ever (I didn't actually check to see if that's true, but almost every single website uses html). That means there's infinite amount of examples, and support etc etc.

I figured, okay, lets load this up, see how it works, do some performance tests, then go from there.

A WEEK LATER, I finally get it working. Like... me working on it every spare moment I have for an entire week. I was ready to bash my head into a wall.

Now that I've wasted a week, figured I should do some performance tests. I figured sink or swim new GUI. I created 3 identical GUIs. One in LGUI1, one in LGUI2, and one in this newGUI. They had something like 50 checkboxes, 50 labels etc.

I then had the same script monitor the fps while idle, then I started sending information to them every frame (this isn't realistic, but it's a good test). It was doing I think almost 200 changes to the GUI every frame. (a label that goes from 1, to 2, to 3, sliders going up like a progress bar etc). I figured put it under stress and see what happens.

Here's the results (higher numbers are better)

Static:

NewGUI: 45.7

LGUI1: 39.4

LGUI2: 33.2

Under extreme load:

NewGUI: 41.9

LGUI1: 36.7

LGUI2: 26.1

Well, that tells two stories. LGUI2 is bad on performance, is difficult to work with, and is in the garbage.

NewGUI is actually better than LGUI1 in performance, and looks better. How about that.

Okay, cool story, time to move on... ... ...

I started messing around to see what it looked like, and what it was capable of doing. Thought it would be nifty, but honestly, a rewrite of Ogrebot still was not worth it. Too time consuming.

But for a new project... maybe.

So I started a new extension, got things loaded up, but wasn't sure what new project to work on. I thought okay, I'll just re-create something of Ogre. I'll do OgreConsole, keep it simple, doesn't require any external things like isxeq2, it simply displays information.

Did that, was pretty nifty. But it was basically a listbox. I used 1 element. May as well do another window. Was curious how it could handle something like MCP. Being able to drag and resize, how it could handle right clicking with new windows, swapping buttons, frame in frame (static vs changing buttons), etc. This was going to be a good test.

It was.. overall.. pretty simple. It was HTML... webpages. Almost anything you want to do, has 25309235 examples available.

Okay, so the GUI works. How am I going to make it actually usable. I've always known that lavishscript is "slow" overall, and here I am using an extension written in c++ (which is very fast). Well, lets go down that road a little bit, and see if I can figure out how to do more stuff in c++, then start testing performance, to see where this goes. As you can tell, performance is likely the highest priority I have. I want more FPS, and never want to lose any FPS. Could I move any big number crunching, into c++. For example, there's HUNDREDS of checks for Ogrebot to find an ability it wants to cast from the caststack. I start down that road....

Okay, have a mock of that working, but the real test is having an actual cast stack. Well, what if we just made a little mock up of Ogrebot's GUI, then loaded the caststack in, and see how it goes.

Well, in order to have a usable caststack, you need an export, so gotta load that up too.

Here's where it became very obvious to me. Loading the export in lavishscript, you know when you load ogrebot, and it has that bed red message of "Loading..." on top of the GUI, most of that time is loading the export and pulling it apart (finding the highest ability etc). It's something like 2-5 seconds.

I have the export in c++, and did the same thing, had it pull out the highest abilities etc. I load it... it loads. Like.. instantly. Okay, I must have missed something... oh no. It's done.. instantly.

Pretty sure I pivoted, and started running tests. Just simple tests.

In lavishscript, doing ${Me.Name}, ${Me.Health}. Doing it both in lavish and in c++. Ran them a few hundred thousand times, turns out c++ does them 3 to 10 times faster (depending, string vs int etc). Everything, is just insanely faster in c++. Okay, how much can I do solely in c++?

Apparently, I started rewriting Ogrebot, in c++, as kind of a, lets see how this goes. Every time I ran performance tests, with the new GUI, and c++, it absolutely destroyed lavishscript and LGUI1 (that's what Ogrebot is currently in). Apparently I was going down this rabbit hole, that I said was not worth it at all.

I had to take a pause and started thinking. Okay, if I'm doing this, it's going to break *EVERYTHING*. Every single side script out there that touches my GUI. I'M ALREADY BREKAING THINGS!

So, what does this mean for the future of Ogre? It's changing with the times. It's getting a complete overhaul. A face lift (new GUI), and complete back end rewrites.

Here's the short "good and bad" about this.

People will need to "learn" a new GUI, but I honestly don't think this will be a big deal. It looks modern, but the same. Once you see it, you'll understand.

That's it for now. I would like to say, I have learnt my lesson.. by putting off doing untolds, I ended up with a much, much bigger project on my hands... but I have definitely not learned anything from this...

&lt;fast forward like 2 months&gt;

It's Oct 14th, 2026. I have said I am going to add some testers this week. So.. this is coming out for people to see and test, REAL soon.

Anyone who was paying attention to my clues I was giving, one of them was this, a common phrase I say:

Which then leads to a question of "full rewrite of what?", and the answer to that, is "EVERYTHING".

Now, lets talk about what, everything means. Oh, it means everything. Every, single, thing.

From authentication, to ogrebot, to craft (yes, another rewrite), to mcp, etc etc. When you are rewriting things, you know what that means? UPGRADES! So many things, got upgrades. When in doubt, right click.

I took 20 years of Ogre content, and rewrote all of it. Was it worth it? I guess in the end, that depends on how you all think of it. So far, I am very pleased with it.

# The basics

Every OgreBot window works the same way. This page covers what they all share.

## The title bar

![A title bar](assets/basics/titlebar.png)

| Part | What it does |
|---|---|
| **Title** | The window's name. Drag it to move the window. |
| **?** | Opens a short help box for this window. Its **Full documentation** button opens this guide. |
| **Lock** | Click it to lock the window, and again to unlock it. A locked window cannot be moved or resized, and the padlock is lit while it is locked. Locking remembers the window's place, so it opens there, still locked, next time. |
| **X** | Closes the window. |

Some windows put extra buttons in the title bar too, for example a gear for settings.

## The right-click menu

Right-click a window's title bar for this menu:

![The right-click menu](assets/basics/menu.png)

| Item | What it does |
|---|---|
| **Help** | The same as the **?** button. |
| **Save Position** | Remembers where the window is and how big it is. It opens there next time. |
| **Scale + / Scale -** | Makes this window bigger or smaller. |
| **Scale: use default** | Goes back to the size set in Ogre Options. |
| **Lock / Unlock** | Stops the window from being moved or resized, or allows it again. Like the padlock, it is remembered for next time. |
| **Pin to back / Unpin from back** | A pinned window always stays behind every window that is not pinned, even when you click it. Remembered for next time. |
| **When Console is open** | A sub-menu: what this window does when the InnerSpace console opens over it - **Use default**, **Slide below**, **Hide** or **Leave in place**. **Use default** follows the choice in Ogre Options (named in brackets); the other three are this window's own, whatever Ogre Options says. The ticked one is in force. Remembered for next time. |
| **Reset** | Puts the window back where it first opened, at its first size, turns off Lock and Pin to back, and sets Console back to use default. |

## The help box

![The help box](assets/basics/help.png)

The help box sits next to the window it explains. You can move it and close it like any other window.

## Resizing

Drag the right edge, the bottom edge, or the bottom-right corner of a window to resize it.

# What's new

What changed in OgreBot, release by release, newest first. Every release listed here was published to the patcher.

A release is named by the day it was published and its number that day: **2026.10.16.005** is the fifth release on October 16, 2026. Releases with nothing you would notice are not listed, so the numbers can skip.

Dates and times are US Eastern time (EST in winter, EDT in summer).

## 2026.10.25.002 {#r2026-10-25-002}

*Sunday, October 25, 2026 at 6:57 PM EDT*

- **New** · Bot: **OgreFollow - a back-off distance.** OgreFollow takes a back-off distance after the break flag, e.g. `-ofol all Leader 3 200 FALSE 1`: closer than it for a second, you face who you follow and back up to halfway to the min distance (0, the default, is off). The max distance now defaults to 200 everywhere, movement always uses your Ogre Key Binds, and a move that gets nowhere for 30 seconds now stops.
- **Fixed** · Bot: **Auto Target when Hated waits while you assist.** Auto Target when Hated no longer picks a target for a character that is assisting someone (Auto Assist on, with someone to assist), so raid characters stop grabbing an aggro mob on their own. With no one to assist, it still takes a mob attacking your group when you have no target, or only something you can't fight such as a corpse, chest, shiny or NoKill NPC.
- **Fixed** · Instance Controller: **The Instance Controller lists zone files that are not valid, and why.** A zone file that cannot load now still shows in the Instance Controller's zone list, in red and marked "not valid", instead of the list saying the folder is empty. Click it and the bar under the list gives every reason, such as a file with no zoneOut step; it cannot be queued or run until it is fixed. A zone with no exit of its own can end with `{ "do": "zoneOut", "op": "none" }` and use Call to GH after each zone.

## 2026.10.25.001 {#r2026-10-25-001}

*Sunday, October 25, 2026 at 1:44 PM EDT*

- **Fixed** · Bot: **Cast Stack tags - items and Maintained.** Item and adornment entries on the Cast Stack now have the tag fields, so you can rotate an adornment such as Pack Mentality across your healers again, and the Embargo and Allow tag boxes are dropdowns of the tags on your Tags tab. A tag with Maintained ticked now stays on while the buff is up, at any rank; before, it switched off about a second after the cast. For an item, Maintained follows the buff the item puts on you.
- **Fixed** · Bot: **Coercer tab - Possess Essence lands on the preferred archetype.** The Coercer tab's Possess Essence now targets the group member of your preferred archetype (or you) before it casts, as OgreBot Classic did. It used to take the essence from whatever you had targeted, so the pet came up the wrong kind, was dismissed, and was cast again in a loop.

## 2026.10.24.004 {#r2026-10-24-004}

*Saturday, October 24, 2026 at 6:18 PM EDT*

- **New** · Other: **Scripts get a timer - ogretimer.** Scripts can declare a countdown: `variable ogretimer Timer_X` (stopped) or `variable ogretimer Timer_X = 1500` (running, ms), then `Timer_X:SetSeconds[20]` and read `${Timer_X.TimeLeft}` (ms left), `.SecondsLeft` and `.Running`. It has OgreBot Classic's Object_Timer methods and members (Set, SetSeconds, SetMinutes, SetHours, SetMinimum, Inc, Dec, Stop), so converting means changing only the `variable` line. A value that is not a number is refused and says so.

## 2026.10.24.002 {#r2026-10-24-002}

*Saturday, October 24, 2026 at 4:43 PM EDT*

- **New** · Setup: **Auto-login can launch an ISBoxer character set.** An auto-login profile can now name an ISBoxer character set (the list shows this PC's sets). Start launches that set through ISBoxer first, then logs your characters into the sessions it opened, and only launches a session that is still missing. Sessions opened under a game profile that does not load the new bot get it loaded before the login.
- **Fixed** · Bot: **"Not enough concentration" rebuffs again.** When the game says "Not enough concentration", the bot again cancels your concentration buffs, so the cast stack can recast them into the slots you have. It tells the group "Max Concentration! Removing buffs and rebuffing." It does nothing if you have turned off the cast stack's buffs.
- **Fixed** · Windows: **Old unpack MCP buttons work again.** MCP buttons that still used -Unpack_Quantity, a reward choice straight after the item, or the Empyral / Planar stone unpack rows stopped working when unpacking became one -Unpack command. They are now rewritten once to that command with -qty, -pick or -all, for example `-Unpack auto "Zon Zobboz Heritage Crate" -qty 20`. Your old MCP file is kept beside it as OgreMCP.json.unpackfix.bak.
- **Fixed** · Windows: **The Auto-Login window resizes properly.** Making the Auto-Login window taller now makes the log at the bottom bigger too, and making it smaller again no longer lets you scroll the whole window so the log disappears. The column headers line up with the boxes under them, the number boxes keep one size, and Dry run and Start stay together when the window gets narrow.
- **Fixed** · Crafting: **Exporting a few abilities is fast.** An ability export that names only some abilities ("Just these abilities", or the export crafting runs when a reaction bar shows an art it does not know) now looks at just those abilities. It used to read and examine every tradeskill ability in your book first, which could take well over a minute; a crafting round's few new arts now take seconds.
- **Fixed** · Crafting: **Far Seas Crafting Station reactions are used.** Crafting at the Far Seas Crafting Station now answers its own reactions (Hold It, Pop Knuckles, Grounded, Concentrate Hard, Awaken and Extinguish). These six arts now ship with the bot in a new file, ReactionArtsSpecial.json, which is applied after the bot's own ability export, so an export can no longer lose or re-file them. Your own custom ReactionArts.json still overrides it.
- **Fixed** · Crafting: **Quest crafting understands more step wordings.** Quest crafting now finds the recipe for steps such as "Cook the seasoned fish on the fire" (Svarni Seasoned Fish), "Craft a Child's Pillow for Alghoza", "Craft the scrolls of Enhanced Undead Control" (one Scroll of...) and "Craft some paper" (Sheaf of Paper - when several recipes fit, the one you scribed most recently is used). It crafts one, then checks the quest moved before making more.
- **Fixed** · Console: **"ogre <name> -ph" loads the bot paused.** `ogre <name> -p` and `ogre <name> -ph` (and `ogre bot <name> -ph`) now log the character in and load the bot paused, with -ph also hiding the main window. The flag after the name used to be ignored, so the bot loaded running. A word after the name that is not -p or -ph is now refused with a message instead of being ignored.
- **Fixed** · Console: **The uplink console window opens again.** The OgreConsole window in the InnerSpace uplink could fail with "Script file 'OgreConsole/uplink/OgreConsoleUplink' not found", because its script was never shipped with the new bot. It now ships under Scripts\Ogre\Common\OgreConsole, so the window opens when the console hub loads.
- **Fixed** · Setup: **Auto-login sees sessions you opened yourself.** Auto-login now finds the EverQuest II sessions already open on that PC, including ones launched by ISBoxer or by hand, and logs into them instead of opening new ones. It used to see only sessions it had launched itself, so with ISBoxer it opened a full new set of sessions.
- **Fixed** · Setup: **Auto-login Start from the panel finds your profile again.** Pressing Start (or Dry run) in the in-game auto-login window failed with "No profile named" for every profile, because the name reached the uplink with quote marks around it. The name now arrives as you typed it, including names with spaces. Desktop shortcuts were not affected.
- **Fixed** · Setup: **The ISXOgreX InnerSpace profile is added whatever you named the game.** The migration now adds the "Everquest 2 ISXOgreX" InnerSpace profile under every InnerSpace game that runs EverQuest2.exe, whatever the game is called. It used to look only for a game named Everquest 2 or EverQuest II, so a game you made yourself (such as "EQ2") was skipped. If yours was skipped, load the new bot again and it is added.

## 2026.10.24.001 {#r2026-10-24-001}

*Saturday, October 24, 2026 at 12:46 AM EDT*

- **New** · Bot: **TaskRunner can run your destroy list after the harvest depot.** TaskRunner Lists has a new chore option, **Destroy list after depot**. With it and **Harvest depot after** both on, a Pack Pony run deposits its harvests, then destroys the items on your Ogre IM destroy list (ogre im -destroy -end) to clear out the excess. It only runs when the depot finished.
- **New** · Windows: **ogre ui report copies a report of your windows to paste.** If something looks wrong on screen (a stray box, a window you cannot find), type `ogre ui report` in the console: it copies a report of every Ogre window, and of anything drawn outside them, to the clipboard. Paste it to whoever is helping you, so they can see what was on screen without asking you to reproduce it.
- **New** · Windows: **Pin a window to the back, and choose what it does when the console opens.** Right-click any Ogre window's title bar for two new settings, both remembered: **Pin to back** keeps it behind every window that is not pinned, and **When Console is open** picks what it does when the InnerSpace console opens over it (slide below, hide, leave in place, or use the default). The default is Ogre Options' "When the InnerSpace console covers a window", now a list with a third choice, **Leave it where it is**; if you had chosen to hide windows before, pick it again in that list.
- **New** · Other: **The script converter follows your #include files.** ogre_convert.py now follows a script's own #include files, so a script split over several files is checked and converted in one run. It follows them on a dry run and on sweep, coverage and sites; add --follow-includes to convert them in place or into a folder. Classic's own files are never followed.
- **Changed** · Windows: **Clicking the game takes your typing out of an Ogre box.** When you are typing in an Ogre box (the OgreConsole, a search box, a setting) and click on the game outside every Ogre window, the box lets go of the keyboard, so your keys go to the game again. Before, it kept the keyboard until you pressed Escape or Enter.
- **Fixed** · Bot: **Balanced Synergy is cast by the group, in combat only.** Balanced Synergy no longer spams out of combat. A character with it in the cast stack as Custom asks the whole group to cast it 10 seconds later, only while fighting a target within its % to attack. Ignore Balanced Synergy now works, and a character running a solo HO for a fight does not join in.
- **Fixed** · Bot: **Consume Status Ingots uses them all.** Consume Status Ingots no longer stops after a few. An item it cannot use, such as a tradeskill ingot, is skipped after two tries and it goes on to the next one, as the old bot did. Before, the first such item ended the whole run.
- **Fixed** · Bot: **Hail works with Assist on.** With Assist on, -Hail no longer hails the character you assist instead of the NPC: the target now stays on the NPC until the hail is done. The same goes for anything else that has to target something for a moment, such as getting or using a flag and repairing gear. If the NPC is still not targeted after a second, the hail is skipped rather than hailing something else.
- **Fixed** · Bot: **No Offensive and No Defensive go by the ability.** No Offensive now holds back every hostile ability in the cast stack, and No Defensive every beneficial one, whatever type the entry is, Custom included. Before, they went by the entry's type, so a Custom entry was never held back by either.
- **Fixed** · Bot: **ogre ae says plainly when it could not write its report.** When `ogre ae` cannot save its report, it now says the report was NOT written and why (for example, Windows refused to create the folder). Before, the failure line ended in the file's path just like the success line, so it read as "here is your file" when there was no file.
- **Fixed** · Bot: **Possess Essence pet swap and Channeler dissonance fixed.** The Coercer tab now dismisses a pet of the wrong essence so Possess Essence can go on your preferred archetype, but only once Possess Essence is off cooldown and never against your combat or instance settings. Construct's Sacrifice is no longer recast while it is already on you. Channelers no longer try abilities they lack the dissonance for.
- **Fixed** · Bot: **Spew relay group reports the group in use.** OgreBotAPI.Comms:SpewRelayGroup now reports the relay group each character really sends to, including a group set in the Relay Groups tab, instead of always saying ogre_everquest2.
- **Fixed** · Bot: **The ability research check makes sure the Knowledge book closes.** After checking ability research, the bot now makes sure the Knowledge book has closed, and closes it again if it comes back. It also closes the book when a check ends early. If the book still will not close, a warning in the log says so.
- **Fixed** · Bot: **The relay group setting now moves OgreConsole lines too.** "Send this bot's fleet commands to another group" now also sends OgreConsole lines (such as oc !c -Jump) to that group, so two fleets can be kept apart. Typing a name into its box no longer joins a group for each letter typed: it only sets where this character sends. For a character to hear a group, add it to "Also join these groups".
- **Fixed** · Windows: **Ogre windows stay when the game's screen size changes.** Changing the game's resolution or window size (loading a UI options file with `/load_custom_options_file`, for example) no longer makes every Ogre window disappear, including the HUDs, which then stayed gone even after reloading OgreBot. The windows now stay where they are, a window the smaller screen left off-screen is moved back onto it, and each one gets its own size back on a larger screen.
- **Fixed** · Windows: **The MCP button builder shows which who is chosen.** In Build command, the who list (who ▾) now highlights the choice the field already holds, the way the For Who window does - Auto when the field is auto or blank. Lists for other settings highlight their current value too.
- **Fixed** · Windows: **The OgreBot mini window stays small.** The OgreBot mini window keeps its own small size again, so it no longer grows over the windows beside it. Its cog makes it bigger only while you choose what it shows, so the Done button is never cut off, and it goes back on Done. It also no longer shows the unsaved-changes star; the main OgreBot window still does.
