What changed in OgreBot, release by release, newest first. Every release listed here was published to the patcher.

A release is named by the day it was published and its number that day: **2026.10.16.005** is the fifth release on October 16, 2026. Releases with nothing you would notice are not listed, so the numbers can skip.

Dates and times are US Eastern time (EST in winter, EDT in summer).

## 2026.10.29.003 {#r2026-10-29-003}

*Thursday, October 29, 2026 at 8:41 PM EDT*

- **Changed** · Windows: **"ogre craft minimize, and ogre export brings back the window an export hid".** `ogre craft minimize` (and `ISXOgreEQ2.Craft:Minimize`) rolls the craft window up to its run controls while crafting keeps going, and `ogre craft` brings it back. Typing `ogre export` while an export runs now shows its window again without stopping the export. `ogre export close` is gone: let it run, or end it with `ogre end export` or the window's X.
- **Changed** · Console: **"Removed: ogre ic close, ogre craftingmats close and the Nav window's Close button".** A window that hid itself while its work kept running is no longer an option: you let it run, or you end it with `ogre end <command>` or the window's X. `ogre ic close` and `ogre craftingmats close` are now unknown words, and the Nav window has no Close button - move or resize it instead; its STOP button and X work as before.
- **Fixed** · Bot: **Characters rejoin the bot's relay group after ISBoxer clears it.** When ISBoxer loads a character set it takes every session out of all its relay groups, which left the bot's group commands unable to reach those characters. Each session now joins the bot's relay group again the moment that happens, along with any groups in your Relay Groups auto-join list, as the old bot did.
- **Fixed** · Console: **"ogre end" and the X now fully close eleven more commands.** `ogre end` and the window's X now stop what the command is doing and close its window for Analysis, Effect Tracker, Level Transmuting, Safe Fall, NPC Cast, Zone Reset, Travel Helper, Hide Effects and Codex Inspect. `ogre end windowreset` closes Reset UI Windows. Zone Reset stops only what it started itself, so a zone read the Instance Controller asked for keeps going.
- **Fixed** · Console: **"ogre end" and the X now fully close the Instance Controller and six other commands.** `ogre end ic` only paused the Instance Controller; it now stops the run and closes the window, the same as the window's X. Export, Crafting Mats, Task Runner, Pot CB and Watcher also stop what they are doing and close their windows on `ogre end` or the X. `ogre end atb` no longer closes OgreBot; use `ogre end bot` for that.
- **Fixed** · Console: **"The window X now ends Ogre Craft, Craft Grandmasters, Inventory Manager and Nav".** Closing these windows with the X now does what `ogre end` does: Ogre Craft ends all crafting, Craft Grandmasters stops its run, Inventory Manager stops its work and Nav stops the trip. `ogre end nav` now closes the Nav window too, and `ogre end mesh` also cancels a trip you ordered while zoning. The X on OgreBot now closes it the same way as `ogre end bot`, so the relay group close settings apply and no combat hold is left behind.

## 2026.10.29.002 {#r2026-10-29-002}

*Thursday, October 29, 2026 at 2:52 PM EDT*

- **Changed** · Bot: **Character reads wait until you are in the world.** While you zone, camp or sit at character select, `ogre assist` prints nothing and `ogre craft queststeps` says "not in world". Script reads about your character, group, target or zone answer empty then instead of reading the game. A console line sent then still reaches a toon by name, class, `all` or `igw:`, but not one aimed by `g1`-`g4`, `groupleader`, an id or an @ alias.
- **Changed** · Crafting: **Crafting Mats: `-ka` alone pulls Kunark's Ascending, and a typo pulls nothing.** `ogre craftingmats -ka` now pulls Kunark's Ascending daily + weekly, like the old `ogre kacraftingmats` (from a script: `ISXOgreEQ2.CraftingMats:Get[-ka]`; `:GetKA` is gone). A word that is not an option is ignored with a warning, and a command of nothing but such words (`-sgi`) pulls nothing - before, it pulled the Visions of Vetrovia signature line.
- **Changed** · Crafting: **Crafting stations missing from the bot's list are found by part of their name.** When a recipe needs a station the bot does not know, it now looks for that name anywhere in a nearby station's name, not only an exact match. A station the game calls "an innovative workstation" is found for a recipe that asks for an "Innovative Workstation".
- **Changed** · Crafting: **The Ogre Craft window's Reload button reloads the craft data files too.** The Reload button at the bottom of the Ogre Craft window now re-reads the craft data files as well as your settings, the same as `ogre craft reload`. `OgreBotAPI.Craft:AddRecipe` now reads a recipe name given as several words the same way `ISXOgreEQ2.Craft:AddRecipe` does, for example `OgreBotAPI.Craft:AddRecipe[all,Tempered,Iron,2]`; a call with one name and a count works as before.
- **Changed** · Console: **Craft add takes the recipe first.** `ogre craft add` is now `ISXOgreEQ2.Craft:AddRecipe`, so the recipe comes first and the count last: `ogre craft add Tempered Iron 2`, and it also takes a recipe id or `lastknownrecipe`. `Craft:Reload` now reloads the craft data files too, and a script's `Craft:Set` and `Craft:Save` say what they did, as the typed words always have. `Craft:Set` and `Craft:Shop` say what they need when a part is missing.
- **Fixed** · Bot: **Craft queue adds and edits go to your own queue, in the order you made them.** A recipe you add while writs or quest crafting run now goes into your own setup queue, which comes back when the run ends; it used to be lost. Removing or changing a recipe right after adding it, while the bot is re-reading your recipe book, now happens after the add, not before. Auto tinkering and low level leveling no longer empty your setup queue each round: anything in it is crafted with the next round.
- **Fixed** · Bot: **Quest helper waits until you stop moving before it clicks anything.** `ogre qh` clicked quest objects and conversation replies while you were moving, and the movement interrupted what the click had started. It now holds every click, hails included, until you are standing still.
- **Fixed** · Bot: **The craft queue buttons work on your own queue while writs or quest crafting run.** While writs or quest crafting run, Clear Queue, Save Queue, Load Queue, the Setup queue list, `ogre craft queue` and `RecipesInQueue` now use your own setup queue, which is set aside for the run, not the run's crafts. Merchant craft (`ogre mc`) now refuses to start while another craft run is going, instead of clearing that run's queue. After the `-Scribe` command, the bot waits for the knowledge book to close before it re-reads your recipe book.
- **Fixed** · Windows: **Ability export keeps Celestial abilities when you pick Journeyman+ through Ancient.** Picking any minimum in the Export window other than "All" left out every Celestial ability, because the export did not know Celestial ranks above Ancient. Celestial abilities are now always kept, and the last choice is labelled Ancient+ since it keeps Ancient and Celestial.
- **Fixed** · Windows: **Quest Compare icons stay drawn properly instead of flickering to a rough version.** The ticks and crosses in the Quest Compare window kept switching between their proper look and a rough, dashed one every few seconds, until you clicked the window. They are now drawn once and only redrawn when someone's step changes.
- **Fixed** · Windows: **Right-click "Apply this to" in the OgreBot window honours All in For Who.** With All picked in the For Who window, right-clicking an option in the OgreBot window still offered and sent to "my group (igw)". It now sends to all, as picked. With nothing picked in For Who it still sends to your group.
- **Fixed** · Crafting: **Quest crafting recognises the EMD Traps step.** In "A Stitch in Time, Part I: Security Measures", quest crafting did not recognise "Create EMD Traps at any of the Innovative Workstations" as a craft step and left it for you. It now crafts the Electric Manaetic Device (EMD) for it.
- **Fixed** · Crafting: **Quest crafting recognises the Hackbot 3000 replacement parts.** In "A Stitch in Time, Part I: Security Measures", quest crafting did not recognise the steps to create the replacement chassis, gears and circuitry for the broken Hackbot 3000, and left them for you. It now crafts the retrofitted chassis, gears and circuitry for them.
- **Fixed** · Crafting: **The Ogre Craft window shows every queue change; -Scribe ends before the book re-read.** The Ogre Craft window now updates when a queue changes but keeps the same number of rows and crafts, for example a recipe renamed, two rows swapped, or a quantity moved from one row to another by a script. The bot now waits for the whole `-Scribe` command to finish, not only its knowledge-book step, before it re-reads your recipe book.
- **Fixed** · Other: **The script converter checks commands inside relay, timedcommand and oc !c.** ogre_convert.py now checks the command inside a relay, timedcommand, squelch or execute line, and inside `oc !c -RawCommandOB_AP` and `-OgreCommandOB_AP`, the same way as a line of its own. Before, a line like `relay all ogre bookcase` was not flagged even though that command is gone. Sweep your converted scripts again: it may list a few more lines.
- **Fixed** · Other: **The script converter checks ogre commands written with capitals.** ogre_convert.py now checks the word after `ogre` in any case, the way the old bot read it. Before, a line like `ogre BookCase` or `relay all ogre BookCase` was not flagged, because only a lowercase word was read. Sweep your converted scripts again: it may list a few more lines.
- **Removed** · Instance Controller: **Instance Controller: every `ogre ic` word is a script call of its own.** The separate `ogreic` command is gone; `ogre ic` takes the same words. Scripts call each word as its own method: `ISXOgreEQ2.IC:List`, `:Check`, `:Run`, `:RunList`, `:Queue[add|startat|clear,...]`, `:Options[-<option>]`, `:Value`, `:Status`, `:Wipe`, `:Open` and `:Close`. A queue add or start-at missing an argument now says what is missing; after updating, run `ogre ui reload` once.
- **Removed** · Crafting: **Crafting Mats: every `ogre craftingmats` word is a script call of its own.** The separate `ogrecraftingmats` command is gone and `ogre craftingmats` works as before; scripts call `ISXOgreEQ2.CraftingMats:Open`, `:Close` and `:Get[-sig,-vov]`. Type each list and category with its dash (`-cd -sig`, not `cd sig`; Kunark's Ascending is `-ka`). After updating, run `ogre ui reload` once.
- **Removed** · Console: **Anti-AFK, Merchant Craft and Refine words are script calls of their own.** `AntiAfk:Run`, `MerchantCraft:Run` and `Refine:Run` are gone; each word is its own `ISXOgreEQ2` call: `AntiAfk:On[1|0]|Off|Invites|Help`, `MerchantCraft:Status|List|Start|Stop|Help` and `Refine:Status|Start|Stop|Plan|Raw|Rare|Bags|Rewards|Reload`. The `ogre` commands take the same words.
- **Removed** · Console: **Craft words are script calls of their own.** `ISXOgreEQ2.Craft:Run[<word>]` is gone; each `ogre craft` word is its own call. A word that already had one uses it: `start`, `writs`, `tinker`, `lll` and `quest` are `Craft:Start`, `StartWrits`, `StartTinker`, `StartLLL` and `StartQuest`, `add` is `Craft:AddRecipe`, and `stop`, `pause`, `scan`, `reload`, `save` and `set` keep their names. The rest are new calls: `Craft:Help`, `Status`, `Clear`, `Queue`, `Catalog`, `Shop`, `QuestSteps` and `ParseStep`.
- **Removed** · Console: **Eight tools' `ogre` words are script calls of their own.** `Run[<word>]` is gone from eight tools; each word is its own `ISXOgreEQ2.<tool>` call: `GetQuest:Start|Stop|List|Reload|Status|Help`, `QuestHelper:On[1]|Off|Status|List|Reload|Help`, `Heartstone:Status|On|Off|Now`, `HarvestLite:On|Off|Status|Interval`, `ReplenishNames:Show|Reload`, `Perf:Measure|Stop|Status`, `Experiment:Status|Boost|Items|Run|Stop` and `PotCb:Open|On|Off|Status|Reset|Interval|Help`. The `ogre` commands take the same words. After updating, run `ogre ui reload` once.
- **Removed** · Console: **Encounter words are script calls of their own.** `ISXOgreEQ2.Encounter:Run[<word>]` is gone; each `ogre encounter` word is its own call: `Encounter:Reload`, `Encounter:Sequences`, `Encounter:Debug[comms|steps,on|off]` and `Encounter:Help`. A word `ogre encounter` does not know now lists its words instead of printing the help.
- **Removed** · Console: **Nav words are script calls of their own.** `ISXOgreEQ2.Nav:Run[<word>]` is gone; each `ogre nav` word is its own call: `Nav:Flags[...]` takes the flags (`-loc`, `-precision`, `-set` and the rest, in any order), and `Nav:Stop`, `Nav:Status`, `Nav:Help` and `Nav:Open` (the nav window) answer `stop`, `status`, `help` and `panel`. `Nav:Stop` now says when it stops. After updating, run `ogre ui reload` once.
- **Removed** · Console: **Overseer words are script calls of their own.** `Overseer:Run[<word>]` is gone: `ISXOgreEQ2.Overseer:Run` starts a run and each other word is its own call, `Overseer:Stop|Status|Traits|Probe|Trace|DumpRows|Populate|Shift|Budget|Profile|UiCost`. `Overseer:BuyMissions` takes flags only; stopping and checking a buy run are `Overseer:BuyMissionsStop` and `Overseer:BuyMissionsStatus`. The `ogre` commands take the same words.
- **Removed** · Console: **Patcher words are script calls of their own.** `ISXOgreX.Patch:Run[<word>]` is gone; each `ogre patch` word is its own call: `ISXOgreX.Patch:Update` (check for and apply updates), `Status`, `RevertExt`, `Mesh`, `Class`, `Ignore` and `TestCorrupt`. Every word after `ogre patch` now reaches the patcher, even before the game part of OgreBot has loaded.

## 2026.10.29.001 {#r2026-10-29-001}

*Thursday, October 29, 2026 at 12:09 AM EDT*

- **New** · Bot: **Crowd Control now mezzes the adds on your group.** With Enable Crowd Control ticked, the bot now mezzes extra mobs that are attacking your group, using the Crowd Control tab's Priority Order list, top first. It never mezzes the mob your group is killing, renews a mez when it has 10 seconds or less left, and gives you your target back after each cast.
- **New** · Bot: **Mystic tab can cancel Torpor when its target is out of combat or too far away.** At lower levels Torpor slows whoever it is on. Two new options on the Mystic tab cancel your Torpor when its target is no longer in combat, or is farther from you than a range you set (blank means 20 meters). Only your own Torpor on that one target is cancelled.
- **New** · Console: **New Kick command removes someone from your group.** `-Kick` in OgreConsole (`OgreBotAPI.Roster:Kick` in scripts) removes a member from your group. With no name it says so and does nothing; a name that is not in your group gets one line and nothing else happens.
- **Changed** · Bot: **CancelCurrentCast shows the bot's own cancels, and FALSE takes a cancel back.** `${OgreBotAPI.Abilities.CancelCurrentCast}` now also reads TRUE when the bot cancels a cast itself, such as `-Cast_Interrupt` or a fight file's cancel, the way OldBot's did. `OgreBotAPI.Abilities:SetCancelCurrentCast[all,FALSE]` now takes back a cancel the bot has not acted on yet, as in OldBot. `:CancelCasting` and the cure-potion interrupt still leave it FALSE, as OldBot's did.
- **Changed** · Bot: **OgreBot leaves the game alone while you zone, camp or sit at character select.** Most of OgreBot now waits while there is no character in the world, instead of reading game data the client is tearing down, which could crash the game during a camp. Logging in, camping, the window title and releasing held movement keys still run, and everything else picks up again once you are in the world.
- **Changed** · Bot: **SpewStats faction and currency events say "Faction" and "Currency", as classic OgreBot.** The `OgreEvent_SpewStats` events a SpewStat faction or currency check sends now have `Command` set to `Faction` or `Currency`, the same words classic OgreBot sends. Before, they were `-faction <name>` and `-currency <name>`. This covers the faction "Not Found" event too.
- **Changed** · Bot: **Task Runner stops when it cannot camp a character out.** If a character could not be camped out (in combat, for example), Task Runner moved on and every following character's login failed the same way. It now stops right there and says which character is still in the world, so you can sort it out and start it again.
- **Changed** · Bot: **The SpewStats recipe event says "Recipe", as in classic OgreBot.** When a SpewStat recipe check finds the recipe, the `OgreEvent_SpewStats` event it sends now has `Command` set to `Recipe`, the same word classic OgreBot sends. Before, it was `-recipe <name>`.
- **Changed** · Bot: **Turning cures on or off at character select changes nothing.** Turning the class cures on or off (Cures:SetEnabled) while a session is at character select or the login screen now says so in one line and changes nothing. Before, it set the cures for no class, or for the character you had just camped. Send it again once a character is in the world.
- **Changed** · Instance Controller: **IC console commands now answer like the panel's buttons.** `ogre ic reload`, `pause`, `resume` and `queue add` now do exactly what the IC panel's Reload, Pause, Resume and Add do, and print the same lines. `ogre ic reload` prints one summary line; each skipped file is still written to the IC log. `ogre ic queue add` no longer prints "queued row"; a zone file that is not valid now says why, and a zone already in the queue is highlighted there.
- **Changed** · Instance Controller: **IC script calls and Max wait answer like the panel.** `ISXOgreEQ2.IC:Stop`, `:Pause`, `:Resume`, `:Refresh`, `:Reload`, `:SetMaxWait` and `:SetFileArgs` now do what the IC panel's buttons do and print the same lines; `:Stop` also clears an IC pause. Max wait per zone never turns text into "no limit": text that is not a number changes nothing and says why, below 0 becomes 1 second, and a fraction rounds up. Adding a zone to the queue says "queued row" again, from the panel and `ogre ic queue add` alike.
- **Changed** · Instance Controller: **More IC console commands answer like the panel.** `ogre ic stop` now does what the panel's End does: it also clears an IC pause and cancels the end-of-list actions while they run. `ogre ic -maxwait=<seconds>` also prints the "max wait per zone" line, and the panel's Clear says "queue cleared" like `ogre ic queue clear`. A zone file that is not valid says how many more reasons the IC log lists, instead of "click it in the list".
- **Fixed** · Bot: **A character running a solo HO sits out Balanced Synergy.** When the group is asked to cast Balanced Synergy, a character running a solo HO for a fight now leaves it out, as intended. Before, it cast Balanced Synergy anyway.
- **Fixed** · Bot: **A class override set with ClassInfo_ChangeValue stays with its character.** A class override set with ClassInfo_ChangeValue, such as making a character count as a fighter, now applies only to the character it was set for. Before, when you camped and logged in a different character in the same session, the new character kept the override.
- **Fixed** · Bot: **A Dirge is recognised as a Dirge for Confront Fear.** A Dirge now cures its own revive sickness with Confront Fear, and accepts the Confront Fear requests other characters send. Before, the Dirge was not recognised as a Dirge, so it asked others for the cure and ignored their requests.
- **Fixed** · Bot: **A sell or destroy list that replaces the shipped list stays that way.** If your sell or destroy list file says `"noMerge": true`, adding or removing an item now keeps it, and the file keeps your whole list. Before, the next change dropped `noMerge`, so names added to the shipped list later joined your list. On the destroy list, that meant items you never reviewed.
- **Fixed** · Bot: **Adding a recipe right after scribing no longer leaves a stray row in the craft queue.** A recipe added while the bot was still re-reading your recipe book after a scribe could appear in the craft queue later, even after you had cleared it. Now it lands only in the queue you added it to, or is dropped with one line saying so, and starting the queue right after waits for it. `AddLastScribedRecipe` right after a scribe now adds the recipe you just scribed, and merchant craft prints one line, not two, when the craft queue will not start.
- **Fixed** · Bot: **Automatic reactions answer only the game's own messages.** Bulwark of Order, Heroic Surge, the encounter kill check, Overseer agent collection, flights, depot transfers, the pack pony, the house plant, IM trade and loot retries now react only to the game's own messages, never to the same words in another player's chat. Fight steps that set a variable, an auto-target name, an assist anchor or the threat ignore list now keep a name with a comma, such as "Krayte, Titan of Colors", whole. Text-to-speech now speaks a message that contains quote marks.
- **Fixed** · Bot: **CancelCurrentCast no longer stays on after a cancel.** After `OgreBotAPI.Abilities:SetCancelCurrentCast`, `${OgreBotAPI.Abilities.CancelCurrentCast}` now goes back to FALSE once the cancelled cast is over, or when the bot starts its next cast, the way OldBot did. Before, it stayed TRUE for the rest of the session, so a script that checked it saw a cancel that was long over.
- **Fixed** · Bot: **Cast stack targets by class or role can pick your own character.** A cast stack entry whose target is a class or a role, such as Guardian, Scout or @Tank, now picks your own character when you are that class or role. Before, it skipped you and looked only at the rest of the group. The Coercer's Possess Essence preference works the same way.
- **Fixed** · Bot: **Channeler Snap Channel and Efficiency cast their conduit once per proc.** When Snap Channel (or Efficiency) came up, the bot queued the chosen conduit dozens of times in a second and then cast it over and over, filling dissonance and carrying on after the fight. It now queues one cast and waits for it to finish before it will queue another.
- **Fixed** · Bot: **Commands sent by tell work again.** With chat commands switched on, commands your own characters send by tell or group chat - "camp time", "mentor:Name", "invite Name", "raid invite:Name", "cast Ability", "kick Name from group" and the rest - act again. Before, they did nothing. The text of the tell is used exactly as typed.
- **Fixed** · Bot: **Fight steps that quote a chat line treat it as plain text.** A fight step that uses a name or word taken from a chat line now runs only when that text is a plain name or number. Otherwise the bot skips that one step, writes a line to the log, and the fight carries on. A line another player types in chat no longer sets off the automatic fighter Intercept or the other reactions to the game's own messages.
- **Fixed** · Bot: **Fight steps that start or stop a solo heroic opportunity now work.** Fight steps that start or stop a solo heroic opportunity now do it. Before, the step did nothing: in Aether Wroughtlands - Native Mettle [Heroic III], Nugget never started its solo heroic opportunity and Goldan never stopped one.
- **Fixed** · Bot: **Get to guild hall knows when you are on a TLE server.** On a TLE server (now including Wuoshi), `-GetToGH` no longer tries to fast travel to Frostfang Sea. When Call to Guild Hall and Call to Home are both not ready, it stops and says there is no route. Before, the bot never recognised a TLE server.
- **Fixed** · Bot: **Group commands no longer reach a camped character.** A command sent to a group (igw: and the other group and raid targets) no longer reaches a session that has camped to character select. Before, that session still counted itself in the group of the character it had camped, until the next character was in the world. Sending a command while your group is zoning still reaches everyone.
- **Fixed** · Bot: **Group water breathing casts the Defiler's and Mystic's ability.** `-CastGroupWaterBreathing` now casts Abominus on a Defiler and Water Spirit on a Mystic, and `-CancelGroupWaterBreathing` cancels it. On other classes, or when the character does not have the ability, both do nothing. Before, both asked for an ability named NULL.
- **Fixed** · Bot: **Heroic Opportunities start with the new character's ability after a swap.** After you camp and log in another character of the same archetype in the same session, starting a Heroic Opportunity now looks up that character's own starter ability. Before, it kept using the ability found for the previous character.
- **Fixed** · Bot: **IM depot stops offering an item the depot is full of.** `ogre im depot` now skips an item for the rest of the run once the depot says "This container cannot hold any more of this item." Before, it only knew the rarer "unique items" message, so it kept offering an item the depot had already refused.
- **Fixed** · Bot: **Loot Distribution weighs a scout's main-hand drop against both hands.** In Loot Distribution, a scout now compares a main-hand item with the weapons in both hands, so it can bid on it as an upgrade for its off hand too. Before, the bot never recognised a scout and only compared the main hand.
- **Fixed** · Bot: **Merchant craft handles any recipe name.** `ogre mc` (merchant craft) now checks whether you know a recipe by reading your recipe book and comparing the name as plain text, so a recipe whose name holds a quote or other special characters works. Before, such a name could break the check. On a very large recipe book the check takes a few seconds before each round.
- **Fixed** · Bot: **Merchant craft no longer leaves a stray row in the craft queue.** If `ogre mc` (merchant craft) stopped at the queue step, its 3 crafts could still turn up in the craft panel's setup queue afterwards, with nothing running them. It now waits until the craft engine has finished re-reading your recipe book before it queues, and if the craft queue will not start it takes those crafts back out. A recipe the craft queue will not take now gives one warning line instead of two.
- **Fixed** · Bot: **Merchant craft only ever queues the recipe it bought.** `ogre mc` (merchant craft) now queues its crafts by the recipe's ID only. Before, if that failed it tried again by name, and the name search could pick a different recipe whose name contains this one. If the craft queue will not take the recipe now, merchant craft stops with one warning line instead.
- **Fixed** · Bot: **No more "ACTOR INDEX NOT SEEDED" warnings while zoning or at character select.** The red "ACTOR INDEX NOT SEEDED - every actor consumer is blind" line printed every 5 seconds while zoning, at the login screen and at character select, where an empty list is expected. It now appears only when a character is in the world, settled, and the list is still empty, which is the real problem it reports.
- **Fixed** · Bot: **Pack Pony no longer crashes the game when you camp to another character.** With the Pack Pony option on, camping from one character to another could crash the game. The Pack Pony check kept reading your character while the world was being torn down. It now does nothing unless you are in the world, and a pony run that a zone or camp interrupts simply ends and tries again later.
- **Fixed** · Bot: **Pack Pony works on characters that have a pet out.** A character with its own pet summoned (a coercer's Possess Essence, a necromancer's or summoner's pet and so on) always failed with "could not find the pack pony", because the game reports the pony differently when you already have a pet. The pony is now found either way, and if it ever is not, the message lists every spawn the bot saw so the cause can be read straight from it.
- **Fixed** · Bot: **Raid invites skip members of your group.** A raid invite - `-RaidInvite` in OgreConsole, `OgreBotAPI.Roster:RaidInvite` in scripts, a `-r` name in `-Inviter`, or a "raid invite" tell - now skips a character who is already in your group, the way the console's raid invite works in classic OgreBot. Before, that character was sent a raid invite.
- **Fixed** · Bot: **Sell and destroy lists keep each item's For Who.** An item on your sell or destroy list that you limited to some characters, such as `{ "forwho": "scout" }`, now keeps that limit when you add or remove another item. Before, the next change saved it as everyone, so on the destroy list more characters destroyed it. A For Who you set on a name from the shipped list is now saved too.
- **Fixed** · Bot: **Yynzik and Arachlord Dyrraga print a setting command that works.** At set up, Yynzik the Scornridden and Arachlord Dyrraga print the command to change their fight settings. That command now works: it reads `OgreBotAPI.Vars:Set[...]`. Before, it named a command the new bot does not have, so typing it did nothing.
- **Fixed** · Windows: **A box no longer appears after your text in OgreBot's text fields.** Some players got an invisible control character, drawn as a box, added to a field (a Cast Stack HP % for example), which made the value invalid. Control characters are now kept out of every OgreBot text field.
