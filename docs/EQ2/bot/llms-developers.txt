# Developers

This section is for people who write their own scripts for OgreBot: raid modules, instance files, side
scripts, MCP buttons, and console lines.

Everything in the new bot has its own TLO and datatypes, so you can explore the scripting surface in game
with `lstype`. The two you will use most are `ISXOgreEQ2` and `OgreBotAPI`.

## Where to start

- **Moving a Classic script over?** Start with [Converting your scripts](converting.md). It has a tool
  that checks a script and fixes what it safely can, and a step-by-step procedure you can hand to Claude.
- **Want a window of your own in game?** [Build your own window](build-your-own-window.md) shows how a script
  or an extension opens one, reads and changes what is in it, and reacts to clicks.
- **Looking up one name?** [Coming from Classic](coming-from-classic/index.md) lists Classic's API
  calls, objects, events and console commands, and what each one is in the new bot.

# Converting your scripts

This page is for moving your own OgreBot Classic scripts over to the new OgreBot: side scripts, helper
scripts, console lines and MCP buttons. It has a small tool that checks a script, fixes what it safely
can, and tells you what is left. The second half is a step-by-step procedure you can hand to Claude
(or do yourself).

> **:no_entry: An old spelling does not give an error - it silently does nothing**
>
> When a script calls a Classic name that no longer exists, LavishScript does not stop: a method call
> does nothing, and a member read gives `NULL`. Nothing is written to any log. A console line with its
> arguments in the wrong order still runs, with the wrong values. So "it loads without errors" proves
> nothing. A script is converted when the tool's **sweep** says `CLEAN`.

## Download

Two files. Put them **in the same folder** - the tool looks for the map next to itself.

- [ogre_convert.py](converter/ogre_convert.py) - the tool (open source)
- [conversion-map.json](converter/conversion-map.json) - the map: one row for every Classic name, saying
  what it does now and what to write instead

You need **Python 3** and nothing else. The tool does not read any bot files and does not talk to the
game, so it runs on any PC. To use a map somewhere else, add `--map <path to conversion-map.json>`.

> **:bulb: Download them again after an update**
>
> The map is generated from the bot itself, so a newer bot can have names an older copy does not know.
> Get both files fresh before you start a conversion.

## What the tool does

Run it from a command prompt in the folder that holds the two files (on Windows, `py` works in place
of `python`). Each command takes a script, several scripts, or a whole folder.

| Command | What it does | Changes files? |
|---|---|---|
| `coverage` | Does the map know every Classic name the script uses? | No |
| `fix` | Makes the safe rewrites, and lists everything else as a to-do | Only with `-o` or `--in-place` |
| `lookup` | Shows what happened to one name, and what to write instead | No |
| `sweep` | Checks a converted script: is any old spelling left? | No |
| `sites` | Lists lines you should keep as they are and mention in your notes | No |

### coverage - does the map know this script?

```
python ogre_convert.py coverage <file.iss>
```

Lists every Classic name in the file that the map has **no row for** (`UNKNOWN`), and ends with a count.
Each unknown is a question to ask before you convert - see [Stop and ask](#7-stop-and-ask). It never says
`CLEAN`: it only checks that the map knows the names, not that anything is converted yet.

It also catches Classic **idioms** - expressions that read differently now even though no Classic name
is in them. The common one is a check that OgreBot is running by its script name,
`${Script["Buffer:OgreBot"](exists)}`. The new bot is not a LavishScript script, so that reads `NULL`.
`fix` rewrites it to `${ISXOgreEQ2.OgreBot.IsReady}`.

### fix - the safe rewrites

```
python ogre_convert.py fix <file.iss>                       (a dry run: writes nothing, prints the list)
python ogre_convert.py fix <file.iss> -o <output.iss>       (writes the result to a new file)
python ogre_convert.py fix <file.iss> --in-place            (keeps the name - see below)
```

`fix` only rewrites what it can prove is right:

- a call that **moved** or was **renamed** and takes the same arguments;
- a Classic call that had no for-who, where the only change is "the for-who is now the first argument":
  it puts `all` first. A script's own call only ever runs on the session running it, so `all` there means
  "this session" - exactly what the old call did;
- a console command that was renamed and takes the same arguments;
- a Classic framework variable that was renamed to a plain member: `${OgreRelayGroup}` becomes
  `${ISXOgreEQ2.Auth.RelayGroup}` (and `${OgreRelayGroup.Length}` becomes `${ISXOgreEQ2.Auth.RelayGroup.Length}`),
  so a relay line like `relay ${OgreRelayGroup} ...` converts with no hand work.

Everything else stays as it was and is printed as a to-do, with the map's how-to-fix text. Each line of
the list says `DONE` (rewritten) or what is left (`signature`, `argOrder`, `notPorted`, `UNKNOWN`, ...).
**Keep that list** - it is the work list for the rest of the conversion.

`--in-place` keeps the file's name, so `run <your script>` and anything that `#include`s it keep working
on the new bot. It first copies the original to a backup beside it (the tool prints the backup's name),
then converts the file. If that backup already exists, it stops and writes nothing - the file may
already be converted.

### lookup - one name

```
python ogre_convert.py lookup Ogre_CampSpot:Set_CampSpot
python ogre_convert.py lookup OgreBotAPI:ChangeCampSpotWho
python ogre_convert.py lookup -ChangeCampSpotWho
```

Object calls are written `Object:Name` or `Object.Name`; console commands keep their dash. `lookup`
prints the map's row:

| Field | Means |
|---|---|
| `status` | what happened to the name (see the table in [Pass 2](#5-pass-2-the-work-list-one-row-at-a-time)) |
| `oldSignature` | Classic's arguments |
| `newForm` | what to write instead |
| `newSignature` | the new arguments - `fw` is the for-who, which comes first |
| `oldSpellingToday` | what the old spelling does under the new bot right now |
| `howToFix` | what to do |
| `note` | **the traps - read it** |
| `newParams` | (console commands) the new command and its parameters, in order |
| `example` | a real Classic line and its new form, when there is one |

`lookup` also answers for a **new** name ("a new-bot name - it exists", and which old names become it),
so you can check every name you write. A name that is not Classic's at all - `oc`, `!ci`, `Script`, `Me`,
`echo` - says so and is unchanged. Only `NOT IN THE MAP` is a question.

### sweep - is it clean?

```
python ogre_convert.py sweep <converted file>
```

`CLEAN` means: no Classic spelling is left that changed, no Classic name the map does not know, no
new-bot call that does not exist, no console command that does not exist, and no console command
wrapped in quotes. Anything else is `NOT CLEAN`, with one line per problem:

| Tag | Means |
|---|---|
| `OLD` | a Classic spelling that changed is still there |
| `UNKNOWN` | a name the map has no row for - a question |
| `BROKEN` | a new-bot call that does not exist, or a console command in quotes |
| `WARN` | a console command whose arguments changed - the sweep cannot tell whether you already fixed them; check each one against its `note` |
| `NOTE` | (button files) a button with a label and no command |

The sweep checks **names** only - not the logic around them. Lines that start with `;` are comments and
are skipped, so `; TODO(Classic): ...` notes are fine.

### sites - lines to keep and list

```
python ogre_convert.py sites <file.iss>
```

Lists lines that should **not** be rewritten, but that you should know about:

| Tag | Means |
|---|---|
| `R10` | the game's own name lookup - `${Me.Ability["..."]}`, `.ToAbilityInfo`, `.ToItemInfo` and the other `.To*Info`. These ask the game server and can come back empty. |
| `R12` | an actor scan or search - `EQ2:QueryActors`, `EQ2:GetActors`, `CustomActorArray`, or `Actor[...]` by name or query instead of by id. These are slow. |
| `INDEX` | a loop guarded by `${Something[${i}](exists)}`. Reading past the end of an ISXEQ2 list **crashes the game client**, and the `(exists)` check is that read. It needs a bound by the list's count. |

The tool finds candidates; look at each one yourself.

## Which files to convert

- **Your own scripts** - yes. That is what the tool and the procedure below are for.
- **Instance files** - not line by line. An instance in the new bot is an IC JSON zone file that the bot
  runs itself, so almost every line of an old instance file becomes a line in that JSON file instead. A
  line-by-line conversion would sweep `CLEAN` and do nothing. Run `coverage` and a dry `fix`: its list
  says what each line becomes, and is the plan for the zone's JSON file.
- **Raid modules** (a file that `inherits Object_ZoneParentInherit` or `Object_ZoneModuleInherit`) - no.
  In the new bot a fight is an encounter JSON file.
- **MCP buttons** - not by hand. The new bot copies your Classic buttons itself when it loads, and puts
  the arguments of every command whose order changed in the new order. `ogre migrate` shows the progress.
  Afterwards, check them with
  `python ogre_convert.py sweep <your Scripts folder>\OgreSave\EQ2\OgreMCP.json`.

## Converting with Claude

You can hand a conversion to Claude (or another AI assistant). Give it the two files above (or their
links), the script, and this instruction:

> Convert this OgreBot Classic script to the new OgreBot. Follow the procedure in the section
> "Converting with Claude" on the "Converting your scripts" page, using ogre_convert.py and
> conversion-map.json.

The rest of this page is that procedure. It is written for Claude, but it works the same for a person.

### 1. The one fact that shapes everything

A Classic spelling does not fail in the new bot - it silently does nothing. A call to a method that no
longer exists does nothing; a read of a member that no longer exists gives `NULL`; nothing is logged. So
"it loads without errors" proves nothing. You are done only when the **sweep** (step 6) says `CLEAN`,
or every line it still names is a question you have listed.

### 2. Rules you must not break

1. **Ask before you write, and never lose the original.**
    - **A file that ships with Classic** (anything in Classic's own folders, such as `EQ2OgreBot`,
      `EQ2OgreCommon`, `OgreConsole`): never edit it. Write the result to a new file (`fix -o`).
    - **The person's own script** (the usual case): ask once, before step 4, which they want:
        - **Keep the name (recommended):** `fix --in-place`. The original is backed up beside it and the
          script keeps its name, so `run` and `#include` lines elsewhere keep working. It refuses if the
          backup already exists - then ask, the file may already be converted.
        - **A new file beside it:** `fix <file.iss> -o <new name>`. The original is untouched.

    Never write over a file the person did not choose, and never without the backup.

2. **Never invent a name.** Every new name you write comes from a map row (`newForm`), or from the map's
   lists of new names (`newApi`, `newConsole`). `lookup` confirms any name. If the map has no row for an
   old name, stop and ask (step 7).
3. **No compatibility shims.** Never write a wrapper, alias or variable that makes an old name keep
   working. Convert the call.
4. **No game name lookups in what you add.** Never write `${Me.Ability["..."]}`, `Me.Ability[name,...]`,
   `.ToAbilityInfo`, `.ToItemInfo` or any `.To*Info` - they ask the game server. Passing an ability or item
   **name** to a bot call (`OgreBotAPI...`, a console command) is fine: the bot looks names up in its own
   ability export. If the Classic line already has a game name lookup, keep it as it is and list it
   (`R10` in `sites`).
5. **No actor scans in what you add.** Never add `EQ2:QueryActors`, `EQ2:GetActors`, `CustomActorArray`
   or an `Actor[...]` that finds an actor by anything but its id (`Actor[query,...]`,
   `Actor[exactname,...]`, `Actor["name"]`). Existing ones: keep, and list (`R12` in `sites`).
   Loops guarded by `${Something[${i}](exists)}` (`INDEX` in `sites`): do not rewrite them (that changes
   the logic) - list them, and say they can crash the game client and need a bound by the list's count.
6. **A name the map does not know is a question.** Leave the line exactly as it was and ask. Do not
   guess what it became.
7. **The for-who comes first** on every new call that takes one (its `newSignature` starts with `fw`).
   When the Classic call had none, the word you insert depends on the line:
    - a **script call** (`OgreBotAPI.<Group>:Name[...]`): `all` - a script's own call only runs on the
      session running it, so `all` is that session;
    - a **console line** (`oc !c -Command ...`): `auto` - the For Who window decides, as it did in Classic.

    A console line that starts `oc !c -cfw <who> -Command ...` already says who: leave it as it is.

### 3. Pass 0 - does the map know this file?

```
python ogre_convert.py coverage <file.iss>
```

Every `UNKNOWN` it lists is a question for step 7. Then decide what kind of file it is:

- It `inherits Object_ZoneParentInherit` or `Object_ZoneModuleInherit`: a **raid module**. Stop. Report
  "raid module - not converted" and nothing else.
- It `#include`s `Ogre_Instance_Include.iss`, calls `function_Handle_Startup_Process`, or lives under
  `InstanceController\Instance_Files`: an **instance file**. Do not convert it as a script. Run a dry
  `fix` (no `-o`, no `--in-place`): its list says what each line becomes. Hand that list back as the plan
  for the zone's IC JSON file, with your questions, and say plainly "instance file - its job moves to an
  IC JSON file; the script is not converted". Writing the IC JSON file is a separate job - ask the person
  before starting it.
- An MCP button file (`OgreMCP.json`): see [MCP buttons](#mcp-buttons) below.
- Anything else: carry on.

### 4. Pass 1 - the mechanical pass

```
python ogre_convert.py fix <file.iss> --in-place          (keep the name - the person's choice in rule 1 of step 2)
python ogre_convert.py fix <file.iss> -o <output.iss>     (a new file, or a file that ships with Classic)
```

It prints every `DONE` line and every line it left for you, with the map's how-to-fix text. **Keep that
list - it is your work list for pass 2.**

### 5. Pass 2 - the work list, one row at a time

For each line the tool left, `lookup` the name, read the row - **the `note` carries the traps** - and do
what its status says:

| status | do this |
|---|---|
| `unchanged` | nothing |
| `moved`, `renamed` | write `newForm`. The tool left it only because it could not prove the arguments line up: compare `oldSignature` with `newSignature` and match each argument by its MEANING, not its position |
| `signature` | write `newForm` and rebuild the arguments from `newSignature` and `note`. "The for-who is now argument 0" on a call that had none: put `all` first. A call that already had a for-who keeps it, moved to the front |
| `argOrder` | write `newForm` (or keep the command) and reorder the arguments exactly as `note` says (console notes give `Old:` and `New:`) |
| `portedElsewhere` | write what `newForm` / `howToFix` names (often a `${ISXOgreEQ2...}` read, a window, or an `ogre` command). If it is a window or command a person uses, it is not script work: comment the line out, `; TODO(Classic) done elsewhere: <newForm> - <old line>`, and list it |
| `dataFile` | the job is now a line in an encounter or IC JSON file. Do not convert it in the script: comment it out, `; TODO(Classic) data file: <newForm> - <old line>`, and list it |
| `notPorted`, `stub`, `removed` | if `howToFix` names a replacement, write it. Otherwise there is no working replacement: comment the line out, `; TODO(Classic) <status>: <old line>`, and list it with what the script loses (`oldSpellingToday`, `note`). Never substitute something "close" |
| `unexamined` | nobody has checked this name yet. Comment it out the same way, list it, and say it needs an answer |

**What depended on a line you commented out goes with it.** An `if !${Return}` (or any read of
`${Return}`) right after a call you commented out would read a stale value, and an `if` or `while` whose
condition you commented out leaves its `{ ... }` body orphaned. Comment those out too, and list each one
with the line it depended on. The same goes for a line the tool rewrote (`DONE`) inside a block whose job
moved to a data file.

**Member reads inside expressions.** `${Ogre_CampSpot.Get_CampSpot}` becomes
`${OgreBotAPI.CampSpot.EffectiveLoc}`: replace only the `Object.Name` part, and keep `${`, `}`, the rest
of the expression, and any `[arguments]` the new member takes. If the new member's empty value differs
(the `note` says so), check that the code using the value still makes sense.

**Commented-out code in the original stays commented**, and is not converted.

**`call` and functions.** A Classic `call OgreBotAPI.X` or `call <Object>.X` is a function call. If the
row's `newForm` is a method (it has a `:`), write a method call, `OgreBotAPI.Group:Name[...]`. If the row
is `unchanged`, keep the `call`.

**Events.** `lookup event:<Name>` says whether a Classic event still fires. An atom attached to an event
whose row is not `unchanged` will never run - list it.

**Console quoting is the same as Classic.** Keep a quoted argument quoted
(`oc !c -ZoneDoor all "${UserInput}"` - without the quotes a value with a space splits in two), and never
wrap a whole command in quotes.

### 6. Pass 3 - prove it

```
python ogre_convert.py sweep <converted file>
python ogre_convert.py sites <converted file>
```

You are not done until the sweep prints `CLEAN` - or until every line it still names is an `UNKNOWN`
you have listed as a question. **Never edit, comment out or "convert" an `UNKNOWN` line to make the sweep
pass**: leave it exactly as Classic wrote it, so the sweep keeps saying `NOT CLEAN` until someone answers
the question. A `NOT CLEAN` result with every unknown listed is an honest result; a `CLEAN` result that
hides them is not. Check every `WARN` line against its row's `note`, and say in the report that you did.

### 7. Stop and ask

Do not decide these yourself:

- A name the map does not have (`UNKNOWN` in `coverage`, `fix` or `sweep`; `NOT IN THE MAP` in `lookup`).
  Leave the line untouched and list it - one question per name, with how often the file uses it.
- An OgreBot **option id** the new bot does not have (`option id the new bot does not have`), in
  `-ChangeOgreBotUIOption`, `Options:Set`, `Options.Value`, `OgreBot.Value` or `TabConfig.<Tab>.<id>`.
  Never swap in an id with a similar name: Classic has several options whose ids differ by one word.
  Proven renames are in the map, and `fix` applies them itself.
- A `notPorted`, `stub`, `unexamined` or `UNKNOWN` call the script cannot work without (its main job).
  Commenting it out makes the script run but not do its job - say so plainly, at the top of the questions.
- A for-who you cannot work out: the old call took it from a variable whose meaning you cannot see, or the
  same line mixes "everyone" and "only me".
- A `signature` row whose `note` and `newSignature` do not tell you how an old argument maps.

In a conversation, ask the person in ONE message with every question together. In a batch run, finish
everything else, then put the questions at the top of the report.

### 8. The report

```
Converted: <in> -> <out>   (kept the name: the original is backed up as <the backup's name>)
Sweep: CLEAN | NOT CLEAN - U unknown names, all in Questions   (N calls checked - the sweep's count; W warnings checked by hand)
Mechanical rewrites: N   (the DONE lines - not repeated below)
Hand conversions:   line  old -> new   (what YOU changed; say WHY for every signature / argOrder one)
Commented out: N   (not ported + done elsewhere + data-file moves + the lines that depended on them)
Not ported (commented out):   line  old  [status]  - what the script loses
Done elsewhere (commented out):   line  old -> <window / ogre command / setting>
Data-file moves:   line  old -> <what>  - belongs in <encounter / IC file>
Game lookups and actor scans kept as they were:   line  text   (R10 / R12 from sites)
Index loops (can crash the client):   line  text   (INDEX from sites)
Questions:   (step 7)
```

### MCP buttons

The new bot copies Classic's buttons itself when it loads - do not rewrite button commands by hand. Your
job is the check afterwards:

```
python ogre_convert.py sweep <Scripts folder>\OgreSave\EQ2\OgreMCP.json
```

In a button file the sweep checks every button's `command` (labels are not code), and names each finding
by its place in the file, with the page and button names, for example
`pages[0]{Combat}.btns.13_0{Intercept}.command`. It reads every command on a line the way the new console
does, including chains. A `WARN` appears only on a button the copy did NOT rewrite - check those against
the row's `note`. A console or `irc !c` button that needs a for-who gets `auto`; a button that calls a
method directly (`OgreBotAPI.<Group>:Name[...]`) is a script call and gets `all`.

You change nothing yourself - the person changes buttons in the MCP window. Report per button:

```
Questions:   button - what is unknown or unclear
Change to:   button - now: <command> - change to: <command> - why (the row's how-to-fix)
No replacement:   button - <command> - [status] - what it loses
Runs, but does less:   button - what changed
Empty buttons:   button   (the NOTE lines)
Checked by hand (WARNs that are fine):   button
Actor scans kept:   button - text   (from sites)
```

Scripts a button starts (`-RunScriptOB`, `runscript ...`) are separate files - each needs its own
conversion; list them.

### The four changes behind most rows

These explain most of what the notes say. [Coming from Classic](coming-from-classic/index.md) has the
longer version, and a page per Classic object with every name on it.

1. **The for-who comes first.** Every new call that acts on some sessions takes the for-who as its
   first argument. A call that had none gets `all` in a script (that session) or `auto` on a console line.
   A name or `igw:${Me.Name}` narrows it, as before.
2. **Calls live in groups.** The flat `OgreBotAPI:Xxx` calls became `OgreBotAPI.<Group>:Xxx` (`CampSpot`,
   `Movement`, `Cures`, `Roster`, `Abilities`, ...). Classic's global objects (`Ogre_CampSpot`,
   `GetInfoOb`, `Obj_CureCurseCalled`, `ClassInfo`, `Ob_AutoTarget`, ...) do not exist in the new bot -
   every call on them is a conversion.
3. **Ability and item names are fine in bot calls.** The bot looks names up in its own ability export.
   Only the game's own name lookups (`${Me.Ability["..."]}`, `.To*Info`) are out.
4. **Data files replace scripts.** Fights are encounter JSON files, and instances are IC JSON files. The
   script calls that drove them (`dataFile` rows) move there instead of being converted.

### Scripts that watched for frozen sessions (OgrePing)

`fix` rewrites the three OgrePing spellings itself. What it cannot do is change the handler's shape, and
the new events mean something different:

| Classic (OgrePing) | New bot (the uplink's session watch) | So the script must... |
|---|---|---|
| `PingTimeOut` fired every round (about 10 seconds) while a session stayed silent | `OgreEvent_SessionFrozen` fires **once** per freeze, after 30 seconds of silence (90 while loading) | act on the first event, and drop any timeout counter |
| a closed or crashed session was never reported, so scripts polled `${Session["is1"](exists)}` | `OgreEvent_SessionGone` fires once for any disappearance (closed, crashed, killed) | attach to it, and drop the polling loop |
| nothing when a session came back | `OgreEvent_SessionRecovered` | (optional) cancel a pending recovery |
| one shared "ignore pings" flag | each event names its session | keep "being recovered" per session |
| `${OgreConsole.bUplink}` | `${LavishScript.Executable.Right[14].Equal["EverQuest2.exe"]}` is TRUE inside the game | test the executable |
| the script had to start OgrePing | the watch is off by default: the ogre config checkbox keeps it on, and `OgreConsoleHub.Sessions:On` turns it on until the uplink restarts | turn it on if `${OgreConsoleHub.Sessions.Watching}` is FALSE |

To bring a session back, let the auto-login do it: it already knows which toon goes in which slot, logs
the toon in and loads OgreBot. Keep every wait bounded, and never test a kill on a session with a toon in
the world without asking first.

# Build your own window

Ogre's in-game windows are HTML pages drawn over the game. Your own script, or your own extension, can put a
window of its own up there, read and change what is in it, react when the player clicks a button, and hear
when any window opens or closes.

All you need loaded is the core, `ext ISXOgreX`. You do not need OgreBot, a profile, or a toon in the world:
it works at the login screen.

> **No promises.** Use this at your own risk, and expect it to change. That said, Kannkor works hard to keep
> things backwards compatible, and the new bot is the first big break in a very long time.

## Quick start

A working example ships with Ogre. In the InnerSpace console, type:

```
run Ogre/Common/OgreUI/examples/hello/hello
```

A small **Hello** window opens. Type a name, tick **Shout it**, and press **Say hello**: the greeting
appears in the console and in the window's status line. Close the window with its **X**, and the script ends.

The example is three files in `Scripts\Ogre\Common\OgreUI\examples\hello\`:

| File | What it is |
|---|---|
| `hello.html` | The window: its options, its style, its markup, and its script, all in one file. |
| `hello.iss` | The script that opens the window, reacts to it, and closes it. |
| `hello.md` | The text the window's **?** button shows. |

To start your own window, copy that folder next to your script and rename things.

### The window: `hello.html`

```html

<script type="ogre/window">{"title":"Hello","w":280,"h":0}</script>

<style>
```

### The script: `hello.iss`

```
; hello.iss - opens hello.html, reacts to its button, follows its checkbox, re-opens it after a UI reload, and
; ends when you close the window.
;   run Ogre/Common/OgreUI/examples/hello/hello
variable string Dir="${Script.CurrentDirectory}"
variable bool Shout=FALSE

; The window's button fires this (hello.html: Event[Hello_Say]:Execute).
atom(script) OnSay()
{
    variable string Greeting="Hello, ${ISXOgreX.UI.Value[hello,hello-name]}!"
    if ${ISXOgreX.UI.Value[hello,hello-shout]}
        Greeting:Set["${Greeting.Upper}"]
    echo "${Greeting}"
    ISXOgreX.UI:Set[hello,hello-status,"Said: ${Greeting}"]
}

; Every window's close comes here. A reload takes every window away - open ours again. Closed by the user: stop.
atom(script) OnClosed(string name, string reason)
{
    if !${name.Equal[hello]}
        return
    if ${reason.Equal[reload]}
        OpenWindow
    else
        Script:End
}

; The window is one file; its ? help is the .md beside it. Already open: nothing happens.
atom(script) OpenWindow()
{
    ISXOgreX.UI:Open[hello,"${Dir}/hello.html","${Dir}/hello.md"]
}

function main()
{
    LavishScript:RegisterEvent[Hello_Say]
    Event[Hello_Say]:AttachAtom[OnSay]
    Event[OgreUI_Closed]:AttachAtom[OnClosed]
    OpenWindow

    ; Follow the checkbox. Value is NULL until the window is open, so only compare once it answers.
    while TRUE
    {
        if ${ISXOgreX.UI.Value[hello,hello-shout](exists)} && !${ISXOgreX.UI.Value[hello,hello-shout].Equal[${Shout}]}
        {
            Shout:Set[${ISXOgreX.UI.Value[hello,hello-shout]}]
            echo "Shout is now ${Shout}"
        }
        wait 10
    }
}

atom atexit()
{
    Event[Hello_Say]:DetachAtom[OnSay]
    Event[OgreUI_Closed]:DetachAtom[OnClosed]
    ISXOgreX.UI:Close[hello]
}
```

## The window file

A window is **one HTML file**. It is not a whole web page, so there is no `<html>`, `<head>` or `<body>`: just
the parts below, in this order.

1. **Options** (optional): one `<script type="ogre/window">` block holding JSON.
2. **Style**: a `<style>` block.
3. **Markup**: what the window shows.
4. **Script**: one or more `<script>` blocks. They run once, after the markup is in place, in file order.

The file can sit anywhere on disk; you pass its full path when you open it. `${Script.CurrentDirectory}` is
the folder your script is in, with forward slashes, so `"${Script.CurrentDirectory}/mywindow.html"` finds a
file next to your script.

### Window options

| Option | Default | What it does |
|---|---|---|
| `title` | the window name | The text in the title bar. |
| `w`, `h` | `0` (fit the content) | Width and height in pixels. |
| `x`, `y` | `60`, `60` | Where the window first opens. |
| `resizable` | `true` | The player can resize it from the corner. |
| `draggable` | `true` | The player can move it by its title bar. |
| `chrome` | `"full"` | `"none"` draws no title bar or frame - just your content. |
| `capture` | `true` | `false` lets clicks fall through the window to the game. |
| `scale` | `0` (the player's UI scale) | A size multiplier for this window only, from 0.5 to 2. |
| `noPersist` | `false` | `true`: never remember where the player put it. |
| `noHelp` | `false` | `true`: no **?** button in the title bar. |

Ogre remembers where the player moves and sizes each window, by its name. `x`, `y`, `w` and `h` are only
where it starts the very first time; after that, the player's position wins.

### Names: keep yours your own

Every window shares one page, and your scripts run in that page's global scope.

- **Give your window a name that is clearly yours**, for example `mytool` rather than `options`. Opening a name
  that is already open does nothing, so a clash with another window means yours never appears.
- **Prefix your element ids, CSS selectors and global functions** with your window's name: `mytool-status`,
  `#mytool-root .row`, `window.mytoolRefresh`. Two windows with the same id, class or global function name
  will fight.

## Loading and unloading the window

| You write | What happens |
|---|---|
| `ISXOgreX.UI:Open[name,path]` | Reads the file at `path` now; the window opens a moment later, once the UI is up. |
| `ISXOgreX.UI:Open[name,path,helpPath]` | The same, and the **?** button shows the markdown file at `helpPath`. |
| `ISXOgreX.UI:Close[name]` | Closes the window. The player can also close it with its **X**. |
| `${ISXOgreX.UI.Window[name](exists)}` | `TRUE` while the window is open, `NULL` when it is not. |

- **`Open` does not wait.** Straight after it, the window is not there yet. To act once it is, attach to
  `OgreUI_Opened` and wait for your window's name; by the time that fires, every `Value` in the window
  answers. Or check `${ISXOgreX.UI.Window[name](exists)}` in a loop, with a limit on how long you wait. With
  the UI up it takes a few frames; at game start, the UI comes up after the core signs in.
- If the file cannot be read, `Open` prints a warning in the console and opens nothing.
- **Opening a window that is already open does nothing**: no second copy, no reset, no event.
- `Close` on a window that is not open does nothing.
- **Closing does not end your script.** The hello example ends itself when it hears its window close; see
  [Knowing when windows open and close](#knowing-when-windows-open-and-close).

## Reading elements

`${ISXOgreX.UI.Value[name,id]}` is the current value of the element with id `id` in window `name`.

| Element | Value |
|---|---|
| Checkbox, radio button | `TRUE` or `FALSE` |
| Text box, password box, text area | The text. An empty box is `""`, not `NULL`. |
| Slider (`type="range"`) | The number, as text. |
| Hidden input | Its value. Ogre's dropdowns keep their choice in one (see the gallery). |
| Any other element with an id and no child elements (a `<span>`, a `<label>`, a `<button>`) | Its text. |

`Value` is `NULL` when the window is not open, or when there is no such element. Use `(exists)` to tell
those cases apart from an empty text box.

The value is kept up to date as the player types, clicks and picks. Elements that contain other elements
(a `<div>` around your form, say) have no value.

## Changing elements

`ISXOgreX.UI:Set[name,id,value]` changes one element, the right way for its kind:

| Element | What `Set` does |
|---|---|
| Checkbox, radio button | Ticks it for `TRUE`, `1`, `on` or `yes` (any case); unticks it for anything else. Ticking a radio button unticks the others in its group, and their `Value`s follow. |
| Text box, text area, slider, hidden input | Sets its value. For a dropdown's hidden input, the dropdown shows the new choice too. |
| Anything else | Sets its text. |

`Set` fires the element's `change` (and, for text, `input`) event, so your window's own script reacts just
as it would if the player had done it. Setting a checkbox to the state it is already in fires nothing.

**You can read your own change straight back**, even inside an event handler:

```
ISXOgreX.UI:Set[hello,hello-name,"Mirelle"]
echo ${ISXOgreX.UI.Value[hello,hello-name]}      ; Mirelle
```

The window applies a `Set` a moment after it is made. A `Value` read of an element you have just changed
waits for that, which takes well under a millisecond. Anything your window's own script changes in its
`change` or `input` handler, with `ogreUISet`, is in by then too. Reads of elements you have not just
changed never wait.

Put the value in double quotes when it has spaces or commas in it: `ISXOgreX.UI:Set[hello,hello-name,"Mirelle Dawn"]`.

### From the window's own script

When your window's script changes an element itself, change it with `ogreUISet` so scripts see the new value:

```js
ogreUISet('hello', 'hello-status', 'Working...');
```

It takes the same three things as `ISXOgreX.UI:Set` and behaves the same way. If you change an element some
other way (`el.textContent = ...`, `el.checked = true`), `Value` keeps answering the old value until the
player next touches that element.

## Reacting to clicks

The window talks to your script with one call:

```js
window.ogreCall('cmd', 'Event[Hello_Say]:Execute');
```

It runs one LavishScript command line, exactly as if typed in the console. The usual pattern is to fire an
event your script has attached an atom to, as hello does. Your script registers the event with
`LavishScript:RegisterEvent[Hello_Say]` and attaches with `Event[Hello_Say]:AttachAtom[OnSay]`.

- The command runs on the **next frame**, not inside the click.
- **Nothing comes back.** `ogreCall('cmd', ...)` returns nothing useful. To answer the window, the script
  uses `ISXOgreX.UI:Set`.
- **Keep the command line fixed.** Do not build it from what the player typed: a `]` or a `"` in their text
  changes the command. Send a fixed command and let the script read the text with `Value`.
- **The command line must be under 8,191 bytes.** A longer one is dropped whole, and nothing tells your
  window or your script; the only trace is one line in the UI log. Send a short command and let the script
  read what it needs with `Value`.

## Knowing when windows open and close

Two events fire for **every** window - yours, OgreBot's, and the help windows the **?** button opens:

| Event | Arguments |
|---|---|
| `OgreUI_Opened` | `name` |
| `OgreUI_Closed` | `name`, `reason`: `closed` (its **X**, or `ISXOgreX.UI:Close`) or `reload` |

- ISXOgreX registers both events when it loads, so your script attaches with
  `Event[OgreUI_Closed]:AttachAtom[...]` and needs no `RegisterEvent`. Load ISXOgreX before your script
  attaches.
- `OgreUI_Opened` fires every time a window is created, including your own re-open after a reload. It does
  not fire for an `Open` of a window that is already open, and it does not say why the window opened: keep
  your own note if you need to tell a first open from a re-open.
- The help window that the **?** button opens is named `help:` followed by the window's name, for example
  `help:hello`.
- Hiding or showing a window does not fire them; only opening and closing does.

### Surviving a UI reload

A reload of the UI closes **every** window at once. That happens when a patch lands, when the player types
`ogre ui reload`, and it can happen while the game is starting up. Each window gets `OgreUI_Closed` with reason
`reload`. **Nothing re-opens your window for you**: re-open it when you see your own name with that reason.

```
atom(script) OnClosed(string name, string reason)
{
    if ${name.Equal[mytool]} && ${reason.Equal[reload]}
        ISXOgreX.UI:Open[mytool,"${Dir}/mytool.html"]
}
```

- Your window counts as closed from the moment the reload starts: `Window` and `Value` answer `NULL` until it
  is open again.
- Calling `Open` from inside your `OgreUI_Closed` handler is fine; the new window opens as soon as the new UI
  is up.
- The new window is a fresh copy of your file: everything in it is back to what the file says.

## Where a window is

`${ISXOgreX.UI.Window[name]}` is the window, while it is open:

| Member | Type | What it is |
|---|---|---|
| `Name` | string | The window's name. |
| `Visible` | bool | `FALSE` while the window is hidden. |
| `X`, `Y` | int | Its top-left corner on the screen, in pixels. |
| `Width`, `Height` | int | Its size on the screen, in pixels, after its scale. |

Ogre can hide a window without closing it: for example, when the player has Ogre hide the windows that the
InnerSpace console covers. A hidden window keeps the position it last had on screen. While the player
drags or resizes a window, the position can be a frame behind.

## The ? button

Pass a help file as the third argument of `Open` and the **?** in your window's title bar shows it. The help
is plain markdown, kept small on purpose:

```
---
title: Hello
---
The smallest example window: type a name and press **Say hello**.

### What you can do here
- **Name** - who to greet.
- **Shout it** - greet in capitals.
```

It understands `### headings`, paragraphs, `- ` list items, `**bold**` and `` `code` ``. Anything else shows
as plain text. The block between the `---` lines at the top is optional and is not shown.

Open a window without a help file and its **?** says "No help written for this window yet." To have no **?** at
all, put `"noHelp": true` in the window's options.

## Every element, working

Ogre's windows use about thirty kinds of element: tabs, dropdowns, drag-to-reorder lists, a color picker,
and more, many of them built by hand. The **gallery** example has a working sample of each, with the code
next to it:

```
run Ogre/Common/OgreUI/examples/gallery/gallery
```

Copy what you need from `Scripts\Ogre\Common\OgreUI\examples\gallery\gallery.html`. For a dropdown, a number
field or a color picker, use the gallery's versions: they are the ones Ogre's own windows are built with.

## Reading OgreBot's own settings

When OgreBot is running, a script can read any setting from the bot's own window:

```
echo ${OgreBotAPI.Options.Value[checkbox_settings_loot]}
```

The id is the setting's name, matched without regard to case. Checkboxes read `TRUE` or `FALSE`; other
settings read as the text or number they hold. An unknown id, or no profile loaded (at the login screen,
say), reads `""` rather than `NULL`. The ids are listed on
[OgreBot option ids](coming-from-classic/options.md).

## From a C++ extension

There is no separate C++ API. An extension uses the same names through InnerSpace:

```cpp
// open, change, read  (myDir = the folder your files are in, with forward slashes)
std::string open = "ISXOgreX.UI:Open[mytool,\"" + myDir + "/mytool.html\"]";
pISInterface->ExecuteCommand(open.c_str());
pISInterface->ExecuteCommand("ISXOgreX.UI:Set[mytool,mytool-status,\"Ready\"]");

char buf[256];
pISInterface->DataParse("${ISXOgreX.UI.Value[mytool,mytool-name]}", buf, sizeof(buf));

// hear every window open and close
static void __cdecl OnUIClosed(int argc, char *argv[], PLSOBJECT)
{
    // argv[0] = window name, argv[1] = "closed" or "reload"
}

unsigned int ev = pISInterface->RegisterEvent("OgreUI_Closed");
pISInterface->AttachEventTarget(ev, OnUIClosed);
// ... and in your Shutdown:
pISInterface->DetachEventTarget(ev, OnUIClosed);
```

- `RegisterEvent` finds the event if it already exists and creates it if not, so it does not matter whether
  your extension or ISXOgreX loads first.
- Events fire on the game's frame, the same thread your extension's pulse runs on.
- Keep the callback short: it runs inside every window open and close.

## Pitfalls

Each of these was checked in game on 2026-10-17 or 2026-10-18.

| You try | What happens |
|---|---|
| `confirm('...')` | No dialog appears. It returns `false`. |
| `prompt('...')` | No dialog appears. It returns `null`. |
| `alert('...')` | No dialog appears. |
| `localStorage` or `sessionStorage` | Throws `SecurityError: The operation is insecure.` Keep state in your script instead. |
| `<script src="...">`, `<link rel="stylesheet" href="...">`, `<img src="...">` | Nothing loads, whether the path is a full `file:///` path or a relative one; the UI log says `Not allowed to load local resource: file:///...`. The window has no web address (`about:blank`). Put styles and scripts inline in your file, and images in as inline SVG or `data:` URIs. |
| `console.log('...')` | Goes to `<InnerSpace folder>\x64\Extensions\ISXDK35\OgreUIRuntime\ISXOgreUIHost.log`, as a line ending `CONSOLE: ...`, not to the InnerSpace console. Every session on the PC writes to that one file. |
| A command over 8,191 bytes through `ogreCall('cmd', ...)` | Dropped, with only a line in that same log. |
| `<select>` | Drawn as a small empty box that cannot be clicked or opened. Use the gallery's dropdown. |
| `<input type="number">` | No up/down arrows. Only digits can be typed: a letter empties the box. Use a text box, or the gallery's number field or stepper. |
| `<input type="color">` | Drawn as a text box showing the color code; clicking it opens nothing. Use the gallery's color picker. |
| `<datalist>` | No suggestions ever appear. Use the gallery's combobox. |
| `</script>` written inside your script's text | Ends the block there, as in any HTML page. None of that block runs, the UI log says `UI:Open <name>: script error - SyntaxError: Unexpected EOF`, and the rest of it shows as text in your window. Split it: `'</scr' + 'ipt>'`. |
| A popup, menu or tooltip with `position: fixed`, placed at `getBoundingClientRect()` or mouse (`clientX`) numbers | Fine at normal size, but in a window the player has scaled up it opens far down and to the right of where it should. A scaled window becomes the frame `fixed` positions are measured in, in its own unscaled pixels. Place it with `ogrePlaceFixed(el, x, y)` instead, and turn a size taken off the screen into the element's own pixels with `/ ogreFixedScale(el)`. |
| An error in your window's script | Nothing in the console. The UI log gets `UI:Open <name>: script error - <the error>`, and that block stops; the other blocks still run. |

A `title="..."` on any element shows as a tooltip when the mouse rests on it: Ogre draws it for you.

**Typing in your window.** While a text box in your window has the cursor, the keyboard types into it and
the game does not see the keys. Your InnerSpace console key still opens the console.

- **Escape** clears the box's text and keeps the cursor; a second Escape gives the keyboard back to the game.
- **Enter** in a one-line text box runs your window's own Enter handling first, then gives the keyboard back
  to the game. In a text area, Enter starts a new line.

Modern JavaScript (arrow functions, `const`, template strings) works. Ogre's own windows are written in plain
older JavaScript, which works too.

## What not to rely on

Only the names on this page are meant for your scripts. Everything else on `ISXOgreX.UI`, and every `ogreWM...`
function in the page, is Ogre's own plumbing and may change or vanish without notice. That includes `Load`,
which replaces Ogre's entire UI and does not bring it back.

# Add your own commands (command packs)

A **command pack** adds your own commands to OgreConsole and to the MCP command builder. Once a pack is
installed, your commands work everywhere ours do: typed in the console, sent to the group, and put on MCP
buttons with the builder, For Who and all.

A pack is a folder of its own, laid out like Ogre's own `Scripts\Ogre` folder. You do not need to build anything
or touch any Ogre file.

> **No promises.** Use this at your own risk, and expect it to change. That said, Kannkor works hard to keep
> things backwards compatible.

## Quick start

1. An example pack ships with Ogre: the folder `Scripts\Ogre\EQ2\Examples\CommandPack\`. Copy the whole
   folder into `Scripts\OgreExternal\` and rename it `Example`. The folder's name is your pack's name.
2. In the InnerSpace console, type `ogre commandpacks`. OgreConsole's **Commands** tab says
   `Command packs loaded: Example (2)`.
3. Try it: `oc !c -Example.HelloPack all Hi there` prints `Hello from a command pack: Hi there` in the
   InnerSpace console of every character.

To start your own pack, rename the folder, then change the file in it.

## The example

`Example\EQ2\Commands\commands.json`:


```json
{
  "author": "Your name here",
  "description": "An example command pack. Copy the whole CommandPack folder into Scripts\\OgreExternal\\ and rename it Example to try it.",
  "commands": [
    {
      "name": "-HelloPack",
      "label": "Hello from a pack",
      "description": "Prints a line in the InnerSpace console of every character the For Who picks.",
      "params": [
        { "name": "who",  "type": "forwho", "description": "Who runs it - leave blank to use the For Who window.", "default": "auto" },
        { "name": "text", "type": "rest",   "description": "What to say.", "default": "" }
      ],
      "execute": [
        { "command": "echo", "args": [ "Hello from a command pack: ${text}" ] }
      ]
    },
    {
      "name": "-RunMyScript",
      "aliases": [ "-rms" ],
      "label": "Run my script",
      "description": "Runs a script, with its arguments, on every character the For Who picks.",
      "params": [
        { "name": "who",    "type": "forwho", "description": "Who runs it - leave blank to use the For Who window.", "default": "auto" },
        { "name": "script", "type": "string", "description": "The script to run, like MyFolder/myscript.", "default": "" },
        { "name": "args",   "type": "rest",   "description": "Anything after the script name is passed to it, one argument each.", "default": "" }
      ],
      "execute": [
        { "command": "runscript", "args": [ "${script}", "${args}" ] }
      ]
    }
  ]
}
```

`oc !c -Example.rms all MyFolder/myscript 12 "two words"` runs `runscript "MyFolder/myscript" "12" "two words"`
on every character.

## Where a pack goes

A pack is a folder in `Scripts\OgreExternal\`, laid out the same way as Ogre's own `Scripts\Ogre\`: a folder
for what works in every game (`Common`), a folder per game (`EQ2`), and inside those, one folder per kind of
thing. Today a pack can carry console commands; keeping to this layout leaves room for more later.

```
Scripts\OgreExternal\
  BJTools\                              your pack - the folder's name is the pack's name
    Common\Commands\commands.json       commands for every game
    EQ2\Commands\commands.json          commands for EverQuest 2
```

| What | Rule |
|---|---|
| Pack folder | `Scripts\OgreExternal\<PackName>\`. One folder per pack. |
| Pack name | The folder's name: letters, digits and `_`, up to 40 characters. No spaces, no dots. |
| Command files | `Common\Commands\commands.json`, `EQ2\Commands\commands.json`, or both. Both are one pack. |
| Patching | Ogre's patcher never touches `Scripts\OgreExternal`. Your pack is safe across updates. |

Every PC that should run a pack's commands needs the pack installed. Each character reads its own command
list, so a character without the pack says `Unknown command entered: -BJTools.YourCommand` when the command
reaches it, and does nothing else.

## The file

The file is JSON. Text goes in double quotes, and a backslash in text is written `\\`.

| Field | Required | What it is |
|---|---|---|
| `author` | yes | Your name. Shown with your pack. |
| `description` | no | One line about the pack. |
| `commands` | yes | The list of commands, below. |

### A command

| Field | Required | What it is |
|---|---|---|
| `name` | yes | The command, like `-BuffMe`: a dash, then letters, digits or `_`. It is typed with your pack's name in front: `-BJTools.BuffMe`. Any case works. |
| `aliases` | no | Other names for it, like `[ "-bm" ]`, typed `-BJTools.bm`. Same rules as `name`. |
| `label` | yes | The name the MCP builder lists it under. |
| `description` | yes | What it does. The builder shows it. |
| `params` | yes | Its parameters, in the order they are typed. **At least one must be a `forwho`.** |
| `execute` | yes | What it runs: one or more steps, run in order. |

### A parameter

| Field | Required | What it is |
|---|---|---|
| `name` | yes | Letters, digits or `_`. Used as `${name}` in the steps. |
| `type` | yes | One of the types below. |
| `description` | yes | What to put there. The builder shows it. |
| `default` | no | The value when it is left out, as text: `"auto"`, `"30"`, `"TRUE"`. |
| `allParams` | no | For a `rest` parameter: `true` takes everything to the end of the line, other commands' names included. Without it, `rest` stops at the next command. |

| Type | Takes |
|---|---|
| `forwho` | Who the command is for: `all`, a name, `igw:Name`, `@Healer1` and every other For Who. Left out, or `auto`, it uses the For Who window. |
| `string`, `int`, `int64`, `float`, `bool` | One word. Put quotes around text with spaces: `"two words"`. |
| `point3f` | A location: `x,y,z` as one word, or three numbers. |
| `rest` | Everything after it, each word as its own argument. |

### An execute step

| Field | Required | What it is |
|---|---|---|
| `command` | yes | What to run. Any InnerSpace command or LavishScript method. |
| `args` | no | Its arguments. `${name}` is replaced by that parameter's value. |

How a step becomes the line that runs:

| `command` | `args` | Runs |
|---|---|---|
| `runscript` (no `:`) | `[ "${script}", "${args}" ]` | `runscript "MyFolder/myscript" "12" "two words"` - each argument quoted, separated by spaces. |
| `Script[MyScript]:QueueCommand` (has a `:`) | `[ "${what}" ]` | `Script[MyScript]:QueueCommand["hello"]` - in brackets, separated by commas. |

An argument that is exactly `${a rest parameter}` becomes one argument per word. Empty arguments at the end are
left off.

## For Who

Every command needs a `forwho` parameter. Ogre checks it **before** your steps run, on every character: a
character the For Who does not pick runs nothing and says nothing. Your script never has to check it.

When a command has more than one `forwho`, the first one decides who runs it. The others are just values you
can pass on.

## Names

Every pack command is typed with its pack's name: **`-<PackName>.<command>`**, like `-Example.HelloPack`, and
its aliases the same way, like `-Example.rms`. There is no short form.

- **Anyone can see it is not one of OgreBot's own.** `-BJTools.Buff` says where it came from.
- **A pack can never replace one of ours.** Ours have no pack name in front.
- **Two packs never clash.** Two packs can both have a `-Buff`; they are `-BJTools.Buff` and `-Other.Buff`.
  Installing a new pack never breaks a command that already works.

## Loading and reloading

- Packs load with the console's own commands when Ogre starts.
- After you change a pack, type `ogre commandpacks` (or `ogre packs`). It re-reads every pack.
- The MCP command builder shows the new list the next time the MCP opens.
- What loaded, and anything that did not, is in OgreConsole's **Commands** tab: `Command packs loaded: ...`,
  then one line for each problem.

A command with a mistake is skipped with the reason, and the rest of its pack still loads. A file with a
mistake in its JSON, or with no `author`, is not loaded at all.

## In the MCP

Pack commands are in the command builder's list, under their `label`, with every other command. Build a
button with them the same way: pick the command, fill in its parameters, save.

## Checklist

For a person or an AI writing a pack:

- [ ] Folder `Scripts\OgreExternal\<PackName>\`, name made of letters, digits or `_`.
- [ ] File `EQ2\Commands\commands.json` (and/or `Common\Commands\commands.json`), valid JSON, with `author` and `commands`.
- [ ] Commands are typed `-<PackName>.<name>` - in buttons, scripts and anything you hand out.
- [ ] Each command has `name` (`-Word`), `label`, `description`, `params` and at least one `execute` step.
- [ ] Each command has a `forwho` parameter.
- [ ] Each parameter has `name`, a `type` from the table, and a `description`. Each `default` is text.
- [ ] Every `${name}` in a step matches a parameter's `name`.
- [ ] `ogre commandpacks` reports your pack with the number of commands you expect, and no problem lines.
