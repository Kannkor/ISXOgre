# ISXOgreEQ2.InvOps

## Members

### `Busy`

`${ISXOgreEQ2.InvOps.Busy}`

TRUE while an inventory flow started through this object (Overflow, MoveBag or Trade) is running. Only one of the three runs at a time, and starting another while one runs is refused with a busy warning.

**Returns:** bool: TRUE while an overflow, bag move or trade flow is running; FALSE when idle.

```text
echo ${ISXOgreEQ2.InvOps.Busy}
```

### `Status`

`${ISXOgreEQ2.InvOps.Status}`

One line naming the running inventory flow and its progress, or "idle". It is the same text `${ISXOgreEQ2.InvOps}` returns.

**Returns:** string: "idle", "overflow (N popped)", "mbc (done/total)" or "trade (done/total)".

```text
echo ${ISXOgreEQ2.InvOps.Status}
```

## Methods

### `MoveBag`

`ISXOgreEQ2.InvOps:MoveBag[from,to]`

The engine behind `ogre mbc`: moves every item in carried bag `from` into bag `to`, one item every 0.2 s, where a bag's number is its inventory slot (1-6). It is refused with a console warning when a number is missing or out of range, both are the same bag, a slot holds no bag, the source bag is empty, or another inventory flow is running.

| Parameter | Type | Default | Meaning |
|---|---|---|---|
| `from` | int |  | bag number (1-6) to empty |
| `to` | int |  | bag number (1-6) to move the items into |

```text
ISXOgreEQ2.InvOps:MoveBag[2,3]
```

### `Overflow`

`ISXOgreEQ2.InvOps:Overflow`

The engine behind `ogre overflow`: pops items out of the overflow window into your bags, one every 0.2 s, until the game says the overflow is empty or has no room, only one bag slot is left free, or 300 items have been popped. It returns at once and the work runs on later frames; it is refused with a console warning when another inventory flow is running or you are not in the world.

```text
ISXOgreEQ2.InvOps:Overflow
```

### `Stop`

`ISXOgreEQ2.InvOps:Stop`

Drops whichever overflow, bag move or trade flow is running, without printing anything; does nothing when idle. An open trade window is left as it is.

```text
ISXOgreEQ2.InvOps:Stop
```

### `Trade`

`ISXOgreEQ2.InvOps:Trade[count]`

The engine behind `ogre trade`: opens a trade with your current target, adds up to `count` whole stacks from your bags of the item you have EXAMINED (exact name, any case), then accepts. You need a target and an open examine window; when nothing is examined or no stack matches, the run rejects the trade it opened and ends with a console line.

| Parameter | Type | Default | Meaning |
|---|---|---|---|
| `count` | int | `12` | most stacks to hand over; missing, not a whole number, or 0 or less uses 12 |

```text
ISXOgreEQ2.InvOps:Trade[4]
```

# ISXOgreEQ2.Lag

## Methods

### `Budget`

`ISXOgreEQ2.Lag:Budget[first,second]`

Sets the two frame budgets the reports count against and saves them, then prints them. A first budget of 1 ms or less, or a second that is not above it, is not taken; with either value missing it prints one warning.

| Parameter | Type | Default | Meaning |
|---|---|---|---|
| `first` | float |  | The first budget in ms. |
| `second` | float |  | The second budget in ms, above the first. |

```text
ISXOgreEQ2.Lag:Budget[33,50]
```

### `Clear`

`ISXOgreEQ2.Lag:Clear`

Clears the recorded frames; recording carries on.

```text
ISXOgreEQ2.Lag:Clear
```

### `Close`

`ISXOgreEQ2.Lag:Close`

Closes the Lag window, the same as `ogre end lag`. The ledger keeps recording; :Off stops it.

```text
ISXOgreEQ2.Lag:Close
```

### `Dump`

`ISXOgreEQ2.Lag:Dump[seconds]`

Writes the recorded frames to the dump file and says where.

| Parameter | Type | Default | Meaning |
|---|---|---|---|
| `seconds` | float |  | How far back to dump. Optional: everything recorded when left out. |

```text
ISXOgreEQ2.Lag:Dump[120]
```

### `Minutes`

`ISXOgreEQ2.Lag:Minutes[minutes]`

Sets how many minutes of frames the ledger holds, saves it, and starts the ledger empty. With no value it prints one warning and changes nothing.

| Parameter | Type | Default | Meaning |
|---|---|---|---|
| `minutes` | int |  | Minutes to hold, held between 1 and 60. |

```text
ISXOgreEQ2.Lag:Minutes[10]
```

### `Off`

`ISXOgreEQ2.Lag:Off`

Turns the ledger off and saves it: nothing is recorded, and the frames already recorded are kept.

```text
ISXOgreEQ2.Lag:Off
```

### `On`

`ISXOgreEQ2.Lag:On`

Turns the ledger on and saves it: every frame is recorded.

```text
ISXOgreEQ2.Lag:On
```

### `Open`

`ISXOgreEQ2.Lag:Open`

Opens the Lag window, the same as bare `ogre lag`.

```text
ISXOgreEQ2.Lag:Open
```

### `Overhead`

`ISXOgreEQ2.Lag:Overhead`

Prints what the ledger itself costs per frame to the console.

```text
ISXOgreEQ2.Lag:Overhead
```

### `Report`

`ISXOgreEQ2.Lag:Report[seconds]`

Prints the report for the last stretch of frames to the console: frame rate, stability, and what cost the most.

| Parameter | Type | Default | Meaning |
|---|---|---|---|
| `seconds` | float |  | How far back to look. Optional: 60 when left out. |

```text
ISXOgreEQ2.Lag:Report[30]
```

# ISXOgreEQ2.MCP

## Members

### `ForWho`

`${ISXOgreEQ2.MCP.ForWho}`

The for-who text MCP buttons and bound keys use on this session, from the For Who picker or MCP:SetForWho. A button with its own for-who still uses its own.

**Returns:** string: the for-who text in force on this session; all when nothing has been picked (everyone).

```text
echo ${ISXOgreEQ2.MCP.ForWho}
```

### `IrcConnected`

`${ISXOgreEQ2.MCP.IrcConnected}`

Whether this session last heard that the IRC link is up. It starts FALSE on a new session and stays FALSE until the IRC hub reports in; while FALSE, MCP buttons that send over IRC go through OgreConsole instead.

**Returns:** bool: TRUE when the IRC hub last reported the link connected; FALSE when it reported it down or has not reported yet.

```text
echo ${ISXOgreEQ2.MCP.IrcConnected}
```

## Methods

### `AddBind`

`ISXOgreEQ2.MCP:AddBind[key,buttonId,name,event]`

Links a keyboard key or mouse button (an InnerSpace key name such as G600-G9) to an MCP button, so pressing it runs MCP:Fire on that button. The bind is saved to Scripts/OgreSave/EQ2/OgreMCPBinds.json, armed at once, and every EQ2 session on this PC picks it up; a bind with the same name is replaced, and a button id that has no command yet only prints a note.

| Parameter | Type | Default | Meaning |
|---|---|---|---|
| `key` | string |  | The InnerSpace key name to bind, such as G600-G9 or F13. |
| `buttonId` | string |  | The MCP button to run, as MCP:Buttons lists it. |
| `name` | string | `MCP_<key>_<buttonId> with every other character turned into _` | A name for the bind, used by MCP:RemoveBind. |
| `event` | string | `press` | release fires when the key is let go; anything else fires on press. |

```text
ISXOgreEQ2.MCP:AddBind[G600-G9,static:0_0,G9Heal,press]
```

### `Buttons`

`ISXOgreEQ2.MCP:Buttons`

Prints every configured MCP button to the console with its id, label, page and command, so you can find the id to give MCP:Fire or MCP:AddBind. With no saved layout it prints a line saying there are no buttons yet.

```text
ISXOgreEQ2.MCP:Buttons
```

### `Close`

`ISXOgreEQ2.MCP:Close`

Closes the Master Control Panel together with its For Who, Build command and Assign keys windows. It also cancels a key test that is still waiting for a press.

```text
ISXOgreEQ2.MCP:Close
```

### `Fire`

`ISXOgreEQ2.MCP:Fire[buttonId]`

Runs an MCP button by its id, exactly as clicking it would: the button's command is read from the saved layout at that moment and sent with the button's own for-who, or this session's For Who when the button has none. A missing id, no saved layout, or a button with no command prints one console line and sends nothing.

| Parameter | Type | Default | Meaning |
|---|---|---|---|
| `buttonId` | string |  | The button's id as MCP:Buttons lists it: btn:&lt;id> (follows the button when it moves), static:&lt;row>_&lt;col> or page:&lt;page>:&lt;row>_&lt;col>. |

```text
ISXOgreEQ2.MCP:Fire[static:0_0]
```

### `FixHoistOrder`

`ISXOgreEQ2.MCP:FixHoistOrder`

Repairs buttons that an older MCP:Migrate wrote with some arguments in the wrong order, touching only the affected buttons and writing OgreMCP.json.bak first. It runs once per file (a second call prints that it is already done), prints how many buttons were fixed or need checking by hand, and has every EQ2 session on this PC reload when anything changed.

```text
ISXOgreEQ2.MCP:FixHoistOrder
```

### `ListBinds`

`ISXOgreEQ2.MCP:ListBinds`

Prints every saved key bind to the console: its name, key, press or release, the button it runs, and whether it is disabled.

```text
ISXOgreEQ2.MCP:ListBinds
```

### `Migrate`

`ISXOgreEQ2.MCP:Migrate[overwrite]`

Converts the old OgreBot MCP buttons (Scripts/EQ2OgreBot/MCP/MCPCustomSettings.xml) into the new panel's Scripts/OgreSave/EQ2/OgreMCP.json and prints a summary; button types with no command equivalent come across as label only. It refuses to replace an existing OgreMCP.json unless you pass overwrite, and on success every EQ2 session on this PC reloads the panel.

| Parameter | Type | Default | Meaning |
|---|---|---|---|
| `overwrite` | string | `off - an existing file is kept` | The word overwrite (or 1, TRUE, yes, on) replaces an existing OgreMCP.json, discarding its current layout. |

```text
ISXOgreEQ2.MCP:Migrate
```

### `Open`

`ISXOgreEQ2.MCP:Open`

Opens the Master Control Panel (MCP), the window of buttons that send commands to your characters, with its saved layout; the same as `ogre mcp`, and alt+backtick toggles it. Calling it while the panel is already open does nothing; if the in-game UI host is not running or a panel file cannot be read, nothing opens and one console line says which, and a missing command catalog opens the builder empty with a line.

```text
ISXOgreEQ2.MCP:Open
```

### `Reload`

`ISXOgreEQ2.MCP:Reload`

Re-reads Scripts/OgreSave/EQ2/OgreMCP.json and updates an open panel to match, which is how a change saved on one session shows up on the others. It is skipped when the file is exactly what this session just saved, or when the file is not valid JSON.

```text
ISXOgreEQ2.MCP:Reload
```

### `ReloadBinds`

`ISXOgreEQ2.MCP:ReloadBinds`

Re-reads Scripts/OgreSave/EQ2/OgreMCPBinds.json, removes this session's live key binds and arms the saved ones again. Adding or removing a bind on any session runs this on every EQ2 session on the PC.

```text
ISXOgreEQ2.MCP:ReloadBinds
```

### `RemoveBind`

`ISXOgreEQ2.MCP:RemoveBind[name]`

Removes a saved key bind by name, disarms it and tells every EQ2 session on this PC to drop it. An unknown name prints a console line and changes nothing.

| Parameter | Type | Default | Meaning |
|---|---|---|---|
| `name` | string |  | The bind's name as MCP:ListBinds shows it. |

```text
ISXOgreEQ2.MCP:RemoveBind[G9Heal]
```

### `Send`

`ISXOgreEQ2.MCP:Send[message,-tab,tab,-rg,group,-cfw,who]`

With arguments it sends message exactly as ISXOgreX.Console:Send does (a leading !c or !ci makes it a command, anything else is a chat line). With no arguments it sends the button just clicked on this session, once, through the same route a click uses, and otherwise the console input box line.

| Parameter | Type | Default | Meaning |
|---|---|---|---|
| `message` | string | `the button just clicked, or the input box line` | The literal line to send; a leading !c or !ci makes it a command. Leave out every argument for the button just clicked, or the console input box line. |
| `-tab` | switch | `(none)` | Also show the line in the console tab named by the next argument; may be given more than once. |
| `tab` | string | `(none)` | The console tab name that follows -tab. |
| `-rg` | switch | `(none)` | Send to the relay group named by the next argument instead of the bot's own relay group. |
| `group` | string | `the bot's relay group` | The relay group name that follows -rg. |
| `-cfw` | switch | `(none)` | Give the command a for-who, used by its commands whose own for-who is left as auto. |
| `who` | for-who | `everyone` | [for-who](../ogrebotapi/ForWho.md): this runs only when this character is one it names - the value that follows -cfw. |

```text
ISXOgreEQ2.MCP:Send["!c -pause","-cfw","igw:${Me.Name}"]
```

### `SetForWho`

`ISXOgreEQ2.MCP:SetForWho[value]`

Sets the For Who that MCP buttons and bound keys use on this session only, held in memory (not saved, not shared, back to everyone after a restart). With a value it sets that as a custom For Who and shows it in the picker (spaces are removed; all or an empty value clears it back to everyone); with no value it takes the choice the For Who picker just made.

| Parameter | Type | Default | Meaning |
|---|---|---|---|
| `value` | string | `(none) - the picker's choice` | The for-who text to use, such as igw:&lt;name> or several names joined with \|. Leave it out to take the For Who picker's current choice. |

```text
ISXOgreEQ2.MCP:SetForWho[igw:${Me.Name}]
```

### `Toggle`

`ISXOgreEQ2.MCP:Toggle`

Opens the Master Control Panel when it is closed and closes it when it is open. This is what alt+backtick runs.

```text
ISXOgreEQ2.MCP:Toggle
```

# ISXOgreEQ2.MerchantCraft

## Methods

### `Help`

`ISXOgreEQ2.MerchantCraft:Help`

Prints the `ogre mc` usage lines to the console and does nothing else. It is what `ogre mc help` runs.

```text
ISXOgreEQ2.MerchantCraft:Help
```

### `List`

`ISXOgreEQ2.MerchantCraft:List`

Reads the recipes your TARGETED merchant sells and prints them numbered, for use with Start["#n"]. It is refused with a console warning when a run is already going, you are not in the world, the target is not a merchant within 9 m, or you lack the Summon Crafting Stations ability.

```text
ISXOgreEQ2.MerchantCraft:List
```

### `Start`

`ISXOgreEQ2.MerchantCraft:Start[words...]`

The engine behind `ogre mc <recipe> [count]`: for each round it buys the recipe from your targeted merchant (only if you do not know it), scribes it, summons the crafting station it needs, empties the craft engine's setup queue and crafts it 3 times. It has the same refusals as List and also refuses with no recipe or while a craft run is going; on a recipe not yet cached it MAKES A SERVER CALL (`.ToRecipeInfo`, to learn the crafting device), and only when the craft panel's "Allow recipe-info server call" option is on, which it is by default.

| Parameter | Type | Default | Meaning |
|---|---|---|---|
| `words...` | string |  | a partial recipe name (one or more words, first match wins) or "#n" for row n of List's numbering, then an optional trailing whole number = rounds (1 to 999, default 1; each round is 3 crafts) |

```text
ISXOgreEQ2.MerchantCraft:Start[ferrite,bracelet,4]
```

### `Status`

`ISXOgreEQ2.MerchantCraft:Status`

Prints the merchant-craft state (running or idle, the current recipe and round, how many recipes the last scan found) and then the usage lines to the console. It is what bare `ogre mc` and `ogre mc status` run.

```text
ISXOgreEQ2.MerchantCraft:Status
```

### `Stop`

`ISXOgreEQ2.MerchantCraft:Stop`

Abandons the merchant-craft run and prints "mc: stopped.", or "mc: nothing is running." when idle. It does not stop a craft queue the run already started, and a summoned station stays.

```text
ISXOgreEQ2.MerchantCraft:Stop
```

# ISXOgreEQ2.MerchantOps

## Members

### `Running`

`${ISXOgreEQ2.MerchantOps.Running}`

TRUE while a buyfuel or buycrate run is in progress. Only one runs at a time; starting another is refused with a busy warning.

**Returns:** bool: TRUE while a fuel or crate purchase run is going; FALSE when idle.

```text
echo ${ISXOgreEQ2.MerchantOps.Running}
```

### `Status`

`${ISXOgreEQ2.MerchantOps.Status}`

One line naming the running merchant run and its progress, or "idle". It is the same text `${ISXOgreEQ2.MerchantOps}` returns.

**Returns:** string: "idle", "buyfuel '&lt;fuel>' (round n)" or "buycrate (done/total)".

```text
echo ${ISXOgreEQ2.MerchantOps.Status}
```

## Methods

### `BuyCrate`

`ISXOgreEQ2.MerchantOps:BuyCrate[flags...]`

The engine behind `ogre buycrate`: targets and opens this zone's crate merchant (who must be nearby), buys one of each chosen heroic and raid crate, accepts the purchase prompt and closes the merchant. Only exp17_dun_fordel_midst and exp18_rgn_svarni_expanse have one (Svarni sells no heroic crate), and anywhere else, or when nothing matches the flags, the call is refused with a warning.

| Parameter | Type | Default | Meaning |
|---|---|---|---|
| `flags...` | string | `-all` | -r/-raid for the raid crate, -h/-heroic for the heroic crate, -all for both; read left to right, so `-raid -all` buys both and `-all -raid` only the raid crate; unknown words are ignored |

```text
ISXOgreEQ2.MerchantOps:BuyCrate[-h]
```

### `BuyFuel`

`ISXOgreEQ2.MerchantOps:BuyFuel[amount]`

The engine behind `ogre buyfuel`: at the guild hall Fuel Depot (within 11 m) it counts how much of the fuel you have EXAMINED the depot holds, buys the shortfall from the merchant titled Guild Fuel Merchant and deposits it, repeating for at most 10 rounds. It is refused when nothing is examined, a run is already going or you are not in the world, and stops with a console warning when the depot is missing, too far or does not open.

| Parameter | Type | Default | Meaning |
|---|---|---|---|
| `amount` | int | `90000` | how much of the fuel the depot should end up holding; missing, not a whole number, or 0 or less uses 90000 |

```text
ISXOgreEQ2.MerchantOps:BuyFuel[20000]
```

### `Stop`

`ISXOgreEQ2.MerchantOps:Stop`

Stops a running buyfuel or buycrate and prints "merchant: stopped."; does nothing when idle. Open depot or merchant windows are left as they are.

```text
ISXOgreEQ2.MerchantOps:Stop
```

# ISXOgreEQ2.Migrate

## Methods

### `Cancel`

`ISXOgreEQ2.Migrate:Cancel[task]`

Backs out of a pending overwrite confirmation for one task, putting its row back to its normal state. It does nothing when that task is not waiting for a confirmation or the name is unknown.

| Parameter | Type | Default | Meaning |
|---|---|---|---|
| `task` | string |  | the task whose confirmation to cancel: accounts, imsettings, imlists, profiles, irc, mcp or isprofile |

```text
ISXOgreEQ2.Migrate:Cancel[profiles]
```

### `Close`

`ISXOgreEQ2.Migrate:Close`

Closes the Migration Assistant window and cancels its pending auto-close. Nothing that has already run is undone.

```text
ISXOgreEQ2.Migrate:Close
```

### `Open`

`ISXOgreEQ2.Migrate:Open`

Opens the Migration Assistant window (the same as `ogre migrate`), listing each migration task with its status and a re-run button. Before it opens it silently runs any task whose old file exists and whose new file does not, and when the window is already up it does nothing.

```text
ISXOgreEQ2.Migrate:Open
```

### `RequestRerun`

`ISXOgreEQ2.Migrate:RequestRerun[task]`

Puts one task's row in the Migration Assistant into its overwrite confirmation state, the same as clicking its re-run button; it reads and writes no files. It only does so when that task's old source data exists, otherwise nothing changes.

| Parameter | Type | Default | Meaning |
|---|---|---|---|
| `task` | string |  | the task to ask about: accounts, imsettings, imlists, profiles, irc, mcp or isprofile |

```text
ISXOgreEQ2.Migrate:RequestRerun[accounts]
```

### `Run`

`ISXOgreEQ2.Migrate:Run[task,overwrite]`

Runs one migration task now, copying old OgreBot data into the new store (your old XML files are kept); the isprofile task instead asks InnerSpace to add its game profile and ignores overwrite. Without overwrite a task whose new file already exists is not rewritten and its row asks you to confirm instead, an unknown task name does nothing, and the result shows in the Migration Assistant window and the log.

| Parameter | Type | Default | Meaning |
|---|---|---|---|
| `task` | string |  | the task to run: accounts, imsettings, imlists, profiles, irc, mcp or isprofile |
| `overwrite` | string |  | the word overwrite (any case) to replace data that already exists; anything else, or leaving it out, keeps existing data |

```text
ISXOgreEQ2.Migrate:Run[irc]
```

# ISXOgreEQ2.Nav

## Members

### `NavActive`

`${ISXOgreEQ2.Nav.NavActive}`

TRUE while a nav trip is in progress - planning its route, waiting for this zone's navmesh, or moving. A paused trip still counts as in progress.

**Returns:** bool: TRUE while a trip is planning, waiting for its navmesh or moving; FALSE when idle or once the last trip has ended (Arrived, Stopped, Failed).

```text
echo ${ISXOgreEQ2.Nav.NavActive}
```

### `NavDistance`

`${ISXOgreEQ2.Nav.NavDistance}`

# ISXOgreEQ2.Queue

## Members

### `Blocking`

`${ISXOgreEQ2.Queue.Blocking}`

Why the most urgent waiting entry cannot start yet, as a line like seq=5 CastAbility prio=100 age=900ms: resource busy: CastBar, or starved by a higher-priority haltQueue entry. Empty when nothing is waiting or the next entry is free to start.

**Returns:** string: the reason line; empty when nothing is held up

```text
echo ${ISXOgreEQ2.Queue.Blocking}
```

### `Count`

`${ISXOgreEQ2.Queue.Count}`

Number of entries in the action queue, running plus waiting.

**Returns:** int: entries running plus waiting; 0 when the queue is empty

```text
echo ${ISXOgreEQ2.Queue.Count}
```

### `Enqueue`

`${ISXOgreEQ2.Queue.Enqueue[priority,kind,arg0,arg1,ttlstart,ttlmax]}`

Adds an entry exactly like ISXOgreEQ2.Queue:Add and returns its seq, the id you pass to Status, IsDone and Remove. Reading the member is what adds the entry, so every read queues another one, and an unknown kind (ApplyVerbCastBar and DialogChoices included) or a flow name that is not registered adds nothing and returns 0.

| Parameter | Type | Default | Meaning |
|---|---|---|---|
| `priority` | int | `100` | Higher runs first; 0 means the default 100 |
| `kind` | string |  | What to do, any case: CastAbility, CastItem, ClickCastBar, RawCommand, Movement or Flow. ApplyVerbCastBar and DialogChoices are not kinds here; OgreBotAPI.Actors:ApplyVerbIDQueued queues an apply-verb |
| `arg0` | string |  | Depends on kind: RawCommand the console command, CastAbility the ability id or name, CastItem the item name, ClickCastBar the actor id, Movement x,y,z with an optional precision, Flow the flow name |
| `arg1` | string |  | Depends on kind: CastAbility the target name (empty = current target), CastItem the equip slot (empty = the bag item by name), ClickCastBar the wait in tenths of a second (empty = 4 seconds), Flow its arguments |
| `ttlstart` | int | `0` | Milliseconds the entry may wait to start before it is dropped with status Expired; 0 = no limit |
| `ttlmax` | int | `0` | Milliseconds the entry may run before it is stopped with status Aborted; 0 = no limit |

**Returns:** int64: the new entry's seq (1 and up); 0 when the kind is unknown

```text
echo ${ISXOgreEQ2.Queue.Enqueue[100,RawCommand,"echo queued"]}
```

### `Entry`

`${ISXOgreEQ2.Queue.Entry[index]}`

One queue entry as a readable line, such as seq=12 prio=100 RawCommand waiting age=40ms arg0=echo hi, where seq is the entry's id. The index counts from 1, running entries first and then waiting ones, each sorted by priority then by the order they were added.

| Parameter | Type | Default | Meaning |
|---|---|---|---|
| `index` | int |  | Position in the queue counting from 1: running entries first, then waiting ones, highest priority first |

**Returns:** string: the entry line; empty when the index is 0, past the end or missing

```text
echo ${ISXOgreEQ2.Queue.Entry[1]}
```

### `EntryJSON`

`${ISXOgreEQ2.Queue.EntryJSON[index]}`

One queue entry as a JSON object with seq, priority, kind, status (running or waiting), holds, haltQueue, haltCastStack, ageMs, blocked, arg0, arg1 and label. Same index as Entry, counting from 1, so a loop from 1 to Count reads the whole queue.

| Parameter | Type | Default | Meaning |
|---|---|---|---|
| `index` | int |  | Position in the queue counting from 1: running entries first, then waiting ones, highest priority first |

**Returns:** string: the entry as a JSON object; {} when the index is 0, past the end or missing

```text
echo ${ISXOgreEQ2.Queue.EntryJSON[1]}
```

### `InFlight`

`${ISXOgreEQ2.Queue.InFlight}`

Whether any queue entry is running right now.

**Returns:** bool: TRUE when at least one entry is running; FALSE when none is

```text
echo ${ISXOgreEQ2.Queue.InFlight}
```

### `IsDone`

`${ISXOgreEQ2.Queue.IsDone[seq]}`

Whether the queue entry with that seq has finished in any way (Done, Failed, Expired, Aborted or Removed), so a wait loop never hangs on a failed entry; read Status for how it ended. A seq that finished and has since been forgotten also reads TRUE, while a seq never issued reads FALSE.

| Parameter | Type | Default | Meaning |
|---|---|---|---|
| `seq` | int64 |  | The entry's id, from Enqueue or the seq= field of Entry and Spew |

**Returns:** bool: TRUE when the entry has finished, however it ended; FALSE while it is waiting or running, or when the seq was never issued

```text
echo ${ISXOgreEQ2.Queue.IsDone[1]}
```

### `Status`

`${ISXOgreEQ2.Queue.Status[seq]}`

The state of the queue entry with that seq. Unknown means the seq was never issued or finished too long ago to remember (only the most recent 256 are kept).

| Parameter | Type | Default | Meaning |
|---|---|---|---|
| `seq` | int64 |  | The entry's id, from Enqueue or the seq= field of Entry and Spew |

**Returns:** string: Pending, InFlight, Done, Failed, Expired, Aborted, Removed or Unknown

```text
echo ${ISXOgreEQ2.Queue.Status[1]}
```

`ISXOgreEQ2.Queue:Add[priority,kind,arg0,arg1,ttlstart,ttlmax]`

### `DespawnsDispatched`

`${ISXOgreEQ2.Spawn.DespawnsDispatched}`

```text
echo ${ISXOgreEQ2.Spawn.DespawnsDispatched}
```

### `HasChest`

```text
echo ${ISXOgreEQ2.Spawn.HasChest}
```

### `IsLive`

`${ISXOgreEQ2.Spawn.IsLive[id]}`

Whether the actor ID is in the live set: seen spawning (or present when the zone settled) and not yet despawned. The set is wiped when you zone and filled again once the new zone settles, so it can read FALSE for a moment after zoning.

| Parameter | Type | Default | Meaning |
|---|---|---|---|
| `<id>` | int64 |  | The actor ID to test. |

**Returns:** bool: TRUE when that actor is live; FALSE when it is not, or when no ID is given.

```text
echo ${ISXOgreEQ2.Spawn.IsLive[${Target.ID}]}
```

### `LiveCount`

`${ISXOgreEQ2.Spawn.LiveCount}`

How many actor IDs are in the live set for this zone. It drops to 0 while zoning and refills once the new zone settles.

**Returns:** int: the number of live actors tracked.

```text
echo ${ISXOgreEQ2.Spawn.LiveCount}
```

### `OnSpawnDelay`

`${ISXOgreEQ2.Spawn.OnSpawnDelay}`

How long after an actor spawns the delayed spawn event EQ2_ActorSpawned_Delayed fires for it (only if it is still live). The default is 1000 ms and the most is 60000; SetOnSpawnDelay changes it for this session only.

**Returns:** int: the delay in milliseconds.

```text
echo ${ISXOgreEQ2.Spawn.OnSpawnDelay}
```

### `Received`

`${ISXOgreEQ2.Spawn.Received}`

**Returns:** int64: spawn plus despawn events received.

```text
echo ${ISXOgreEQ2.Spawn.Received}
```

### `SpawnsDispatched`

```text
echo ${ISXOgreEQ2.Spawn.SpawnsDispatched}
```

## Methods

### `DelayStatus`

`ISXOgreEQ2.Spawn:DelayStatus`

Prints the delayed spawn event's state to the console: the delay, the per-drain cap, what is waiting and ready, and the counters since the last zone-in.

```text
ISXOgreEQ2.Spawn:DelayStatus
```

### `ResetOnSpawnDelay`

`ISXOgreEQ2.Spawn:ResetOnSpawnDelay`

Puts the delay before EQ2_ActorSpawned_Delayed back to the default of 1000 ms and prints the value to the console.

```text
ISXOgreEQ2.Spawn:ResetOnSpawnDelay
```

### `SetOnSpawnCap`

`ISXOgreEQ2.Spawn:SetOnSpawnCap`

Sets how many due spawns one drain may emit, for this session only, held between 1 and 5000 (0 or a negative is 1), and prints the value in force to the console. A value that is not a number keeps the cap and says so; with no value it prints one warning and changes nothing.

| Parameter | Type | Default | Meaning |
|---|---|---|---|
| `<k>` | int |  | The per-drain cap, 1 to 5000. |

```text
ISXOgreEQ2.Spawn:SetOnSpawnCap[25]
```

### `SetOnSpawnDelay`

`ISXOgreEQ2.Spawn:SetOnSpawnDelay[<ms>]`

Sets the delay before EQ2_ActorSpawned_Delayed fires, for this session only (it is not saved), and prints the value in force to the console. More than 60000 ms is held at 60000; a value that is not a whole number of 0 or more is refused with a warning and the delay is unchanged.

| Parameter | Type | Default | Meaning |
|---|---|---|---|
| `<ms>` | int |  | The delay in milliseconds, 0 to 60000. |

```text
ISXOgreEQ2.Spawn:SetOnSpawnDelay[1500]
```

### `Status`

`ISXOgreEQ2.Spawn:Status`

Prints the spawn consumer's counters to the console: spawns and despawns seen, duplicate and unknown ids, the live actor count, the chest id and the router's subscribers and throughput.

```text
ISXOgreEQ2.Spawn:Status
```

# ISXOgreEQ2.TagTimers

## Methods

### `Close`

`ISXOgreEQ2.TagTimers:Close`

Closes the Tag Timers window, the same as `ogre end tags` or its X, and does nothing while it is closed. A ticked Show Tag Timers window box stays ticked and opens it again on the next profile load.

```text
ISXOgreEQ2.TagTimers:Close
```

### `Open`

`ISXOgreEQ2.TagTimers:Open`

Opens the Tag Timers window, the same as `ogre tags`, and does nothing while it is already up. The Show Tag Timers window box on the Tags tab opens it with the profile.

```text
ISXOgreEQ2.TagTimers:Open
```
